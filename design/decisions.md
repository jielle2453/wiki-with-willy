## D-026 ingest 與 note 維持分開，對帳共用規則
- 日期：2026-10-11
- 選了：維持六個 skill。補三條：(1) `rules/core.md` 加一條編號規則「出處優先序」：檔案高於使用者陳述高於推導；檔案與使用者衝突時兩者並存、各標出處，回答必須同時講兩邊。(2) `rules/synthesis.md` 範圍寫明：變動不論來自檔案或使用者口述，對綜合頁的反查與連帶處理都走這裡；ingest 與 note 本文只留一行指針。(3) 路由判準是語意的：這句話說的事，重讀檔案能不能驗證。能就是 ingest，不能就是 note。配機器後盾：ingest 開頭必跑 `kb changes`，查無變動即交 note；誤走 note 的檔案變動由下次開場的變動偵測補上。
- 為什麼：兩個 skill 真正共用的只有「連帶哪些頁要改」，已在 synthesis.md；「誰贏」是 answer 每題也要用的優先序，該住 core.md 不住 skill；其餘判斷（刪不刪問、分批、重複檔 vs 四種哪一種、寫哪個 JSON）本來就不同。「有沒有檔案名詞」只是表面特徵，反例很多（「那份報價的付款條件談好改 30 天了」有檔名卻是 note），所以判準寫原則加例子，靠 `kb changes` 當機器後盾，不寫死。
- 放棄了：合併成 update 一個 skill（省一行常駐，但描述最長、本文要分岔、三條決策重寫）；依寫入目錄 wiki/ 與 admin/ 切（路由要先判斷事實還是規則）；note 降成規則加腳本（糾正需要判斷連帶改哪些頁）。
- 重談條件：確認報告裡 ingest 查無變動後交 note 的次數，多到客戶抱怨慢。

## D-038 綜合卡結構

## D-039 實體四大類
- 日期：2026-10-11
- 選了：程式只認四個大類，具體型別名字住客戶設定檔，每個型別標一個大類。**對象**：人或組織，有關係，底下掛事與物，有只能靠口述累積的段如偏好與禁忌。**事**：有開始有結束的工作，有狀態機（進行中、結案、擱置），日程多半掛這。**物**：被管理的東西，屬性帶數值與日期，推算段最常用，到期日進日程。**主題**：不屬於任何對象、事、物的知識，沒有狀態機，現況是「規則現在是什麼」，紀事是「規則怎麼變」，跨實體統計放這。一個客戶不一定四類都用。年度不是實體，是檔頭的篩選欄位。關係第一版不要客戶填，從共用的檔案卡推，角色留到有客戶要再加。客戶中途要加型別走 note，在設定檔加一行標大類。

## D-050 密碼 PDF 與憑證管理員
- 日期：2026-10-12

## D-081 憑證預設擋、個案裁示放行、總資料夾內部豁免、帳密走憑證管理員
- 日期：2026-10-15
- 選了：(1) **預設**：檔名像密碼或金鑰的檔不讀不寫（守門三道），製卡與 note 不把密碼寫進卡（ingest 題的規則）。沒有總開關：同一個客戶會覺得有些密碼可以記、有些不行。(2) **例外是個案裁示**（D-041）：客戶說「這份密碼檔可以讀」「這組門禁密碼記下來」，掛具體檔或實體記進 `rulings.json`，守門讀裁示放行那一份、製卡者看到裁示才寫進卡；rulings.json 是 note 題的，守門先留讀裁示的位置。(3) **對話裡給的帳密**（「幫我登入 ERP，帳號 X 密碼 Y」）：登入是外部動作先確認（R-09）；帳密照 D-050 走 Windows 憑證管理員、客戶選存或用完丟，不進卡、不進任何狀態檔；問要不要存是 note 的事。(4) **總資料夾內部豁免**：三道只對登記來源、含來源的上層夾、知識庫外生效；總資料夾內部（Z1～Z8）不比、不走訪，走訪含總資料夾的上層夾時跳過總資料夾整棵。內部的東西只會經同意的路進來：收件匣是客戶自己丟的，卡是裁示後才寫的。第二道（裸 token）與「走訪 cwd」只在效用 cwd 不在總資料夾裡時做。(5) **遮值**：回合檔的 `prompt_head` 與之後工作日誌的「問」先過程式遮值：關鍵詞（密碼、帳密、帳號、password、token、金鑰、secret 等）後面到下一個標點或關鍵詞前的字換成 ███；程式是地板，AI 第二層（`kb turn redact`）等工作日誌題。
- 為什麼：「什麼算敏感」是訪談五句之一（D-051），客戶的答案不是一個開關而是一件一件的；守門寫死的是預設不是不可關。I-032 要防的是 raw 裡的密碼表被整夾製卡送上雲端，不是客戶主動交給 AI 的東西。測試第三輪 P1：知識庫裡一張叫「門禁密碼.md」的卡讓整庫 `grep -r` 被擋、answer 讀不了那張卡；第四輪又證明 shell 字串猜「範圍搜尋沒給路徑」追不完，內部豁免後 cwd 在總資料夾裡時不用猜。客戶打進對話的帳密已經在 Claude Code 自己的對話紀錄與雲端，遮值只防它擴散進我們的檔與備份，建置告知要講「敏感帳密不要打在對話裡」。
- 放棄了：總開關 `credential_guard`（太粗）；維持不分區（誤擋正常使用）；內部只做第一道不走訪（半套）；AI 遮值當地板（機率不是保證）。
- 重談條件：確認階段客戶對「這份可以讀」的裁示太頻繁，或收件匣常被拿來放密碼檔。
