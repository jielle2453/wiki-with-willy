## D-026 ingest 與 note 維持分開，對帳共用規則
- 日期：2026-10-11
- 選了：維持六個 skill。補三條：(1) `rules/core.md` 加一條編號規則「出處優先序」：檔案高於使用者陳述高於推導；檔案與使用者衝突時兩者並存、各標出處，回答必須同時講兩邊。(2) `rules/synthesis.md` 範圍寫明：變動不論來自檔案或使用者口述，對綜合頁的反查與連帶處理都走這裡；ingest 與 note 本文只留一行指針。(3) 路由判準是語意的：這句話說的事，重讀檔案能不能驗證。能就是 ingest，不能就是 note。配機器後盾：ingest 開頭必跑 `kb changes`，查無變動即交 note；誤走 note 的檔案變動由下次開場的變動偵測補上。
- 為什麼：兩個 skill 真正共用的只有「連帶哪些頁要改」，已在 synthesis.md；「誰贏」是 answer 每題也要用的優先序，該住 core.md 不住 skill；其餘判斷（刪不刪問、分批、重複檔 vs 四種哪一種、寫哪個 JSON）本來就不同。「有沒有檔案名詞」只是表面特徵，反例很多（「那份報價的付款條件談好改 30 天了」有檔名卻是 note），所以判準寫原則加例子，靠 `kb changes` 當機器後盾，不寫死。
- 放棄了：合併成 update 一個 skill（省一行常駐，但描述最長、本文要分岔、三條決策重寫）；依寫入目錄 wiki/ 與 admin/ 切（路由要先判斷事實還是規則）；note 降成規則加腳本（糾正需要判斷連帶改哪些頁）。
- 重談條件：確認報告裡 ingest 查無變動後交 note 的次數，多到客戶抱怨慢。

## D-039 實體四大類
- 日期：2026-10-11
- 選了：程式只認四個大類，具體型別名字住客戶設定檔，每個型別標一個大類。**對象**：人或組織，有關係，底下掛事與物，有只能靠口述累積的段如偏好與禁忌。**事**：有開始有結束的工作，有狀態機（進行中、結案、擱置），日程多半掛這。**物**：被管理的東西，屬性帶數值與日期，推算段最常用，到期日進日程。**主題**：不屬於任何對象、事、物的知識，沒有狀態機，現況是「規則現在是什麼」，紀事是「規則怎麼變」，跨實體統計放這。一個客戶不一定四類都用。年度不是實體，是檔頭的篩選欄位。關係第一版不要客戶填，從共用的檔案卡推，角色留到有客戶要再加。客戶中途要加型別走 note，在設定檔加一行標大類。

## D-094 清冊掃描與比對規則：以上次掃描為基準、快速模式只比大小時間、changes 只讀、scan 才寫
- 日期：2026-10-16
- 選了：**範圍**：登記且未排除的外部來源；總資料夾自身三區（型別夾底下除綜合卡以外的檔、收件匣、AI 產出），不掃檔案索引、系統、隱藏三樣。**跳過**：點開頭或隱藏／系統屬性的夾與檔、暫存名（`~$*`、`*.tmp`、`Thumbs.db`、`desktop.ini`、`.DS_Store`）、junction 與符號連結不跟（I-021）、開不了的夾記 error 繼續走。憑證樣式檔用守門同一份清單列著不算指紋（`read=credential`）；占位檔看 Windows 屬性不算指紋（I-020）；單檔超過 `fingerprint_max_bytes` 不算指紋只比大小時間。**比對**以清冊上次掃描為基準：新增（磁碟有清冊無、指紋對不到）、修改（大小或時間變且指紋變；指紋沒變是假變動只更新時間不報）、搬動（舊位置不見別處同指紋，換位置不報）、重複（同指紋加位置不新建）、不見（所有位置不在也沒搬，`status=missing` 記 `missing_since`；問客戶是 ingest 題）。**快速模式**（開場 hook）只比大小時間，只對既有條目變了的與大小等於某個不見條目的新檔算指紋，總讀取量上限 `changes_quick_hash_budget_bytes`（I-081）超過當修改，走訪超過 `changes_quick_seconds` 停下改印「來源很大還沒比完」。**誰寫**：`kb changes` 只讀不寫（印分類清單、`--json`）；`kb inventory scan` 把比對結果套進清冊；開場 hook 不寫清冊，只寫 `env.json` 的「已報過」記號。**整個來源找不到**（來源根展不開或不是資料夾）：條目不動不標 missing，新建 `.system/env.json`（schema 1）按機器名記 `missing_sources_reported`，開場只報一次「這台電腦找不到 X」（I-045），`kb changes` 每次都列。**開場行**：`變動：新增 N、修改 N、不見 N`，全 0 整行不印，搬動與重複不印。三個數字住 `defaults.json`。

## D-096 OOXML 內容指紋用標準函式庫先做，假變動不報
- 日期：2026-10-16
- 選了：docx、xlsx、pptx（含 docm、xlsm、pptm）除位元組 sha256 外多算一個內容指紋 `text_sha256`：`zipfile` 加 `xml.etree`，docx 以段落為單位接所有 `w:t`，xlsx 抓每格座標、值（認 `t="s"`、`inlineStr`、`str` 三種字串寫法，數值轉 float 後統一 `.10g`）與公式，pptx 以段落接 `a:t`。比對：位置已知、大小時間變、位元組變，但兩邊都有內容指紋且相同 → 假變動，現行那筆指紋的 `sha256` 原地換新、不追加、不報修改。搬動與重複仍只認位元組。zip 打不開、不是這幾種、加密 Office 檔退回位元組。這是 D-014 補「Office 指紋用抽出文字算」的第一版；ingest 題的 `kb convert` 出來後要不要改用它抽的文字，到時再看。
- 為什麼：客戶「打開看一下再存」是日常，Excel、Word、LibreOffice 存檔都重寫 zip 裡的 metadata 與 XML 排版（I-015）；不處理，開場天天報「修改 N」，跟 I-045 一樣訓練客戶不看。標準函式庫就做得到，不用等選配的 markitdown。LibreOffice 存檔改得更兇（inline string、run 重切），所以抽內容要以段落接、字串三種寫法都認；確認環境只有 LibreOffice，真客戶兩種都可能有。
- 放棄了：等 ingest 題的 convert（這題開場就會誤報）；只比 zip 成員的位元組（LibreOffice 重存 XML 整個重排，救不到）；內容指紋也用來認搬動（另存的副本會被當成搬動，位元組認法保守）。
- 重談條件：ingest 的 convert 抽出的文字跟這裡的內容指紋常不一致，或 .doc／.xls／PDF 的假變動多到客戶抱怨。

## D-132 SKILL 的內容住哪裡：判斷在本文、細節在 references、介面在程式輸出
- 日期：2026-10-19
- 選了：(1) **SKILL.md 本文**只放分辨（客戶在說什麼、該不該做、做多少、何時要問）、原則與禁止、步驟骨架（每步一行，寫明讀哪份 reference 或照哪個程式輸出做）；每條原則帶一句給模型看的理由加決策或事故編號（「刪除只認明確的確認，記錯檔案客戶一刪卡就跟著沒了（I-082）」），完整的理由與取捨仍住 decisions。(2) **references 與 rules** 放判斷的細節（卡怎麼寫、綜合卡怎麼寫、日期怎麼換算）；同一件事只寫一處，本文只放指標。(3) **程式介面住程式的輸出**：欄位、指令與參數、「客戶答了什麼叫哪個指令」由程式給：要做的項目帶 `do`，要問的帶 `question` 與 `answers`（指令可帶 `{新名字}` 這類空格），會刪東西的標 `strict`（只認明確確認），一次最多問幾個由程式排好給；本文不寫對照表。(4) **補丁**：為某次做錯加的句子，程式已保證的刪掉；該由程式保證的先留著、記 backlog 寫明改哪裡；只能靠文字的改寫成通則（不寫針對某一次事故的叮嚀）並標編號。(5) **驗證**：改寫既有 skill 時照 skill-creator 做新舊版對照（同幾個真實情境，舊版快照與新版各跑一次，比結果與過程）；新 skill 的描述寫積極一點（模型容易該用卻沒用），可用 skill-creator 的描述優化。審閱照 skill-reviewer 加這五條。本文字數上限照 D-070。conventions 二「理由不寫在規則裡」管的是 `rules/`，SKILL 的一句理由不受它限制。

- 放棄了：照現在的方式繼續加、只調高字數上限；只把內容搬去 references 但對照表仍用文字寫；原則只標編號不寫理由。
- 重談條件：程式帶 `answers` 之後 AI 仍常不照答案做或自己另外發揮；或新舊版對照的成本高到每題做不起。

- 選了：D-132 的 `answers` 是**程式能做的結果清單**（有順序），不是客戶要說的話：每個結果有一句白話（「跟著改名叫王宅」）與要執行的指令（可帶 `{新名字}` 這類空格，客戶說了 AI 填）。AI 問的時候把結果列成編號選項；同一則回答裡最多 3 個問題，編號接著編（第一題 1～3、第二題接 4、5…），編號由程式排好給、AI 照抄，客戶的「1」只會對到一個結果（I-083）。客戶回編號或直接說意思都可以，AI 對到清單裡的一個結果才執行；對不上就再問一次，清單裡沒有的事照實說這版做不到，不自己發明做法。標 `strict` 的（會刪東西）：回編號或明確說出那個結果才算，「好」「嗯」「可以」不算、再問一次（I-082）。
- 為什麼：客戶照平常說話，不受限制；結果清單讓 AI 只負責聽懂意思、指令由程式給不會打錯（D-132）；同一則多個問題各從 1 編號會撞。
- 放棄了：只收意思（客戶想回編號時不方便）；只收編號（對話生硬，「其實叫王公館」這種回答沒有編號可選）；每題各自從 1 編號。
- 重談條件：確認階段 AI 常把客戶的話對到錯的結果，或客戶覺得選項列表太囉嗦。
- **2026-10-20 修訂**（整理 ingest 確認後，使用者定）：選項怎麼排不限制，接續的數字、字母、每題各自 1～3 都可以；程式給的 `n` 是內部用來對結果的，不一定照抄給客戶。要守的只有兩件：回答裡說的回覆方式跟畫面上一致；客戶的回覆要對到唯一一個結果才照做，對不到或有兩個可能就問清楚（I-083 由這條擋，不靠編號形式）。

## D-135 一次最多 3 個問題：客戶這句需要的先問，整理問題照程式的順序補滿
- 日期：2026-10-20

- 重談條件：確認階段整理問題常常拖太久沒問到，或客戶覺得每句末尾都有問題很煩。

## D-148 別名：kb entity alias 加與拿掉；撞到已登記的實體就改問合併
- 日期：2026-10-20

## D-158 `kb journal recent` 每段帶問、結果、做了、改了，給篩法讓 AI 照問法挑（收 B-034）

- 為什麼：改原檔要保住她的格式，只有本機改副本做得到；PowerPoint 改字不動版面，移動縮放要看得到結果，整份重排等於盲著重新設計，重做比較好（使用者定）。新做的 artifacts 對 AI 簡單很多（只給內容、版型負責排版、不用裝 node 套件）也比較好看（使用者定先推薦）；但它不在知識庫，沒有備份、退回、製卡，所以要另外登記，資料放雲端要說清楚。
- 放棄了：新簡報只給大綱（使用者要這版就能做新簡報）；成品一律本機、雲端只在要分享時用（我原先的提議）；每次都問要檔案還是線上版；PowerPoint 只改字或什麼都改。
- 重談條件：B-081 驗出桌面版沒有 artifacts，或下載回本機做不到、客戶常要檔案。

## D-170 `kb office`：程式準備工具、給原檔副本、把成品放進 AI 產出；AI 照樣自己寫做檔的程式
- 日期：2026-10-21
- 選了：一組 `kb office` 指令（名稱與參數 spec 定），只管三件事，做檔的程式照樣由 AI 寫（D-162）。(1) **準備工具**：查這台有什麼（Office、LibreOffice、node、python 套件）；第一次要做文件時問客戶一次、把 node 與 python 套件裝在這台電腦的固定位置（`%LOCALAPPDATA%\wiki-with-willy\`，不進知識庫，免得同步軟體把套件一起傳）；幫 AI 跑它寫的做檔腳本（路徑程式設好）；轉 PDF、Excel 重算、轉成圖片看版面（包住 LibreOffice，有 Office 時可改用；處理中文編碼；都沒有就照實說要裝什麼）。(2) **給原檔副本**：程式把客戶原檔複製一份到工作區（`.system/temp/`，照 `temp_keep_hours` 清），AI 在副本上改；守門擋「改原檔」的理由句改成指到這個指令（現在叫 AI 用檔案工具另存，Office 檔做不到）。(3) **成品放進 AI 產出**：程式把工作檔放進 `AI 產出/…`，同時備進回合（退回會拿掉）、登記清冊（AI 產出、改自哪份原檔），之後照常做卡；守門加一條：腳本直接寫進 `AI 產出/` 的一律擋、理由句指到這個指令（只多擋不多放，仍做 security-review）。**這版不做**：PowerPoint 字超出框的程式檢查（字型寬度估不準；AI 轉圖看，有改到字變多的頁就提醒她用 PowerPoint 打開確認）；Docs 匯出存檔的專用指令（程式拿不到 claude.ai 登入；小檔 AI 自己把匯出的編碼內容存成檔再經 (3) 放進來，有圖的請她在網頁按匯出、存進登記的夾）。
- 為什麼：B-081 spike：做檔、改 XML、看圖模型都一次做成，坑全在環境：技能說「預先裝好」的套件 Windows 上沒有、要設路徑；技能附的 LibreOffice 工具在 Windows 原樣全失敗（AF_UNIX）、有一支寫到 `C:\tmp`；Windows 沒有 zip；每個對話重摸一次既浪費又不穩。守門那題（第 9 題）：腳本寫進 AI 產出的 Word 沒備份、沒登記（R-01 說的「程式會先備份、登記」只認檔案工具，二進位檔寫不了），退不掉也找不到；`cp 原檔` 被擋、理由句叫 AI 做做不到的事，換成 python 讀就放行，看起來像繞路。由程式把關口守住，不靠 AI 記得（D-132）。
- 放棄了：全交模型自己處理（每次重摸、成品在知識庫保證之外）；PostToolUse 看 Bash 寫了什麼來補登記（要從指令字串猜寫了哪些檔，守門題證明 shell 字串啟發式一直破，I-106）；做字寬估算與 Docs 匯出指令。
- 重談條件：客戶電腦常裝不起來套件；或確認時 AI 常被「直接寫 AI 產出」的新規則擋住又不會改走 `kb office`。
- **2026-10-21 補**（使用者定）：分兩組：`kb office` 管工具與原檔副本（查、裝、跑腳本、轉 PDF、重算、轉圖、給副本），`kb output save` 管成品放進知識庫、不限檔案種類（PDF、圖片、Docs 匯出、網頁下載的 Excel 都走它）；三件事各自單獨用得到（新做的不用副本、只看版面的不用放成品）。守門細節寫 spec 時查程式後定：AI 產出本來就擋指令寫入，但判不出 `node x.js "AI 產出/…"` 是寫，改成指令裡看得到 AI 產出的路徑、又不是單一 kb 呼叫就擋（讀也擋），腳本寫死路徑的由掃描補登記（見 produce spec 釐清）。

## D-173 manage 幫忙刪原檔：先講後果、明確確認，丟進資源回收筒

## D-174 不讀某夾的卡跟著拿掉；「不想讓 AI 看到」同一句話清乾淨（D-024 補）
- 日期：2026-10-22
- 選了：(1) 拿掉來源、排除（「用不到」與「不想讓 AI 看到」兩種）時，那夾的檔案卡一起拿掉（先備進回合，退回救得回），相關綜合卡列待更新。(2) 「不想讓 AI 看到」在同一句話裡做完：程式排除並列出受影響的綜合卡 → AI 當場照 `rules/synthesis.md` 重寫、拿掉那夾的內容 → 最後程式清殘留：那夾的檔案卡（含回合備份裡的舊版）、暫存、待處理、清冊（已是如此），以及含那夾內容的綜合卡舊版（含這一回合重寫前剛備的那份；那幾個回合的綜合卡因此退不回）。清殘留排在重寫之後；中途停下來，沒重寫完的綜合卡由程式一直列著，清殘留等全部寫完才跑。(3) 工作日誌（D-065 永久）：「做了」「改了」的檔名換成「（已排除）」，客戶自己的問句不動；有改到那夾的回合，「結果」整欄遮掉。只讀過沒改的回合程式不知道，遮不到；這點與 Claude 自己的對話紀錄、已送過雲端的，回答照實講清不掉。指令與順序細節 spec 定。
- 為什麼：卡留著沒有原檔，會被誤說成「原檔不見了」（B-059），也會被 answer 當事實引用；隱私比退回重要（D-024），只清卡不清綜合卡舊版，退回一次內容就回來了；列待更新拖到下次整理，那段時間綜合卡還寫著她不想讓 AI 看的事。
- 放棄了：卡留著（孤兒卡）；綜合卡列待更新、下次整理才重寫；綜合卡舊版留著保退回；工作日誌只遮檔名不遮結果。
- 重談條件：受影響的綜合卡常多到一句話做不完；或客戶常排除後又加回來、嫌卡要重做。
