### D-171、D-172 能不能照做

- **D-171（公開 repo 放清單與 zip、用網址加市集）：能照做。** 桌面版收 https 的清單網址、沒有錯誤（1-2）；archive 來源的 zip 帶 sha256 裝得起來（1-3）；不用 Git、不用帳號。App 把市集來源同時寫進 `known_marketplaces.json` 和使用者的 `settings.json`（1-2、1-3），跟 D-171「服務人員寫 `extraKnownMarketplaces`、`enabledPlugins`」是同兩段——**用畫面裝就等於寫了這兩段**，不用另外手寫。
- **D-172（服務人員在畫面手動裝；裝前更新 Claude）：能照做，但有三處要改寫。**
  1. 「說明 → 檢查更新」：新版已下載好時，選單裡**沒有「檢查更新」**，那格變成「重新啟動以更新至 Claude 3.1623.1」（1-1）。步驟寫成「說明選單裡有『重新啟動以更新』就按，有『檢查更新』就按」比較準。另外**桌面版更新不會順便更新內建的 Claude Code**（1-1b，仍 2.1.304，比 PATH 上的 CLI 舊），D-172「更新到最新就都過版本門檻」要以內建版本為準：2.1.304 已過 archive（2.1.224）與 `onFailure`（2.1.295）兩個門檻。
  2. 「安裝 wiki-with-willy、重開」：**不用重開**。裝完舊對話下一句就有 UserPromptSubmit／PreToolUse／PostToolUse／Stop，開新對話就有開場（1-3b、1-4、1-5）。「重開」可以改成「開一個新對話」。
  3. 「安裝」要寫清楚按哪裡：卡片上的「＋」一下就裝成**整台電腦（user 範圍）**，沒有警告也沒有確認（1-3）；目錄詳細頁的「安裝 ⌄」下拉有「為我安裝／為專案安裝（共用）／安裝至專案（個人）」三個（2-1b）。給客戶裝 user 範圍是對的，就按「＋」或選「為我安裝」。
- **不能讓 Claude 代點**：computer use 不能操作 Claude 桌面版自己的視窗，這是固定規則（0-3）。裝、更新、移除只能由人點，或用 CLI。
- **hook 用的 Python 在中文 Windows 預設 cp950**（1-5a、1-5b）：真 plugin 每支 hook 都已經自己換成 UTF-8，開場中文正常（2-3）；以後新加的 hook 也要照做。

### 升級那題要知道的

- **有新版怎麼看到**：App **不會自己發現**。push 新清單後，外掛詳細頁、已裝列表、目錄卡片都沒有任何提示，「更新」鈕是灰的（1-6b～1-6g）。唯一的路是：外掛程式總覽 →「探索」→ 目錄 → 外掛程式 → Code → 市集名後面很小的「⋯」→「檢查更新」（1-6h）。檢查完也沒有訊息，只在卡片名字旁多一個沒有字的橘紅小圓點（1-6i）。
- **要點幾步**：檢查更新（上面那串）→ 點卡片 →「管理」→「更新」（滑鼠停上去才看到「更新至 0.1.1」）→ 假警報按「仍要更新」，約 7 下（1-6i～1-6k）。**更新後不用重開**：舊對話下一句、新對話開場都已是新版（1-6l、1-6m）。舊版夾不刪，標孤兒等清掃。
- **自動更新開關**：這版畫面上**找不到**（市集「⋯」、卡片齒輪、「＋ 新增 ▾」三處都沒有，1-7a、1-7b）；`known_marketplaces.json` 也沒有這個欄位。D-171 說的 marketplace `autoUpdate` 只能靠寫設定檔，畫面上預設是什麼看不出來。
- **假警報（B-008）確定重現，原因也找到了**：「更新將覆寫本機變更：有 392 個檔案已在本機修改」那 392 個，剛好是舊版夾裡 Claude Code 自己留的 `.in_use` 使用中標記，plugin 本身的檔一個都沒改（1-6k）。標記是**每個載入這個 plugin 的 Claude Code 程序留一個**，user 範圍的 plugin 會被這台電腦上所有 Claude Code（評測、`claude -p`、別的實驗）載入，13 分鐘就累積了 392 個（1-6n）。客戶電腦上只開對話的話累積得慢，但只要有標記就會跳這個警告，服務人員或客戶要知道「按仍要更新沒關係」。

### 移除與裝回

- **畫面上「移除」不等於停用**（3-1、3-2a）：local／project 範圍裝的，移除只刪 `installed_plugins.json` 那筆與 cache，**設定檔裡的 `enabledPlugins` 留著**；市集是 directory 來源時，hook 直接從原始夾跑，所以移除後在那個夾開新對話照樣有開場、守門照擋，而 `claude plugin list`／`uninstall` 都看不到它。user 範圍用畫面移除沒有這個問題（1-8a，`enabledPlugins` 那行刪了、hook 立刻停）。
- **三種清法的差別**：
  - 畫面移除（local）：設定留著。
  - `claude plugin disable … --scope local`：沒安裝紀錄也肯做，改成 `false`、不刪行（3-2e）。
  - `claude plugin uninstall … --scope local`：整行刪掉（收尾-1）。user 範圍的 uninstall 會刪 plugin 的 data 夾、cache 留成孤兒；畫面移除則相反，刪 cache、留 data 夾（3-4b 對 3-1）。
- **生效時機**：設定一改，**下一句就生效**，不用開新對話（收尾-2）；同一回合裡還是舊的（3-2e）。
- **知識庫完整保留**：移除期間 `知識庫\` 的檔、`.system\`、工作日誌都在，來源夾沒被動到（3-2b、3-2c）；裝回後開場、回合、工作日誌直接接上，舊紀錄都在（3-4d、3-4e）。
- **沒開場時 AI 的反應符合 CLAUDE.md**（3-3）：不改檔、說程式沒跑起來、主動提要查 Python。但 CLAUDE.md 只寫了「沒裝 Python」這一種原因，plugin 被停用或移除時客戶照著查會查不到；可以考慮加一句「Python 正常就請服務人員看外掛畫面」。
- **畫面重裝很容易裝錯範圍**：3-4a 使用者在畫面上重裝，又裝成整台電腦；2-1b2 選「專案」裝到的是外掛頁資料夾鈕的夾（`install-spike\`），不是知識庫夾。選單上沒寫「專案」是哪個夾。給客戶裝 user 範圍時不會遇到，但測試、確認 session 用 local 範圍時，**用 CLI 在知識庫夾裝才可靠**（2-1c、3-4c）。
- **移除後「不讀」就沒人守了**：hook 一停，排除夾的檔名在 Glob 結果裡就看得到（收尾-2）。
