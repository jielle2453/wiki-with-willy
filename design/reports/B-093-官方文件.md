桌面版安裝與發行那題（D-171、D-172）談的時候查的，原本放在那題的 spec 草稿；那題不寫 spec（D-133 2026-10-22 補），spike 完收到這裡。第 (6) 題（升級）與密碼與守門（`onFailure`）會用到。實測結果見 `B-093-spike.md`。

## 官方文件查到的（2026-10-21，code.claude.com/docs 的 plugins 與 hooks、setup 頁）
- marketplace 來源：`owner/repo`、git 網址（要 Git）；其他 https 網址當成 `marketplace.json` 抓（不用 Git）；本機夾或 json 檔。網址來源的清單不能用相對路徑的 plugin，要用 github、git-subdir 或 archive。
- archive：https 的 zip 帶 sha256，不用 Git，Claude Code 2.1.224 以上；下載上限 256 MiB、120 秒。
- 私有 repo：靠客戶電腦既有的 git 認證（ssh 金鑰或 credential helper），只設 token 不算。
- 預先設定：使用者或受管設定寫 `extraKnownMarketplaces` 加 `enabledPlugins`，下一次開 session 自動登記並安裝。
- 自動更新：每個 marketplace 一個 `autoUpdate`，第三方預設關；開了之後第一句話後隨機 10 分鐘內在背景更新，下次 session 或 `/reload-plugins` 生效（給升級那題）。
- Windows：Git for Windows 選配，沒有就用 PowerShell 當指令工具（守門已攔 PowerShell）。桌面版有沒有內建 Git 沒寫。
- hook 失敗：預設放行；`"onFailure": "block"`（2.1.295 以上）會擋（B-016，歸密碼與守門）。

## 之後補問到的（2026-10-22）
- plugin.json 與 marketplace 條目都**沒有**宣告最低 Claude Code 版本的欄位；hooks.json 遇到舊版不認得的欄位（如 `onFailure`）會怎樣，文件沒寫。
- hook 拿不到 Claude Code 版本號（環境變數與輸入都沒有）；對話紀錄每行有 `version`，但開場那一刻讀不到（B-093 1-5b）。
- 網址來源的清單：頂層要 `name`、`owner.name`、`plugins`；條目要 `name`、`source`；archive 的 zip 根目錄或下一層放 plugin 都可以；跟著轉址最多 5 次、都要 https；sha256 是整個 zip 的 64 位十六進位。
