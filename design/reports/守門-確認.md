### 第 2、7 步的原因
`kb guard decide --tool Read --path …\薪資\s.xlsx --cwd <vault>` 印 `deny Z10 excluded 這個夾你說過不讀；…`，所以判斷邏輯是對的。問題在呼叫順序：Claude Code 2.1.296 的 Read 會先檢查輸入（副檔名是二進位就拒絕），檢查不過就不會叫 PreToolUse hook。同一個夾用非二進位檔名 `note.txt` 去 Read，hook 有跑，Z10 有擋，ledger 也有記。

影響：
- 不會外洩：Read 本來就讀不了 xlsx。AI 會改走 Bash／python，那條路守門會擋（第 4 步與第 7 補）。
- 客戶聽到的理由不對：AI 會說「這是二進位檔，讀不了」，而不是「這個夾你說過不讀」，可能接著提議「我用 python 讀」，然後才被擋。多一個來回，而且第一句理由不對。
- 事件帳少記：直接 Read 排除夾的二進位檔不會留 ledger 行，lint 算趨勢時會漏掉這類事件。

建議（給設計 session 決定，我沒改任何程式）：確認情境第 2、7 步改用排除夾裡的文字檔（例如 fixture 加 `薪資/s.txt` 或 `s.csv`），或把預期改成「被擋即可，理由可能是 Claude Code 的二進位檢查」；第 9 步的預期行數跟著調整。要不要讓 AI 在 Read 被拒後先問 `kb guard decide` 再提議別的讀法，可以進 backlog。
