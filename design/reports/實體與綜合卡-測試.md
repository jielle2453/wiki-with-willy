## 發現

### F1（中）`by:program` 的備份先到，會讓 AI 之後改同一張綜合卡不被 D-075 數到
`turn.backup` 同回合同路徑只做第一次；寫檔案卡後程式的 `render_cache` 先備份了綜合卡（`by:"program"`），AI 接著照 `synthesis_stale` 改寫同一張時，`before_write` 看到已有紀錄、不再檢查門檻，`modified_synthesis_count` 又略過 program 的那一行。實跑（回合內：寫一張掛信義王的檔案卡 → 用 Write 改寫信義王綜合卡）：manifest 只有 `{"path":"案子/信義王/信義王.md","action":"modify","by":"program"}`，`turn.modified_synthesis_count(vault, 該回合)` = **0**，`big_change_synthesis_max` = 10。ingest 的正常順序（先寫檔案卡、再改 stale 綜合卡）幾乎每張都這樣，所以「AI 一回合改 10 張以上綜合卡要先問客戶」這道門在更新情境下實質失效。建議：AI 的寫入要能把這條路徑從 program 轉成要計數的（例如 manifest 多記一行 AI 的 modify，或計數時 program 與 ai 分開記同一路徑）。

### F2（中）`rename`／`merge` 在中途被拒或失敗，留下一半
`entities.rename` 先 `retarget_cards`（改完全部檔案卡的 `實體` 欄），最後才 `_save` `entities.json`；`_move_card` 的拒絕（目標已有檔）或 `os.rename` 失敗發生在中間。
- 確定性版本：`案子/王宅/王宅.md` 已有一個客戶的檔，`rename 信義王 --to 王宅` → 印 `「案子/王宅/王宅.md」已經有檔，沒有改名；先把它搬走` exit 3，**但兩張檔案卡已經是 `實體: [王宅]`**，`entity list` 變 `信義王…掛 0 張，有綜合卡`、`cards todo` 之後 PostToolUse 會對這些卡說 `實體「王宅」還沒登記`。不會自己好，客戶要先搬走檔、再重跑。
- Windows 版本：夾裡有檔被別的程式開著（用一個持有 `合約.docx` 的程序模擬）→ `沒有寫入：PermissionError: [WinError 5]…` exit 3，檔案卡一樣先被改了；關掉檔案重跑一次就恢復（實測）。訊息說「沒有寫入」是錯的。
- `merge` 同型：`retarget_cards` 與 `_delete_card` 在 `_save` 之前。
建議：先驗目標路徑、先搬夾，最後才改檔案卡與 `entities.json`；或失敗時把已備份的檔案卡還原。

### F3（中低）merge 進一個已有綜合卡的實體後，那張卡變成 `synthesis_broken`，不是 `synthesis_stale`，快取也不會更新
`merge` 把來源名稱加進目標 `aliases`，但目標綜合卡檔頭的 `別名: []` 沒跟著改。實跑：`merge 王宅 --into 信義王` 之後 `validate` 回 `「別名」照 kb cards todo 給的檔頭抄`，`cards todo`：`synthesis_stale` 空、`synthesis_broken` 一項（`reason` 同上，沒有 `header`）、`entity render` 印 `重寫了 0 張`（`render_cache` 只動合法或只差整理到的卡），所以 `merge` 印的 `信義王的綜合卡下次整理會補上這 1 張` 對不上實際：新掛的那張在 `broken` 時看不到 `added`。AI 手改 `別名` 那行（Edit）後才會變成 `stale added`（實測，過程中 PostToolUse 還會先打回 `整理到不是現行的`）。建議：merge 時一併改寫目標卡的 `別名`（像 rename 那樣用 `replace_front`），這樣就走 stale。

### F4（低中）實體名稱的字元規則放行了 `,` `[` `]`，這些名稱寫不進檔案卡檔頭
名稱規則同型別名（為了夾名），但名稱同時要放進一行清單 `實體: [..]` 與 `別名`、`相關實體`。實跑：`entity add --type 案子 --name "Smith, John"` 成功，卡寫 `實體: [Smith, John]` → block `實體「Smith」還沒登記，先跑 kb entity add`；`x]` → `檔頭解析不了：清單裡不能再有清單`；`"Smith, John"` 用引號包也不行（`實體「"Smith」還沒登記`）。英文公司名帶逗號（`Lee, Inc`）是現實會遇到的。`ABC Co., Ltd.` 剛好因為結尾的點被擋。建議：`name_problem` 另外擋 `, [ ] #`（或在清單解析支援跳脫）。
### F5（低中）`entities.json` 壞了：所有第二版檔案卡寫不進去、`cards todo` 整個失敗，訊息沒指到檔名
`entities.json` 寫成 `{bad` 後：`cards todo` → `狀態檔讀不到：Expecting property name enclosed in double quotes…` exit 3（沒說是哪個檔）；寫任何第二版檔案卡 → block `檔頭有錯：檔頭解析不了：JSONDecodeError`（把狀態檔的錯說成卡檔頭的錯，AI 會一直重寫正確的檔頭）；`entity list`／`add` exit 3；沒有 `kb` 指令能修它。`session` 與 `changes` 不受影響（I-046 在那兩處做到了）。`entities.json` 只准程式用原子寫，壞掉機率低（OneDrive 衝突、手改），影響是整個 ingest 停擺。建議：`_entity_problems` 遇到 `ValueError` 回一個指到 `entities.json` 的原因，`cards todo` 的拒絕句帶檔名。
### F6（低）`profile apply`：`entities.sync_self` 失敗時設定檔已寫完，重跑變成「沒有改」，第五節永遠進不了 `entities.json`
`entities.json` 壞著時加第五節一列並 `apply` → `狀態檔讀不到：…` exit 3，`profile.json`／md 已寫；再跑 `apply` → `客戶設定檔沒有改，沒有套用` exit 0。修好 `entities.json` 後 `profile check` 也說沒有改。客戶自己就沒被登記成 `self`。（code-review 也提出。）
### F7（低）`cards.rewrite_entities` 只換 `實體:` 一行
檔案卡用區塊寫法（`實體:` 接 `  - 信義王`）時，`rename` 後變成 `實體: [信義王大安, 林小姐室內設計]` 加上原來的 `  - 信義王`、`  - 林小姐室內設計` 兩行殘留（實測），解析成 4 項，舊名成別名後被 PostToolUse 判「該寫登記的名稱」。範本與 carding.md 都教行內寫法，只有 AI 自己寫成區塊才會遇到；`synthesis.replace_front` 已有處理續行的做法可共用。
### F8（低）`entity clean` 不正規化 `..`
`clean "案子/../z.md"`（z.md 在知識庫根、檔頭有 `編號: e-…`）→ 印 `已清掉放錯的綜合卡：案子/../z.md` 加 `夾裡還有 31 個檔，夾留著`，**實際刪的是知識庫根的 z.md**（備成 delete，退得回來）。範圍受限：路徑只能是三段、第三段是 .md、檔頭要有 e- 編號。總資料夾外的絕對路徑被擋（`不在總資料夾裡`）。
### 其他（code-review 提出、我讀了碼沒實跑、都不嚴重）
