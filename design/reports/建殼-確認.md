## 四步

### 1. 開場錯誤或警告
- 實際看到：我的 context 裡沒有任何錯誤或警告，也沒有 plugin 載入失敗的訊息。開場只有 superpowers plugin 的 SessionStart hook 注入的內容，那是另一個 plugin。
- 落差：終端機畫面上印的開場訊息我看不到，只看得到注入 context 的內容。要確認「畫面上零錯誤」需要人看一眼終端機。`~/.claude/debug` 不存在，沒有 debug log 可以查。
- 補充：`claude plugin validate "C:\Users\Jie\Desktop\llm-wiki-j"` exit 0，結果是「Validation passed with warnings」，警告一條：
  `root: CLAUDE.md at the plugin root is not loaded as project context. To ship context with your plugin, use a skill (skills/<name>/SKILL.md) instead.`
  這是預期中的：repo 的 CLAUDE.md 是寫給改 repo 的 Claude，本來就不是 plugin 的 context。不過以後每次跑 plugin 驗證都會看到這條，可以考慮在 repo 的 CLAUDE.md「改完要做的事」裡註明這條警告可以忽略。

### 2. 「你有哪些 wiki-with-willy 的指令」
- 實際看到：沒有任何 `wiki-with-willy:` 開頭的 skill 或 command，也沒有屬於它的 hook。回答時沒有觸發任何 skill。
- 符合預期（沒有，或清單是空的）。
- 落差（風險）：同一個 session 裡有另一個 plugin `llm-wiki@llm-wiki`，來源是 github `Q00jkf/llm-wiki-plugin`，在使用者層 `~/.claude/settings.json` 的 enabledPlugins 啟用。它帶了 13 個 `llm-wiki:wiki-*` skill（wiki-init、wiki-query、wiki-ingest、wiki-core 等）。問「wiki 指令」時，模型很容易把這些當成答案。以後 wiki-with-willy 有 skill 以後，兩者的 description 會在同一個領域互搶觸發，確認測試也會被它干擾。建議：之後的確認情境先停用 `llm-wiki@llm-wiki`，或在乾淨的使用者設定下開。
