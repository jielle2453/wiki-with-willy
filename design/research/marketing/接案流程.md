# 接案流程：建置時要裝什麼、一位客戶從洽談到結案

這份由兩份合併（2026-10-10）：第一部分是建置安裝清單（現行），第二部分是流程演練（2026-10-08 寫於 Cowork 時期，部分已過時，待依桌面版更新）。

## 第一部分：建置安裝清單

日期：2026-10-10
依據：決策 #44（Word／Excel 用 Anthropic 文件技能）、#45（照客戶原本的習慣，不幫客戶裝辦公軟體）；實測見 `實測/doc-skill-workspace/測試結果.md`、`實測/format-workspace/測試結果.md`。
狀態：清單已定；plugin **0.13.0 已照這份改**（第七節；另加 envcheck 的 Office 自檢，spec 4.9）。

### 結論先講

- 要裝的只有 **Python、一行 pip 指令、Node.js＋docx 套件**，Git 待確認。合計約 0.5–0.8 GB（推估）。
- **整個建置不需要管理員權限。**
- 不幫客戶裝辦公軟體：客戶有 Microsoft 365 桌面版就用 Office，沒有就做輕量功能。
- 刪除了 7 項原本列過或考慮過的東西（第六節）。

### 一、要裝的（每個客戶都一樣）

| # | 項目 | 用途 | 大小（推估） | 要管理員嗎 | 怎麼裝 |
|---|---|---|---|---|---|
| 1 | Python 3.10 以上 | plugin 所有程式 | 約 100 MB | 不用 | `winget install Python.Python.3.12`，或 python.org 下載（勾選加入 PATH） |
| 2 | markitdown（含各格式）＋pdfplumber | 讀 Word、Excel、PowerPoint、PDF；製卡、算文字指紋；文件技能也會用到 | 約 300 MB | 不用 | `python -m pip install "markitdown[docx,pptx,xlsx,xls,pdf]" pdfplumber`（和現在一樣） |
| 3 | Node.js | docx 技能產生新 Word（技能規定用 docx-js） | 約 100 MB | 不用 | 官方 zip 版解壓縮，或 `winget install OpenJS.NodeJS.LTS` |
| 4 | npm 的 docx 套件 | 同上 | 約 23 MB | 不用 | `npm install docx`（裝的位置待 spec 決定） |
| 5 | Git for Windows | plugin 程式用 Bash 執行（PowerShell 遇到中文路徑會一直跳權限詢問） | 約 300 MB | 一般不用 | `winget install Git.Git`。**待確認**是否需要（第五節） |

第 2 項會**自動一起裝**下列套件，不用另外列：openpyxl、pandas（讀寫 Excel）、lxml（python-pptx 需要）、defusedxml（markitdown 需要）、pypdfium2、pdfminer.six（pdfplumber 需要；pypdfium2 也拿來把 PDF 頁面轉成圖片）、magika／onnxruntime（markitdown 判斷檔案類型）。

以上都是有數位簽章的官方版本，開著 Windows「智慧型應用程式控制」也能執行。

### 二、不用裝，但要確認有

| 項目 | 說明 |
|---|---|
| Claude 桌面程式＋付費方案 | 客戶日常用的窗口（Code 分頁） |
| docx、xlsx 技能 | 從客戶的 claude.ai 帳號**自動同步**到 Claude Code（`~/.claude/skills/synced/…`）。專有授權，**不能**放進 plugin。客戶的方案會不會同步，要在端到端試跑確認；同步不到時改裝 GitHub 上的 anthropics/skills |

### 三、有就用，沒有不裝（照客戶原本的習慣）

| 客戶原本有 | 用來做 | 沒有時 |
|---|---|---|
| Microsoft 365 **桌面版** Word、Excel | Excel 改完後重算、Word 轉 PDF（AI 檢查排版、給客戶 PDF）、舊版 .doc 轉 .docx（背景操作，**未測**） | 輕量：Excel 只改數字、客戶打開時才重算；不給 PDF；舊版 .doc 請客戶另存 |
| LibreOffice（客戶原本就在用） | 同上 | 同上 |
| Google 文件、試算表 | 存到 Google 雲端硬碟；做法等第一位 Google 用戶再設計 | — |

注意：Microsoft 365 有些方案**只有網頁版**（例如商務基本版），沒有桌面版 Word、Excel，照「沒有」處理。

### 四、建議但不必裝

| 項目 | 為什麼只是建議 | 大小 | 要管理員嗎 |
|---|---|---|---|
| Visual C++ 2015-2022 執行環境（14.3x 以上） | 太舊時 onnxruntime 載入會讓 Python 崩潰；plugin 會偵測並自動改用替身，不影響使用。更新後讀檔的檔案類型判斷比較準 | 約 25 MB | **要** |
| Windows 長路徑 | 程式已用長路徑方式讀檔，一般不影響 | — | 要 |

### 五、待確認

| 項目 | 要確認什麼 | 在哪裡確認 |
|---|---|---|
| Git for Windows | 桌面版 Claude Code 沒裝 Git 時，有沒有 Bash 工具可用；如果桌面版本身就需要或已內建，就不用另外列 | 端到端試跑 |
| Node.js 的替代 | 有 Microsoft 365 桌面版的客戶，能不能讓 Word 自己產生新文件，就不用裝 Node.js | 有 Office 的電腦 |
| docx、xlsx 技能同步 | 客戶的方案、設定會不會同步技能 | 端到端試跑 |
| 用 Office 背景操作 | 重算、轉 PDF、處理 Office 跳出的視窗 | 有 Office 的電腦 |

### 六、已刪除

| 項目 | 原本為什麼列 | 刪除原因 | 日期 |
|---|---|---|---|
| **LibreOffice** | Excel 改完後重算公式、Word 轉 PDF 檢查排版、舊版 .doc 轉檔 | 決策 #45：辦公軟體照客戶原本的習慣，客戶沒在用就不裝。有 Microsoft 365 桌面版的客戶改用 Office 本身做；測試時解壓縮約 1.6 GB，正式安裝可能要管理員 | 2026-10-10 |
| **pandoc** | docx 技能用它讀 Word；格式測試曾建議用它把 Markdown 轉成 Word | markitdown 已能讀 Word；產生新 Word 改用 docx 技能（Node.js） | 2026-10-10 |
| **poppler** | 製卡代理讀超過 10 頁的掃描 PDF；docx 技能把 PDF 轉成圖片 | 沒有數位簽章，開著「智慧型應用程式控制」的電腦會被擋（實測）。改用 pdfplumber 已附帶的 pypdfium2（待辦 #17：製卡代理與 envcheck 要跟著改） | 2026-10-10 |
| **PyMuPDF** | 測試時用來把 PDF 轉成圖片 | AGPL 授權，商業服務使用有疑慮；pypdfium2 能做同樣的事，是寬鬆授權，而且已經跟著 pdfplumber 裝了 | 2026-10-10 |
| **python-docx** | 原本草案（決策 #37）自己寫程式改 Word | 改用 docx 技能（決策 #44）；技能改 Word 是直接改 XML，不需要 python-docx | 2026-10-10 |
| openpyxl、lxml、defusedxml（另外列） | 改 Excel、檢查 Word 修訂 | 不是不用，而是 markitdown 已經會一起裝，不必另外列 | 2026-10-10 |
| Visual C++ 列為必裝 | e8 實測舊版會讓 LibreOffice 起不來、markitdown 崩潰 | 不裝 LibreOffice 之後，只剩 onnxruntime 需要，而 plugin 有替身。**改成建議**（第四節），建置因此不需要管理員 | 2026-10-10 |
| Claude for Word／Excel 外掛 | 修訂標記、Excel 自己重算 | 是第二個窗口，產品負責人要求客戶只用一個窗口；也沒辦法從 Claude Code 指揮它 | 2026-10-10 |

## 第二部分：流程演練（歷史）

日期：2026-10-08
用途：用一位虛構客戶，把 [服務設計](服務設計.md) 的服務流程與 [spec](../design/spec.md) 的 plugin 操作串起來走一遍，檢查哪裡接不起來。

**範例客戶：林小姐，接案室內設計師。** 電腦裡有「客戶案件」「報價與合約」「廠商資料」「公司行政」四個資料夾，約 1,200 份檔案，用 Google 雲端硬碟同步到 D 槽。

### 總覽

| 時間 | 階段 | 主角 | 用到的 plugin 元件 |
|---|---|---|---|
| 第 0 天 | 洽談與訪談 | 你 | 示範知識庫、訪談問題清單 |
| 第 1 天起 | 建置 | 你在 Claude Code 操作，AI 執行 | 指令：建置準備、盤點、試讀、製卡、收尾 |

| 第 4–17 天 | 磨合 | 客戶日常使用，你調整 | 技能：問知識庫、起草文件、更新、健檢、改動與退回；指令：磨合調整 |
| 第 18 天 | 結案 | 你 | 技能：健檢 |

plugin 還沒有安裝。

### 第 1 天起：建置

你在林小姐的電腦上用 Claude Code，登入她的帳號。

#### 步驟 1　準備（指令：建置準備）

- 安裝 Python、MarkItDown、plugin。
- 建立 `文件/我的知識庫/`，放入空白結構。
- 填來源清單：三個分區對應三個資料夾；「公司行政/薪資」列入排除。
- 把訪談內容寫進客戶設定檔。

#### 步驟 2　盤點（指令：盤點）

清冊程式走訪資料夾，只看結構。你在畫面上看到的範例：

```
共 1,184 份檔案：Word 312、Excel 205、PDF 498（約 120 份疑似掃描檔）、PowerPoint 41、其他 128
跳過：暫存檔 37、捷徑 12、排除的資料夾 64 份
重複檔：53 組
雲端占位檔：88 份尚未下載到電腦 → 請林小姐設定為保留在裝置
分區建議：客戶案件（依案件子資料夾）、報價與合約、廠商資料
估計：約 9 小時、XX 萬 token；以她目前的方案約需 2 到 3 天
```

產出：檔案清冊。你和林小姐決定先處理哪一區。

#### 步驟 3　試讀（指令：試讀）

AI 每區抽樣十幾份讀內容。你只看到推測的文件類型：

```
報價單、合約、平面圖說明、會議紀錄、廠商型錄、請款單
```

推測的人名、廠商名、案件名也寫進了設定檔，標為「推測」，你不看。

#### 步驟 4　製卡（指令：製卡）

轉換程式把檔案轉成文字 → AI 製卡 → 刪除暫存文字。每批完成就更新索引、清冊、改動紀錄。

```
第 7 批／共 24 批｜完成 341｜失敗 6
```

額度用完或電腦關機時，下次輸入「製卡」就從清冊記錄的斷點繼續。

#### 步驟 5　收尾（指令：收尾）

AI 寫出各分區總覽、總目錄、讀取問題清單、「我對你資料的理解」頁、三個建議問題。你看到建置報告：

```
完成 1,031 張卡
讀取問題 14 份：.doc 舊檔 5、加密 PDF 2、掃描品質太差 7
```

### 第 3 天：交付（指令：交付確認）

帶林小姐打開 Cowork，連接知識庫與三個來源資料夾。

#### 1. 看「我對你資料的理解」

```
你的主要客戶：信義王、大安陳、內湖李…
常往來的廠商：XX 木作、YY 系統櫃…
你的文件類型：報價單、合約、平面圖說明…
```

她修正兩個錯的、確認其他的。設定檔中這些條目從「推測」變成「客戶確認」。

#### 2. 問第一個問題（從建議問題中選）

> **林小姐：** 信義王那案的系統櫃，最後是跟誰報價、多少錢？
>
> **AI：** 最後採用 YY 系統櫃的第二版報價，總價 NT$186,000。
> - 第一版 NT$212,000，2025-04-02［出處：報價與合約/信義王/YY報價v1.pdf 第 2 頁］
> - 第二版 NT$186,000，刪除了更衣室吊櫃［出處：…/YY報價v2.pdf 第 2 頁］
> - 合約確認採用第二版［出處：…/信義王合約.docx 第 4 條］
>
> 已存成「信義王專案」頁。

背後發生的事：

1. 讀總目錄 → 選「報價與合約」與「客戶案件」兩區。
2. 讀兩區的索引挑卡片 → 讀卡片。
3. 金額回原檔核對。
4. 回答並附出處。
5. 整合了三份資料，所以存成綜合頁。
6. 寫改動紀錄與版本備份。

#### 3. 交給她速查卡與資料去向說明

### 第 4–17 天：磨合期

#### 日常使用（技能：問知識庫、起草文件）

| 林小姐說 | 系統做什麼 |
|---|---|
| 「大安陳的平面圖在哪？」 | 找檔案：列出位置 |
| 「內湖李現在進度到哪？」 | 掌握背景：產生「內湖李專案」綜合頁 |
| 「照信義王的格式幫我寫一份新報價」 | 起草：產出新檔到 `我的知識庫/產出/`，不碰原資料夾 |
| 「XX 木作的統編是多少？」 | 統編不屬於敏感資料，正常回答 |
| 「員工的身分證字號？」 | 該資料夾已排除；就算出現在其他檔案，卡片也只記「含有」，答案指向原檔 |

#### 被糾正

> **林小姐：** 不對，信義王最後是請 ZZ 系統櫃做的，YY 那份只是比價。
>
> **AI：** 已修正「信義王專案」頁，並記下「信義王的系統櫃由 ZZ 承作」。原本的頁面可以退回。

設定檔的糾正紀錄多一筆，以後不再犯。

#### 每次開始使用時的更新（技能：更新知識庫）

```
有 6 份新檔案、2 份修改過，已整理好。
「大安陳專案」頁因報價更新，標為待更新。
```

如果她把「客戶案件」整個資料夾搬走：

```
「客戶案件」資料夾找不到了，是改名或搬家了嗎？
```

她回答新位置 → 只改來源清單一處，所有卡片的出處自動恢復。

#### 每週健檢（技能：健檢，Cowork 排程或手動）

```
這週整理了 23 份新檔案。需要你看一下：
- 「大安陳專案」有兩份報價的總價不同，哪一份是最終版？
- 有 3 個推測的廠商名稱還沒確認。
- 你可能想問：「今年哪些案子還沒收尾款？」
```

#### 大改動

```
你要求的整理會改動 14 頁，已放進待確認清單，要我現在執行嗎？
```

#### 你在磨合期做的事（指令：磨合調整）

林小姐回報「AI 常把型錄當成報價單」→ 你在設定檔的文件類型加上判斷線索 → 重做受影響的卡片。你只看她回報的問題類型，不看檔案內容。

### 第 18 天：結案

- 最後一次健檢。
- 說明之後的運作：新檔案自動納入、每週健檢、答錯就直接糾正。

### 演練中發現的薄弱處

尚未寫進 spec 或服務設計。

| # | 地方 | 問題 | 可能的方向 |
|---|---|---|---|
| 1 | 盤點時的雲端占位檔 | 占位檔要先下載才能讀；客戶的雲端資料很多時，下載本身就要花時間，流程沒有安排 | 盤點報告估算下載量；在建置前一天請客戶先下載 |
| 2 | 建置跨多天 | 你是每天到場，還是讓製卡在客戶電腦上自己跑？ | 製卡分批自動執行，額度用完就停、恢復後續做，你遠端看進度。若改用 API 製卡，這個問題大致消失（見服務設計第十一節） |
| 3 | 安靜模式 | 試讀與製卡時，Claude Code 畫面可能還是會閃過內容 | 待 spec 待驗證第 9 項的結果 |
| 4 | 交付確認頁 | 推測的人名可能有幾十個，客戶很難一次確認完 | 只列最常出現的前幾名，其餘在健檢時陸續確認 |
| 5 | 起草的檔案 | 產出放在知識庫裡，客戶可能找不到 | 回答中直接附檔案連結，並建議搬到工作資料夾 |
| 6 | 磨合期的回報 | 客戶怎麼把「AI 常把型錄當成報價單」這類問題傳給你？ | 定一個回報管道與格式，只描述問題類型、不附內容 |
