## 目的
PreToolUse 守門 hook：客戶原檔只讀、排除的夾 AI 看不到、總資料夾裡每一區照路徑表決定能不能寫、`kb.py` 不用按允許。這是六個面裡「資料去了哪」由機器保證的那一層，也是所有 skill 的前提：ingest 讀 raw 靠它放行，produce 寫 AI 產出靠它放行，manage 之外沒有別的路能動原檔。對應 backlog B-013 的「載入正面證據」也由它給：守門擋得住就代表 plugin 載進去了。

## 決策
D-034 守門預設嚴、D-043 實體夾其他檔是原檔、D-046 守門路徑表、D-073 讀取與 kb.py 放行走守門、D-024 排除兩種理由都不讀、D-021 可攜路徑 spec、D-027 語言分層、D-050 密碼不進狀態檔（本題不碰）。事故 I-025、I-031、I-101、I-102 第 5 點（路徑不正規化、Read 以外會繞）。

兩個本題釐清、不改 D 的點：
- `.system/ledger.tsv` 是守門**事件帳**，一行一事件（deny、解析不到）；D-064 說的「只在變化時寫、只報變差」是 lint 從事件帳算出來的趨勢摘要，不是這張表。
- 守門內部出錯時：檔案工具一律 deny 並寫 `hook-errors.log`，理由白話；Bash／PowerShell 不表態但寫 log。依 D-034 預設嚴，讀取在 auto mode 沒有別的防線（I-101）。

## 要做的事

### 1. hooks
- `hooks/hooks.json`：只有 PreToolUse 一段，matcher `Read|Edit|Write|MultiEdit|NotebookEdit|Glob|Grep|Bash|PowerShell`，command `python "${CLAUDE_PLUGIN_ROOT}/hooks/guard.py"`，timeout 10。
- `hooks/guard.py`：入口。開頭 `sys.dont_write_bytecode = True`、stdout 與 stderr reconfigure UTF-8、`sys.path.insert(0, <plugin>/scripts)`（hook 不是從 scripts/ 跑的，這是 kb.py 之外唯一准動 sys.path 的地方，寫進 CLAUDE.md）。讀 stdin JSON，呼叫 `kb.guard.decide(payload)`，拿回 `(decision, reason, ledger_rows)`，印 JSON 或不印，exit 0。任何例外：寫 `.system/hook-errors.log` 一行，檔案工具印 deny（理由「守門出錯，這次不放行。說「檢查」我看原因」），Bash／PowerShell 不印，exit 0。**永不以非 0 結束，永不丟例外到 Claude Code。**

### 2. 判斷邏輯 `scripts/kb/guard.py`
純函式，不碰 stdin／stdout，給 hook 與 CLI 共用。

- `find_vault(cwd) -> Path | None`：從 cwd 往上找第一個含 `.system/sources.json` 的目錄。找不到回 None：不是在知識庫裡開的對話，守門只做 kb.py 放行，其他不表態。
- `classify(path, vault, sources) -> zone`：正規化後判屬於哪一區。區與決定見「資料與介面格式」的決策表。
- `decide(payload) -> Decision`：依 `tool_name` 分流：
  - Read、Glob、Grep：目標是 `tool_input.file_path` 或 `tool_input.path`（Glob／Grep 沒給 path 就是 cwd）。查表的「讀」欄。
  - Edit、Write、MultiEdit、NotebookEdit：目標 `tool_input.file_path`（NotebookEdit 是 `notebook_path`）。查「寫」欄。
  - Bash、PowerShell：`tool_input.command`。先判 kb.py 呼叫：引號外沒有 `; && || | 換行`，且整句是 `python "<plugin>/scripts/kb.py" ...` 或 `python <plugin>/scripts/kb.py ...`（plugin 路徑從 `CLAUDE_PLUGIN_ROOT` 取，正規化比對）→ allow。否則抽路徑（見 3），每個路徑查表：有任一 deny 就 deny。有寫入動作（見 3）而目標落在「寫擋」區 → deny。有寫入動作但一個路徑都抽不出來 → deny，理由「看不出這個指令會寫到哪，請用檔案工具或告訴我路徑」，ledger 標 `unparsed`。其餘不表態：Bash 只有 deny 與 kb.py allow 兩種表態，提到登記來源的讀、寫 Z1／Z3 都交回預設（疑義 1，2026-10-12 定：一句指令能做的不只碰那條路徑）。
- 不表態 = 不輸出，Claude Code 走預設流程。

### 3. 路徑與指令解析 `scripts/kb/_lib/paths.py`（擴充）與 `_lib/cmdparse.py`（新）
- `normalize(p, cwd) -> str`：相對路徑接 cwd；`/c/Users/...` 轉 `C:/Users/...`；`\\?\` 前綴去掉；統一正斜線；去尾斜線；Windows 上 `normcase`（小寫）。不做 Unicode NFC。
- `inside(path, dir) -> bool`：用分段比對，`C:/a/bc` 不算在 `C:/a/b` 裡。
- `resolve_spec(spec, vault) -> str`：D-021 可攜 spec：`~/x`、`${VAR}/x`、相對 vault 根的 `x` 或 `../x`、絕對 `C:/x`。展不開的環境變數回 None，呼叫端當作來源不存在（不擋、不放，寫 ledger `unresolved`）。
- `cmdparse.extract_paths(command, cwd) -> list[str]`：抽引號內字串與含 `/` 或 `\` 的 token，去掉 `>`、`|` 等符號，正規化。照舊 guard.py 的 `ABS_PATH`、`outside_quotes`、`norm_cmd` 改介面。
- `cmdparse.is_write(command) -> bool`：引號外有 `>`、`>>`，或有寫入動詞：`rm mv cp tee touch mkdir rmdir del move copy ren rename Remove-Item Move-Item Copy-Item New-Item Set-Content Add-Content Out-File sed -i python -c`（含 `open(…, "w"`）。照舊 guard.py 的 `WRITE_WORDS`、`REDIRECT`、`DISCARD_OUTPUT`（導到 null 不算寫）。
- `cmdparse.is_single_plugin_call(command, plugin_root) -> bool`：照舊 `single_plugin_call`，腳本固定 `scripts/kb.py`。

### 4. 來源登記表 `scripts/kb/_lib/sources.py`（新）

- `Sources.lookup(path) -> ("registered"|"excluded"|None, source)`：先比排除（排除贏），再比來源。排除的 spec 相對該來源根。

### 5. 留痕 `scripts/kb/_lib/ledger.py`（新）

- `touch_status(vault)`：`.system/guard-status/<主機名>.json` 寫 `{date, python, host, plugin_version}`，同一天只寫一次（比日期）。
- `log_error(vault_or_None, text)`：`.system/hook-errors.log` 追加一行 `時間\tguard\t訊息`；找不到 vault 就寫到 `%TEMP%/wiki-with-willy-hook-errors.log`。

## 資料與介面格式

### sources.json（`.system/sources.json`）
```json
{
  "schema_version": 1,
  "sources": [
    {"id": "src-3f9a", "alias": "客戶案件", "spec": "../raw/客戶案件", "excludes": []},
    {"id": "src-7c21", "alias": "行政", "spec": "../raw/行政",
     "excludes": [
       {"spec": "薪資", "kind": "hidden", "reason": "薪資個資", "added": "2026-10-12"},
       {"spec": "舊檔", "kind": "unused", "reason": "都是舊版", "added": "2026-10-12"}
     ]}
  ]
}
```
`spec` 照 D-021；排除的 `spec` 相對該來源根。`kind` 兩值 `hidden`、`unused`，守門一視同仁都不讀。本題不提供寫這個檔的指令，fixture 手寫；`kb folders` 是另一題。

### hook 輸入（stdin，Claude Code 給的，本題用到的欄位）
`tool_name`、`tool_input`（Read／Edit／Write／MultiEdit 的 `file_path`；NotebookEdit 的 `notebook_path`；Glob／Grep 的 `path`；Bash／PowerShell 的 `command`）、`cwd`、`permission_mode`。路徑原樣不正規化（I-101）。

### hook 輸出
allow 或 deny：stdout 一行 JSON，exit 0：
```json
{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "<白話一句>"}}
```
不表態：不輸出，exit 0。理由句全中文、一句、說「為什麼」與「可以怎麼做」，例如「客戶原檔只讀。要改內容我另存一份，說「改成…」就好」。

### 決策表
路徑先正規化，區由上到下第一個命中。`V` 是總資料夾，`T` 是任一不是保留名的第一層資料夾（型別夾），保留名：`AI 產出`、`收件匣`、`檔案索引`、`系統`、`.system`、`.claude`。

| # | 區 | 讀（Read／Glob／Grep／Bash 讀） | 寫（Edit／Write／MultiEdit／NotebookEdit／Bash 寫） |
|---|---|---|---|
| Z1 | `V/T/<名>/<名>.md` 綜合卡 | allow | allow |
| Z2 | `V/T/<名>/` 其他檔 | allow | deny：原檔只讀，搬入只能經 `kb source-edit move` |
| Z3 | `V/AI 產出/**` | allow | allow |
| Z4 | `V/收件匣/**` | allow | deny：只有 `kb intake` 能寫 |
| Z5 | `V/檔案索引/**` | allow | allow |
| Z6 | `V/系統/**` | allow | deny：程式渲染，跟我說要改什麼 |
| Z7 | `V/.system/**`、`V/.claude/**`、`V/CLAUDE.md` | allow | deny：只有 kb 腳本能改 |

### ledger.tsv（`.system/ledger.tsv`）
欄位：`time	tool	decision	zone	reason_code	path_or_command_head`。`reason_code` 固定英文：`excluded`、`readonly_source`、`entity_file`、`inbox`、`system_render`、`protected`、`unparsed`、`unresolved`、`guard_error`。只寫 deny、unparsed、unresolved、guard_error；allow 不寫。`path_or_command_head` 最多 120 字。

### guard-status（`.system/guard-status/<主機名>.json`）
```json
{"date": "2026-10-12", "python": "3.12.4", "host": "DESKTOP-XXXX", "plugin_version": "0.2.0"}
```

### hook-errors.log
一行：`2026-10-12T21:30:11	guard	<例外類名>: <訊息前 200 字>`。
