## 目的
總資料夾從「fixture 手抄」變成「plugin 自己建得出來、來源自己登記得進去」：`kb init` 建五區骨架，`kb folders add|exclude|list` 登記來源與排除。對應六個面的「資料去了哪」。順便補守門的資料層底線：憑證檔名樣式一律不讀（I-032），因為一登記來源就立刻可讀（D-073），來源夾裡的密碼表會跟著開放。

ingest、第一個 skill、桌面版確認都要一個 plugin 建出來的總資料夾，這題是地基。

## 決策
D-077 範圍；D-078 不建型別夾、標記維持 sources.json；D-079 憑證樣式住守門、settings.json 空殼；D-080 CLAUDE.md 只寫身分與五區；D-021（含 2026-10-14 補）spec 壓縮順序；D-042 五區與保留字；D-046 路徑表（settings.json 只有 kb folders 能寫，這題不寫）；D-073（含 2026-10-14 修訂）；D-074 腳本改狀態檔先備份；D-027 語言分層；D-014 schema_version；D-019 不寫 plugin 路徑；D-004 數字住 config。事故 I-021、I-030、I-032、I-033、I-046、I-050、I-054、I-066、I-101。

本題釐清、不改 D 的點：
- `kb.py` 從 CLI 跑、沒有 hook 開回合時，`turn.current` 用 `current.json`（事務層定的）：連續幾個 CLI 指令會落在同一個回合，同一檔只備第一次。所以確認情境裡要驗「退回」的那段在 Claude 對話裡一句一句下，不在純 CLI 裡驗。
- 守門對 `kb.py` 單一呼叫先回 allow 再看路徑（守門題 decide 的順序），所以 `kb folders exclude <密碼夾>` 不會被憑證規則擋到。
- 憑證規則寧可多擋：`AI 產出/密碼重設通知.docx` 這種會被擋，客戶多說一句改名就好（D-034 的取捨，誤擋率併 B-110）。
- `kb init` 不開回合、不備份：init 之前還沒有知識庫。`kb folders list`、`--check` 也不開回合。

`.gitkeep` 只為了讓 git 留住空夾，init 複製時跳過。`.system/` 不在骨架裡，由 init 程式建。CLAUDE.md 內容見「資料與介面格式」。不建型別夾、不建 `系統/` 的六個渲染 md、不建 `.skeleton-policy`（D-078、D-080）。

### 2. `config/defaults.json`
加 `"source_spec_max_up": 4` 與 `_why_source_spec_max_up`：相對總資料夾的 spec 最多往上幾層，超過改用 `~/` 或絕對（D-021 補）；數字照舊 llm-wiki。

### 3. `scripts/kb/_lib/paths.py`
- `compress_spec(target, vault, max_up) -> str`：照搬舊 llm-wiki `vaultpaths.portable_path`。`target`、`vault` 是**原始大小寫**的絕對路徑（存進 sources.json 的字串給人看，不用 `normalize` 的小寫結果；存在的部分用 `os.path.realpath` 展開 8.3 短名）。順序：同一顆磁碟且 `os.path.relpath` 的 `..` 段數 ≤ `max_up` → 相對（正斜線，`../來源/公司行政`）；在 `Path.home()` 底下 → `~/Documents/x`；否則絕對（正斜線 `D:/x`）。只搬這一個函式，其餘 vaultpaths 的東西 `_lib` 都已有。
- `is_abs_spec(spec) -> bool`：spec 是不是沒壓掉的絕對路徑（磁碟代號或 `//` 開頭）。給 add 印警告用。

### 4. `scripts/kb/_lib/sources.py`
- `load_raw(vault) -> dict`：讀 `.system/sources.json` 原始 dict（`Sources` 類是展開後的，寫回要用原始）。壞 JSON 丟例外。
- `save(vault, data)`：`FileLock` 加 `write_json_atomic`。
- `new_id(existing_ids) -> str`：`src-` 加 4 碼 hex（`secrets.token_hex(2)`），撞到重抽；跟 inventory 的 `out-` 同做法。
- `RESERVED_ALIASES = ("知識庫", "AI 產出", "收件匣")`：`檔案索引/<來源別名>/` 保留給知識庫自身、AI 產出、收件匣三個來源（D-042）。

### 5. 守門 `scripts/kb/guard.py`：憑證檔名樣式（D-079）
- `CREDENTIAL_PATTERNS`：寫死在程式，不讀 config、不讀客戶設定。初版：`.env`、`.env.*`、`*.pem`、`*.ppk`、`*.kdbx`、`id_rsa*`、`id_ed25519*`、`*password*`、`*passwd*`、`*secret*`、`*credential*`、`*密碼*`。**不含「憑證」**：會計憑證、報關憑證是客戶的正常文件。
- `is_credential(path) -> bool`：path 已 normalize（小寫、正斜線）；拆段，**任一段**對任一樣式 `fnmatch` 就算（`D:/資料/密碼/x.txt` 整夾都擋）。磁碟代號段不比。
- `decide` 的順序：kb.py 單一呼叫 allow 維持最先；接著檔案工具的目標路徑、指令字串抽出的每個路徑，**先查 `is_credential` 再查區**：命中回 `Decision("deny", <classify 的 zone>, "credential", 理由句)`。所有檔案工具（Read、Glob、Grep、Edit、Write、MultiEdit、NotebookEdit）與 Bash／PowerShell 都適用，讀寫都擋。理由句：`檔名像密碼或金鑰（<該段>），一律不讀也不寫，這條關不掉。`
- ledger 一行照舊（decision deny、reason_code credential），hooks/guard.py 不用改。`kb guard decide` 自然會印出來。
- 決策表 `ZONES` 不加欄：憑證是區之前的一道，寫在 `decide`，`classify` 不動。

### 6. `kb init`（`scripts/kb/init.py`，新）
- `add_arguments(sub)`：`path`（要建的總資料夾），`--check`，`--json`。
- 流程：
  1. `p = Path(path).resolve()`（原始大小寫）。`p` 存在但不是資料夾 → 印「<p> 是檔案，不能當總資料夾」exit 3。`p` 的任一**上層**有 `.system/sources.json` → 印「上層 <x> 已經是知識庫，不能在知識庫裡再建一個」exit 3（I-054）。`p` 自己有 → 走「補齊」。
  2. 計畫：骨架樹（跳過 `.gitkeep`，`.gitkeep` 的父夾算空夾）加 `.system/`、`.system/sources.json`，每項標「會建」或「已有」。
  3. `--check`：逐行印計畫（`會建 AI 產出/`、`已有 CLAUDE.md`），什麼都不寫，exit 0。
  4. 建：缺的夾 `mkdir`；缺的檔從骨架讀文字、`write_text_atomic` 寫（LF、UTF-8）；`.system/sources.json` 寫 `{"schema_version": 1, "sources": []}`。**既有檔一律不碰**（I-066）。
  5. 隱藏屬性：`CLAUDE.md`、`.claude/`、`.system/` 三項，Windows 用 `ctypes.windll.kernel32.SetFileAttributesW`（先 `GetFileAttributesW` 再 `| 0x2`），失敗印一句「隱藏屬性沒設成：<原因>」不算失敗；非 Windows 跳過。
  6. 印：新建「已建立知識庫 <p>：建了 N 項」；補齊「<p> 已是知識庫，補齊了 N 項」；N 為 0 印「<p> 已是知識庫，沒有缺的」。`--json`：`{"vault", "created": [rel...], "existing": [rel...]}`。
- 不開回合、不寫 ledger。

### 7. `kb folders`（`scripts/kb/folders.py`，新）
- `add_arguments(sub)`：子子命令 `add`、`exclude`、`list`，各有 `--json`；共同 `--vault <路徑>`（沒給用 `guard.find_vault(os.getcwd())`，找不到印「這裡不是知識庫；到知識庫裡執行，或加 --vault」exit 3）。
- **add** `<路徑> [--alias 名稱] [--check]`：
  1. `t = Path(路徑).resolve()`。拒絕（印原因 exit 3，第一個命中就停）：不存在或不是資料夾；整顆磁碟根（`os.path.splitdrive` 後剩空）；系統資料夾互相包含（`SystemRoot`、`ProgramFiles`、`ProgramFiles(x86)`、`ProgramData`、`~/AppData`，照搬舊 `kbcommon.system_dirs`）；跟總資料夾互相包含；跟既有來源互相包含（印「和既有來源「X」重疊，同一份檔會有兩張卡；要細分請在來源裡建子夾」）；`t` 或其上層有 `.system/sources.json`（印「<x> 是另一個知識庫，不能當來源」，I-050）。
  2. 別名：`--alias` 沒給用 `t.name`。拒絕：空、含 `/` 或 `\`、在 `RESERVED_ALIASES`、跟既有別名相同。
  3. 數檔：`os.walk(t, onerror=略過)`，不跟隨符號連結，逐項容錯（I-021）；數檔案份數；順便收集 `is_credential` 命中的相對路徑；走到任何目錄含 `.system/sources.json` → 拒絕「裡面有另一個知識庫 <x>」。不讀內容、不算指紋、不分格式。
  4. spec：`compress_spec(t, vault, config.get(vault, "source_spec_max_up"))`。
  5. 提醒（只印，照做）：份數 0；`is_abs_spec(spec)` →「這個位置存的是絕對路徑，換電腦會找不到」；`t.name` 在 `Desktop`、`Documents`、`Downloads`、`桌面`、`文件`、`下載` 且 `t.parent == Path.home()` →「這是整個「X」資料夾，範圍很大，可以只加裡面的某個資料夾」。
  6. `--check`：印下面同一段報告，不寫，exit 0。
  7. 寫：`turn_id = turn.current(vault)["turn"]`；`turn.backup(vault, ".system/sources.json", turn_id)`；`load_raw` 追加 `{"id", "alias", "spec", "excludes": []}`；`save`。不碰 settings.json。
  8. 印：
     ```
     已登記「公司行政」（../來源/公司行政，52 份）
     - 其中 1 份檔名像密碼或金鑰，不會讀：公司行政/網站密碼.txt
     - 提醒：…
     ```
     憑證清單最多列 10 條，多的印「…還有 N 份」。`--json`：`{"id","alias","spec","path","files","credential_files":[...],"warnings":[...],"check":bool}`。
- **exclude** `<路徑> --kind hidden|unused [--reason 文字]`：
  1. `t = Path(路徑).resolve()`，可以是夾或檔，不收萬用字元。拒絕 exit 3：不存在（I-033：對到 0 份不寫規則）；不在任何登記來源裡（找路徑最深的那個包含 `t` 的來源根；找不到就拒絕）；就是某個來源的根（印「整個來源的拿掉這版還沒有」）；已經在排除裡（等於或在某條排除底下）。`--kind` 沒給或不是兩值之一 → argparse 自己擋（exit 2）。
  2. spec：相對該來源根，正斜線，原始大小寫。
  3. 寫：同 add 的備份加 `save`，`excludes` 追加 `{"spec","kind","reason": 文字或 "","added": "YYYY-MM-DD"}`。
  4. 印：hidden「已排除「公司行政/薪資」（不想讓 AI 看到）。之前讀過的已送過雲端；這版還沒有卡和備份要清。」；unused「已排除「公司行政/舊檔」（用不到）。」。`--json`：`{"source_id","alias","spec","kind","reason","added"}`。
- **list**：每個來源一行 `「客戶案件」 ../來源/客戶案件 → C:/…/來源/客戶案件`，路徑展不開或不存在尾註「（這台電腦找不到）」；底下排除各一行 `  - 排除 薪資（hidden，薪資個資，2026-10-12）`。沒有來源印「還沒有登記任何來源」。`--json`：`{"sources":[{"id","alias","spec","path","exists","excludes":[{"spec","kind","reason","added","path","exists"}]}]}`。
- `cli.py` `COMMANDS` 加 `init`、`folders`。

## 資料與介面格式

### `skeleton/CLAUDE.md`
```markdown
# 知識庫

這個資料夾是 wiki-with-willy 維護的知識庫。客戶的原始檔案在外面，位置登記在系統裡，只讀。

第一層有五區：
- 型別夾：名字是客戶自己的分類（例如案子、客戶、廠商），一個實體一夾，夾裡跟夾同名的 .md 是綜合卡。
- AI 產出：AI 替客戶做的文件先放這裡。
- 收件匣：對話裡收到的、客戶自己丟進來的檔。
- 檔案索引：每份原檔一張檔案卡，位置由程式排。
- 系統：程式產生的報表與紀錄，客戶可以開。
```
實作可微調字句，但不加規則、不提 plugin 路徑、不超過 25 行與 1200 字。

### `skeleton/.claude/settings.json`
```json
{
  "permissions": {
    "deny": []
  }
}
```

### `.system/sources.json`（init 寫出的）
```json
{"schema_version": 1, "sources": []}
```
add 之後的條目格式照守門 spec：`{"id": "src-3f9a", "alias": "公司行政", "spec": "../來源/公司行政", "excludes": [{"spec": "薪資", "kind": "hidden", "reason": "薪資個資", "added": "2026-10-14"}]}`。

### `config/defaults.json` 新鍵
```json
"source_spec_max_up": 4,
"_why_source_spec_max_up": "相對總資料夾的來源 spec 最多往上幾層，超過改用 ~/ 或絕對路徑（D-021 補）；數字照舊 llm-wiki"
```

### 守門
- `Decision("deny", <zone>, "credential", "檔名像密碼或金鑰（網站密碼.txt），一律不讀也不寫，這條關不掉。")`
- ledger 一行：`<時間>\tRead\tdeny\tZ9\tcredential\t<路徑>`
- `kb guard decide --tool Read --path <R>/客戶案件/.env` 印 `deny 檔名像密碼或金鑰（.env），一律不讀也不寫，這條關不掉。`

### CLI 輸出
- `kb init D:\知識庫`：`已建立知識庫 D:\知識庫：建了 10 項`；再跑：`D:\知識庫 已是知識庫，沒有缺的`。
- `kb init --check`：每行 `會建 <rel>` 或 `已有 <rel>`。
- `kb folders add`、`exclude`、`list`：見第 7 節。
- 拒絕一律：第一行原因、exit 3。

### exit code
0 成功（`--check` 也是 0）；2 argparse 參數錯；3 拒絕（原因印在第一行）。
