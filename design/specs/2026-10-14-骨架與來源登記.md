## 目的
總資料夾從「fixture 手抄」變成「plugin 自己建得出來、來源自己登記得進去」：`kb init` 建五區骨架，`kb folders add|exclude|list` 登記來源與排除。對應六個面的「資料去了哪」。順便補守門的資料層底線：憑證檔名樣式一律不讀（I-032），因為一登記來源就立刻可讀（D-073），來源夾裡的密碼表會跟著開放。

ingest、第一個 skill、桌面版確認都要一個 plugin 建出來的總資料夾，這題是地基。

## 決策
D-077 範圍；D-078 不建型別夾、標記維持 sources.json；D-079（含 2026-10-15 補與修訂）憑證樣式住守門、settings.json 空殼；D-081 憑證預設擋、裁示放行、內部豁免、遮值（第四輪加）；D-080 CLAUDE.md 只寫身分與五區；D-021（含 2026-10-14 補）spec 壓縮順序；D-042 五區與保留字；D-046 路徑表（settings.json 只有 kb folders 能寫，這題不寫）；D-073（含 2026-10-14 修訂）；D-074 腳本改狀態檔先備份；D-027 語言分層；D-014 schema_version；D-019 不寫 plugin 路徑；D-004 數字住 config。事故 I-021、I-030、I-032、I-033、I-046、I-050、I-054、I-066、I-101。

本題釐清、不改 D 的點：
- `kb.py` 從 CLI 跑、沒有 hook 開回合時，`turn.current` 用 `current.json`（事務層定的）：連續幾個 CLI 指令會落在同一個回合，同一檔只備第一次。所以確認情境裡要驗「退回」的那段在 Claude 對話裡一句一句下，不在純 CLI 裡驗。
- 守門對 `kb.py` 單一呼叫先回 allow 再看路徑（守門題 decide 的順序），所以 `kb folders exclude <密碼夾>` 不會被憑證規則擋到。
- 憑證規則寧可多擋：`AI 產出/密碼重設通知.docx` 這種會被擋，客戶多說一句改名就好（D-034 的取捨，誤擋率併 B-110）。
- `kb init` 不開回合、不備份：init 之前還沒有知識庫。`kb folders list`、`--check` 也不開回合。

### 5. 守門 `scripts/kb/guard.py`：憑證檔名樣式（D-079）
樣式與比對搬到 `scripts/kb/_lib/credentials.py`（新，第一輪修正），guard 與 folders 共用；guard 的 `decide` 只做判斷順序。
- `CREDENTIAL_PATTERNS`：寫死在程式，不讀 config、不讀客戶設定。初版：`.env`、`.env.*`、`*.pem`、`*.ppk`、`*.kdbx`、`id_rsa*`、`id_ed25519*`、`*password*`、`*passwd*`、`*secret*`、`*credential*`、`*密碼*`。**不含「憑證」**：會計憑證、報關憑證是客戶的正常文件。比對不分大小寫（`fnmatchcase` 對小寫）。
- `match_segment(segments) -> str | None`：給一串路徑段，任一段命中就回那一段。
- `scan_dir(path, max_entries) -> (hit, truncated)`：容錯走訪（`os.walk` onerror 略過、不跟隨連結，I-021），每個夾名與檔名都比；命中回第一個命中的相對路徑；走訪項數超過 `max_entries` 就停、`truncated=True`。`folders add` 的 `_survey` 改用它收集憑證清單（add 用不設上限的版本或大上限）。
- 三道（D-079 補）：
  1. **目標路徑的段**（M1 修正）：路徑在登記來源裡（Z9、Z10、Z10b）只比來源根以下的段；在總資料夾裡（Z1～Z8）只比總資料夾以下的段；其他路徑（Z11）只比最後一段。上層夾叫 `secretary` 不影響底下。命中 → `Decision("deny", <zone>, "credential", 理由)`，理由句：`檔名像密碼或金鑰（<該段>），一律不讀也不寫，這條關不掉。`
  2. **指令字串的裸 token**（H1 修正；第一輪修正裁定 1 收窄）：Bash／PowerShell 的每個 token（去引號，取 `/` 與 `\` 的最後一段）**只有像檔名的才比**：最後一段含 `.`，或命中沒副檔名的樣式 `id_rsa*`、`id_ed25519*`；`-` 與 `$` 開頭的 token（旗標、變數）跳過。命中就 deny `credential`，不解析路徑、不看 cwd。`cat id_rsa`、`type .env`、`Get-Content 網站密碼.txt`、`cat passwords.txt` 都擋；`grep -i password notes.txt`、`echo $PASSWORD`、`curl --password=x`、`cat passwords`（沒副檔名）不因這道擋。 **第二輪 N3 再收**：token 含空白、或含正規式與萬用字元的字元（`* ? [ ] ^ $ ( ) |`）就不是檔名，跳過；`grep -rn "password.*=" 收件匣`、`echo "My password is safe."` 不因這道擋。萬用字元由第三道的前綴夾走訪處理。
  3. **讀取範圍是資料夾**（H1 修正；第二輪 N1、N2、N4 補）。要走訪的夾：Grep 的 `path`（沒給就是 cwd）；指令抽出的路徑是存在的資料夾；萬用字元的前綴夾（裸 `*` 接效用 cwd，即 cd 之後的 cwd）；`cd`／`pushd`／`Set-Location` 的目標；`.`、`..`；**沒斜線但在效用 cwd 底下存在的資料夾 token**（`grep -r "" 收件匣`）；**範圍搜尋類指令沒給任何路徑時的效用 cwd**（`grep -r x`、`rg x`、`findstr /s`、`Select-String`／`sls`、`Get-ChildItem -Recurse`／`gci -r`、`find`、`tree`、`ls -R`、`dir /s`；清單寫死在 guard，`ls`、`git status` 這類不算）。那個夾要「在登記來源或總資料夾裡」**或「底下含任何登記來源根或總資料夾」**（N2：含來源的上層夾也走訪，跟寫入的 `_above_roots` 同理；其他 Z11 不走訪）→ `scan_dir(夾, config.get(vault, "credential_scan_max_entries"))`：命中 → deny `credential_inside`，理由 `這個範圍裡有檔名像密碼或金鑰的檔（<相對路徑>），請縮到不含它的子資料夾或指定單一檔。`；`truncated` → deny `credential_scan_limit`，理由 `範圍太大，守門來不及檢查有沒有密碼檔，請縮小範圍。`。只對讀取；Glob 只列檔名不走訪；寫入資料夾不適用。 走訪**跳過排除夾**（hidden 與 unused 都跳，N4）：排除夾裡的檔名不准出現在理由句，那種範圍交給 Z10b 用它自己的理由句擋。`scan_dir` 多收一個要略過的夾清單（來源的排除根）。 **第三輪補**：走訪起點本身是排除夾或排除的單檔就不走訪（交 Z10，P3）；跳過清單含排除的單檔；走訪也跳過 `.system/` 與 `.claude/`（程式獨占，裡面沒有要讀的東西，O2）。裸萬用字元只認**引號外**的 token（P1）；「範圍搜尋沒給路徑」以**子指令**判（`&&`、`;`、`||` 切開各自看，P4），而且只在該子指令是管線第一段時算（第二段以後的 `grep` 讀 stdin，不走訪，P1）；`grep` 家族要帶 `-r`／`-R`／`--recursive`／`/s` 才算範圍搜尋，`rg`、`find`、`tree` 本來就遞迴。指令有寫入時仍走訪讀取範圍，只有寫入目標不走訪（S2）。萬用字元的展開命中照第一道比段（P2，fd50114 的行為），不存在又含萬用字元的路徑只在「有正規式字元且不是萬用字元」時才跳過。不帶斜線的 `.`、`..` 也要當路徑抽出來經區判斷（S1，守門題舊洞，這題順手補；`cmdparse.py` 這輪可以動）。已知不擋：cwd 裡沒副檔名又不是金鑰樣式的裸檔名（`cat passwords`），寫進 D-079 補的界線。
- 順序：kb.py 單一呼叫 allow 最先；接著三道憑證；再來才是區判斷。憑證三道都 deny、不會放行任何東西，所以放在區之前不影響既有決策表。
- **生效範圍（D-081，第四輪修正）**：三道只對登記來源（Z9、Z10、Z10b）、含來源或總資料夾的上層夾、知識庫外（Z11）生效。**總資料夾內部（Z1～Z8）一律不比、不走訪**；走訪上層夾時跳過總資料夾整棵（不只 `.system/`、`.claude/`；Q4：raw 裡的 `proj/.claude/.credentials.json` 要照比，所以「跳 `.system/`、`.claude/`」改成「跳總資料夾根」）。第二道（裸 token）與「走訪效用 cwd」只在效用 cwd **不在**總資料夾裡時做。
- **走訪 cwd 的規則收窄（第四輪 Q1～Q3、Q6）**：效用 cwd 在總資料夾裡 → 永遠不走訪 cwd，不猜「有沒有給路徑」。效用 cwd 在 raw 或含 raw 的夾 → 子指令**任一處**出現搜尋動詞（`grep` 家族帶遞迴旗標、`rg`、`find`、`tree`、`Select-String`／`sls`、`dir`／`ls`／`Get-ChildItem`／`gci` 帶 `-r`／`-R`／`-Recurse`／`/s`，不限第一個字，`time`、`LC_ALL=C`、`sudo`、`$x = ` 前綴都跳過）而且該管線段沒有**存在的**讀取路徑（樣式參數 `"2026/10"`、`TODO/FIXME` 不存在就不算路徑）→ 走訪效用 cwd。寧可多擋：cwd 在 raw 裡本來就少見。
- 其餘第四輪：引號裡的字不當萬用字元，`glob_tokens` 只收引號外（Q7）；萬用字元展開命中排除的檔或夾交 Z10 用它的理由句，不印檔名（Q5）；`.`、`..` 只在它是導向目標或寫入動詞那段才算寫入目標，`grep -r X . | tee /tmp/a`、`tar czf ../b.tgz .` 的 `.` 是讀取範圍（Q8）。
- **理由句改**（D-081，不再說「關不掉」）：`credential`：`檔名像密碼或金鑰（<該段>），客戶沒說這份可以讀，不讀也不寫。`；`credential_inside`：`這個範圍裡有檔名像密碼或金鑰的檔（<相對路徑>），客戶沒說可以讀；請縮到不含它的子資料夾或指定單一檔。`；`credential_scan_limit` 不變。守門讀 `rulings.json` 放行的那一步這版不做，留 TODO 註解指 D-081。
