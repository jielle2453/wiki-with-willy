## 目的
清冊現在只記 AI 產出（D-076），客戶原檔完全沒入冊；ingest 開頭必跑的 `kb changes` 沒有基準可比，開場的「變動」一行也沒數字可印。這題把 `.system/inventory.json` 長成 D-014 的狀態機（schema 2），加全量掃描 `kb inventory scan`、快速比對 `kb changes`、開場狀態行「變動：新增 N、修改 N、不見 N」；登記與清冊同一筆交易（`kb folders` 四個子命令連清冊一起改）。對應六個面的「資料去了哪」「要我決定什麼」的數字來源；是 ingest 製卡的地基。

## 決策
D-092 範圍；D-093 schema 2；D-094 掃描與比對規則；D-095 登記與清冊同一筆交易。既有：D-014（含 2026-10-12 補：Office 文字指紋等 `kb convert`，本題位元組）、D-021（含補：找不到的來源報一次、按機器記 env.json）、D-027 語言分層、D-042 保留別名、D-043 實體夾裡非綜合卡的檔是原檔、D-046 路徑表（`.system/` 只有 kb 腳本能寫）、D-048 origin 三值、D-060 開場行、D-074 腳本改狀態檔先備進回合、D-076 最小版、D-079／D-081 憑證樣式清單共用、D-085 程式段、D-087 狀態行預算（8 行 400 字）。事故 I-015、I-017、I-018、I-020、I-021、I-022、I-041、I-045、I-046、I-047、I-049、I-081、I-097、I-098。

本題釐清、不改 D 的點：
- 綜合卡 `<型別>/<名稱>/<名稱>.md` 不進清冊（它是 AI 筆記，不是檔案）；型別夾裡其他任何檔（含直接放在 `<型別>/` 第一層的）都是客戶原檔入冊。
- 實體夾改名、刪除的認出（D-057 三問）不在本題：本題只看檔，夾改名就是檔搬動（同指紋換位置），綜合卡不掃所以不會被報不見。
- `kb changes` 不開回合、不寫任何檔。`kb inventory scan` 寫清冊前先備進目前回合（D-074），終端機跑記程式段（D-085）。
- 來源 spec 展不開（`${VAR}`、`~/` 對不到）跟來源根不是資料夾一樣，都算「這台電腦找不到」。
- 開場 hook 唯一寫的是 `env.json` 的「已報過」記號（D-094 補），其他只讀。
- 位置比對用正規化（casefold、正斜線）的 uri 當鍵，存的是原始大小寫。
- `versions revert` 還原 `inventory.json` 用既有機制（manifest 有就還原），不改 versions.py。已知邊角：同一回合裡先 `folders add`（備份清冊）再由 AI 寫成品（登記），退回會讓那份成品的條目消失、檔留著；lint 的「登記表對實際檔」接（I-047），本題不處理。
- `系統/總目錄.md` 等渲染、待處理條目（不見的檔要不要問客戶）都是 ingest 題。

### 3. `scripts/kb/_lib/inventory.py`（改，schema 2）
**schema**：`{"schema_version": 2, "entries": [...]}`，一筆：
- `id`：`f-` 加 `secrets.token_hex(4)`，撞到重抽；既有 `out-` 條目不改（D-093）。
- `origin`：`client_file`｜`intake`｜`ai_output`。掃描依位置判：外部來源與型別夾 → client_file；收件匣 → intake；AI 產出夾裡沒登記過的 → ai_output。
- `locations`：清單，每個 `{"uri", "size", "mtime"}`。`uri` 是 `file://<來源別名>/<相對來源根的路徑>`，正斜線、原始大小寫；總資料夾自身：`file://知識庫/<型別>/<名稱>/x.docx`（相對總資料夾根）、`file://收件匣/<相對收件匣>`、`file://AI 產出/<相對 AI 產出>`。`mtime` 是 `YYYY-MM-DDTHH:MM:SS`（取整秒）。同指紋多位置一筆；位置順序照發現順序，第一個是主位置。
- `fingerprints`：照 D-076，`[{"sha256", "time", "turn"}]`，最後一筆是現行指紋；掃描時 `turn` 填目前回合代號。
- `read`：`ok`｜`placeholder`｜`credential`｜`too_large`｜`error`；後四種不算指紋，`error` 另帶 `"error": "<原因一句>"`。read 是最近一次掃描看到的。
- `status`：`active`｜`missing`｜`excluded`｜`turn_reverted`｜`deleted`｜`superseded`。
- `first_seen`、`created_turn`（既有）、`missing_since`（`status` 不是 missing 時是 `null`）。

**遷移 1 → 2**（`load` 時在記憶體做，`save` 寫 2；I-049 舊條目全部補齊）：`locations` 字串包成物件，檔在就從磁碟補 `size`、`mtime`，不在就 `null`；`created` 改名 `first_seen`；補 `read: "ok"`、`missing_since: null`。`schema_version` 大於 2 丟 `ValueError`（I-046：壞檔明講，hook 寫 log）。`EMPTY` 改 2。

**既有函式**：`register_output` 寫新格式（位置物件帶大小時間）、id 改 `f-`；`outputs_of_turn`、`set_status`、`sha256_of` 不變（`sha256_of` 改經 `long_path`）。

**新函式**（全部純函式或只在呼叫端給的鎖裡寫）：
- `roots(vault, sources) -> list[Root]`：要掃的根：`sources.entries` 每個來源（alias、root、excludes）、加總資料夾三區：知識庫（根是總資料夾，只走第一層非保留、非隱藏的夾，跳 `<名稱>/<名稱>.md`）、收件匣、AI 產出。`sources.unresolved` 與來源根不是資料夾的收進 `missing_sources`（alias、spec、id）。
- `walk(root, skip_roots) -> Iterator[(rel, stat, error)]`：`os.scandir` 迭代、不遞迴呼叫、經 `long_path`。跳過：名字 `.` 開頭、屬性隱藏或系統（`st_file_attributes & 0x6`）的夾與檔；重解析點（`is_symlink()` 或屬性 `0x400`）不跟不列（I-021）；`skip_roots`（排除夾、排除單檔、總資料夾在來源底下時整棵）；暫存名 `SKIP_NAMES = ("~$*", "*.tmp", "Thumbs.db", "desktop.ini", ".DS_Store")`（`fnmatch` 不分大小寫）。開不了的夾 `yield (rel, None, "無法開啟資料夾：<strerror>")` 繼續走；stat 失敗同樣 yield error。
- `read_kind(rel_segments, st, size_cap) -> (read, error)`：占位檔屬性 `0x40000`｜`0x400000`｜`0x1000` → placeholder（I-020，常數照舊 plugin）；`credentials.match_segment(來源根以下的段)` 命中 → credential；`st_size > size_cap` → too_large；其餘 ok。
- `scan(vault, sources, *, quick=False, only_roots=None, now=None) -> Report`：D-094 的比對，**不寫檔**。`only_roots` 給 folders 限定某個來源。演算法：
  1. 載入清冊，建索引 `key(uri) → (entry, location)`；`only_roots` 時只對那些根底下的位置比，其他條目原樣帶過。
  2. 走訪每個根，每個檔算 uri、read。位置已知：大小時間都同 → 不動；不同且 read 是 ok → 算指紋（快速模式受讀取預算），指紋同最後一筆 → 假變動，只更新位置大小時間；不同 → `modified`，追加指紋、更新位置。read 不是 ok → 只更新位置大小時間、更新 read，不算指紋。
  3. 位置未知：全掃一律算指紋（受 size_cap）；快速模式只在「大小等於某個這次不見的位置或 `missing` 條目的大小」時算，其他直接當 `added`。有指紋：等於某條目現行指紋 → 那條目這次有位置不見（或 status missing）就是 `moved`（換位置、missing 條目轉回 active、`missing_since` 清空），否則 `duplicate`（追加位置）；對不到 → 新條目 `added`。沒指紋（read 不是 ok、或預算用完）→ 新條目。
  4. 走完：根存在但位置沒看到的 → 從條目拿掉那個位置；條目沒有任何位置剩下 → `status=missing`、`missing_since=now`（原本就 missing 的不重報、不改日期），記 `missing`。根找不到的來源，底下的條目與位置原樣不動（D-094）。
  5. `excluded` 條目在這次掃描的根底下被找到同指紋的檔 → 轉 active、位置補回（給 `folders include` 用）。
  6. 快速模式：讀取總量超過 `changes_quick_hash_budget_bytes` 後不再算指紋，已知位置變了的算 modified、未知的算 added；走訪經過時間超過 `changes_quick_seconds` → 停止走訪，`report.incomplete = True`，已比到的照報。

  `Report` 欄位：`added`、`modified`、`missing`（uri 清單）、`moved`（`[old_uri, new_uri]`）、`duplicates`（`[uri, id]`）、`unchanged`（數）、`total`（活著的位置數）、`by_source`（`{alias: {"files", "bytes"}}`）、`read_counts`（`{placeholder, credential, too_large, error}`）、`read_examples`（每種最多 3 個 uri）、`errors`（`[{"path", "error"}]`）、`missing_sources`（`[{alias, spec, id}]`）、`incomplete`、`entries`（套用後的整份 entries，給 `apply`）。
- `apply(vault, report, turn_id)`：持 `inventory.json` 的 `FileLock`，`turn.backup(vault, ".system/inventory.json", turn_id)`，寫 `{"schema_version": 2, "entries": report.entries}`。備份失敗丟 OSError 不寫（D-074）。
- `reconcile(vault, sources, turn_id) -> {"excluded": n}`：給 `folders exclude`／`remove`：每個條目的每個位置，查 `sources.lookup`：來源不在了或落進排除 → 拿掉那個位置；位置全沒了 → `status=excluded`。在同一把鎖裡備份、寫。
- `path_of(vault, sources, uri) -> Path | None`：uri 反查絕對路徑（別名對不到回 None）。

### 8. `scripts/kb/folders.py`（改，D-095）
四個子命令在既有 `sources.json` 的鎖裡寫完 sources 之後、同一把鎖還沒放之前，接著改清冊（清冊自己的鎖在裡面）；兩份都 `turn.backup` 進同一回合。
