# ingest 製卡
日期：2026-10-17
狀態：implemented（2026-10-18，commit 8c26ef4、e87c248）
版本：（發行後填）

## 目的
清冊知道哪些檔在、哪些變了，但沒有任何一張卡；六個面裡「答與出處」還是空的。這題讓檔案變成檔案卡：`kb convert` 抽出純文字、製卡者照 `carding.md` 寫一張卡到 `檔案索引/`、程式算哪些檔還沒有卡或該重做、開場有變動時 AI 自己整理、原檔不見與讀不到的檔落進待處理讓客戶看得到、根目錄的 `總目錄.md` 渲染成可摺清單讓客戶（含 Obsidian）從這裡點到卡、卡裡一條連結開原檔（D-105 的「我的檔案」頁）。對應使用者時刻：林小姐把「報價_v3.pdf」丟進信義王的夾，隔天開對話，不用開口，回答末尾多一句「我把報價_v3 整理進去了」；她刪掉的檔，AI 問一句再把卡拿掉。

## 決策
D-098 範圍；D-099 `kb convert` 標準函式庫為主、PDF 與圖片交給 Read；D-100 製卡者這版只有主對話、開場少量自動多量先問；D-101 檔頭中文鍵名；D-102 待處理最小版；D-103 刪檔的卡拿掉；D-104 程式算待製卡清單、PostToolUse 驗檔頭。既有：D-014（主鍵 id）、D-022（安靜模式：原檔內容不印到終端機）、D-027（語言分層：檔頭中文、`--json` 與 `.system` 英文）、D-029（卡檔名是標題加短 id，原檔改名卡不動）、D-032（抄多少由製卡判斷，數值回正本讀）、D-036（檔案卡位置鏡射原檔路徑、程式排）、D-037（範本一份固定、建議段落沒內容不寫）、D-042／D-043（保留別名、型別夾裡非綜合卡的檔是原檔）、D-046（路徑表：`檔案索引/` 回合備份、指令寫擋）、D-048（出處類別三種）、D-053（規則寫給「製卡者」）、D-060／D-087（開場注入預算 8 行 400 字）、D-062（待處理欄位）、D-070（skill 描述 150 字、本文 120 行、reference 150 行）、D-074（腳本改狀態檔先備進回合）、D-085（終端機跑記程式段）、D-091（路由 eval 20 句）、D-093／D-094／D-096（清冊 schema 2、比對規則、內容指紋）、D-105（`總目錄.md` 在總資料夾根、巢狀可摺清單、檔案卡一條 `file:///` 開原檔；本題接這兩件，`.obsidian/` 骨架與 CSS 片段是 Obsidian 題）、D-064 補（卡裡的開原檔行是絕對路徑的例外）。事故 I-003、I-004、I-010、I-012、I-014、I-015、I-017、I-020、I-022、I-028、I-029、I-040、I-047。

本題釐清、不改 D 的點：
- 檔案卡只掛「檔」，不掛實體：檔頭沒有實體欄位，實體題加欄位時走範本版本 2 與 lint 補欄（B-106）。
- 卡型沒有客戶設定檔可讀：`carding.md` 放一組預設建議段落（這是什麼、重點、日期與數字、提到的人與單位、沒讀到的部分），卡型欄由製卡者填一個簡短名詞（報價、合約、會議紀錄、型錄、進度表、範本、說明、其他），客戶設定檔題再搬成資料。
- 「出處」欄照清冊 `origin` 翻譯：`client_file` 客戶原檔、`intake` 對話收件、`ai_output` AI 產出。AI 產出的卡第一段寫明「AI 於 YYYY-MM-DD 起草」（日期取清冊 `created_turn`），answer 題再定引用時怎麼說。`derived_from`／「改自」這版不做（清冊還沒有該欄）。
- 同一份內容多位置（清冊一筆多 `locations`）只做一張卡，放主位置（`locations[0]`）的鏡射夾，檔頭「原檔」列全部位置。主位置換了（原本的第一個位置不見）由 `kb cards sync` 搬卡。
- 大檔不切子卡（D-098 不做）：`kb convert` 印「大檔」提示，製卡者照 D-032 摘要加定位，卡不超過 `carding.md` 的長度上限。
- `kb convert` 寫的暫存檔在 `.system/temp/`（守門 Z7：Read 放行、寫只有 kb 腳本）；製卡者讀完不用刪，`kb convert` 每次先清掉超過 `temp_keep_hours` 的暫存檔，再長的體積由 lint 題管（D-018）。
- 清冊 `read` 是 `credential`、`placeholder`、`too_large` 的條目不進待製卡清單，`kb cards todo` 只印份數；占位檔那句話照舊 plugin（「在檔案上按右鍵選保留在這台電腦上」）寫進 `carding.md`。
- 製卡者用 Write 寫卡，守門 Z5 放行並回合備份（既有）；修改既有卡用 Write 整張重寫（不用 Edit 補），PostToolUse 對 Write 與 Edit 都驗。
- `kb cards drop` 刪卡走 `turn.backup(action="delete")`，`kb versions revert` 用既有機制還原；不改 `versions.py`。
- 開場的指示行只有「變動」行印出來時才印，整段仍守 8 行 400 字（`test_budget`）。
- `skills/manage/SKILL.md` 只改「加資料夾」那列的收尾句：「從現在起讀得到；要我現在整理成卡嗎？」客戶說要就照 ingest skill 做（architecture 三的交棒）。`tests/evals/manage.json` 不動。
- 兩個對話同開同一知識庫時 `kb cards drop`、`kb pending` 的回合歸屬照 B-019，本題不處理。
- 待處理的原檔不見條目以**清冊狀態**為準、不以 scan 的 report 欄位為準：`inventory.apply` 寫完清冊後，對每個 `status == "missing"` 且沒有 open 的 `missing_file` 條目的檔開一條；對每個有 open `missing_file` 條目但檔已回 `active` 的自動 done「找回來了」。這樣 `pending` 那段失敗（只記 `hook-errors.log`，不往上丟、不影響 `folders add` 的交易）下次 scan 會補上，也不用管 scan 把恢復記在 `moved` 還是 `restored`。
- 渲染檔 `系統/待處理.md` 跟 `.system/pending.json` 一起 `turn.backup`（退回後客戶打開看得到的要一致；工作日誌 md 不備是因為它整月重渲染）。`kb cards drop` 改清冊前自己先 `turn.backup(".system/inventory.json")`（`set_status` 不備份）。
- 檔頭解析得了但其他檢查不過的卡（出處錯、檔名錯、標題仍「（填）」、夾對了但 `原檔` 清單跟清冊位置不同以外的錯）併進 `todo` 的 `broken`（帶 `path`、`reason`），人讀第一行多印「檔頭有問題 N 張」；修不修由製卡者照原因重寫，lint 題再接。
- `總目錄.md` 放總資料夾根（D-105），守門是 Z8（AI 寫擋），只有程式寫：PostToolUse 驗過一張卡、`kb cards sync|drop|index` 之後重渲染；渲染只讀 `檔案索引/` 的卡檔頭，不讀清冊，所以孤兒卡也會列（排除後清殘留是 manage 第二版）。
- 檔頭 `開原檔` 一行由程式算（主位置的絕對路徑，`urllib.request.pathname2url` 加 `file:` 前綴，中文與空白照它編碼），製卡者照抄，PostToolUse 驗跟程式算的一模一樣；來源搬家、搬動由 `kb cards sync`（本題）與 `kb folders relocate`（manage 第二版）重寫。B-050 spike 驗出 Obsidian 要別的形式時只改這一個函式再 `sync` 整批重寫。
- 測試用的 OOXML、cp950、CFB、`/Encrypt` 檔由測試自己組（zipfile、位元組）寫進 tmp 的 `<V>`／`raw` 複本，`tests/fixtures/inventory` 不動（那裡的 `.docx` 是假 zip、`Big5備忘.txt` 其實是 UTF-8）；驗收準則裡提到的檔名都讀作「tmp 複本裡同名、由測試寫入的真檔」。

### 實作疑義裁定（2026-10-18，設計 session 對實作 session 7 條的回答）
1. **xlsx 每列帶列號**：`xlsx_text` 每行開頭 `第 N 列：`（N 是工作表裡的真實列號，跳過空列不影響），例如 `第 12 列：a | b | c`；製卡者的〔位置〕照抄這個 N。`content_fp` 的內容指紋不受影響。
2. **「找不到原檔」不寫待處理**：`kb convert` 對不存在的檔只印 `讀不到：找不到原檔` exit 3，不開 `unreadable` 條目、不印第二行；原檔不見由 `sync_missing` 的 `missing_file` 管。對 status 是 `missing` 的條目同樣回這句。
3. **總目錄連結的編碼**：連結目標只把空白、`(`、`)`、`[`、`]`、`#`、`%` 百分比編碼，中文照原樣（raw md 還看得懂）；連結文字裡的 `[`、`]` 用反斜線跳脫。驗收 20 的「含空白的檔名編成 `%20`」加一條「檔名含 `（修）` 之類的全形括號不編碼、半形括號編碼」。
4. **`總目錄.md` 備進回合**：`render_index(vault, turn_id=None)`，有 `turn_id` 就先 `turn.backup` 再寫；PostToolUse 用目前回合（`turn.current(vault, session_id)`），`sync`／`drop`／`index` 用各自的回合。退回後跟卡一致。
5. **開原檔用磁碟大小寫**：`open_link` 對存在的路徑先 `os.path.realpath` 取磁碟上的大小寫（junction 換成實際路徑也照樣開得到）再 `pathname2url`，產出 `file:///C:/Users/…`；路徑不存在（missing）時用 `path_of` 給的原樣。`validate` 比對時也用同一個函式算，所以兩邊一致。
6. **`todo` 的不製卡份數印第二行**：`skipped` 任一不為 0 時第二行 `不製卡：檔名像密碼或金鑰 N、只在雲端 N、太大 N`（0 的項不印）；第一行格式不變，全 0 且沒有別的桶時仍只印 `卡都是最新的`。
7. **`validate` 不查 `原檔` 清單內容**：照 spec，只查它是非空清單；清單寫錯由 `todo` 的 `moved` 列出、`sync` 修。
8. **`kb convert` 自己守門，不繞過排除與憑證**（實作抓到的洞：守門對單一 `kb.py` 呼叫一律放行，convert 開檔是程式自己開）：抽字之前對解析出的磁碟路徑做跟守門同一套判斷，用既有函式不另寫：`guard.classify` 回 Z10／Z10b 或清冊條目 `status == "excluded"` → exit 3 `讀不到：這個位置你說過不讀`；路徑在來源根以下的段命中 `credentials.match_segment`（總資料夾內部豁免，D-081）→ `讀不到：檔名像密碼或金鑰，預設不讀`；`classify` 回 Z11（不在登記來源、也不在總資料夾三區）→ `讀不到：不在登記的資料夾裡`；Z1、Z6、Z7、Z8（綜合卡、系統、狀態檔、第一層）→ `讀不到：這不是要製卡的檔`。四種都不寫待處理。只動 `convert.py`，`guard.py` 不動。驗收 4 補：對排除夾裡的檔、不在清冊且檔名像密碼的路徑、總資料夾外任一路徑、`.system/inventory.json` 各跑一次都 exit 3 且 `.system/temp/` 沒有新檔。

### 測試後修正裁定（2026-10-18，對測試第一輪 `design/reports/ingest製卡-測試.md` 的回答；實作只修這些）
15. **S1 高：`kb convert` 不收 `--vault`**。總資料夾一律從 cwd 往上找（`guard.find_vault(os.getcwd())`），找不到印 `NOT_IN_VAULT` exit 3；測試用 subprocess 的 `cwd` 指到 `<V>`。原則記進 I-111 補：**會把原檔內容帶給 AI 的子命令不准由參數指定總資料夾**，守門放行 kb.py 的前提是它只信 cwd 所在的那個知識庫。`cards`、`pending` 仍收 `--vault`（它們不讀原檔內容，最多動假總資料夾自己的檔）。
16. **S2 高：暫存檔名只用驗過的編號**。`_temp_name` 對任何來源（參數、uri 反查、路徙反查）的 id 都要 `_ID.fullmatch`，不合就改用指紋前 12 碼；寫前 `os.path.realpath` 確認目的地的父夾等於 `.system/temp` 的 realpath，不等就 exit 3「暫存位置不對」。
17. **S3 高：`clean_temp` 在 gate 之後跑、temp 是重解析點就不清**：`.system/temp` 的屬性有 `REPARSE_POINT`（`inventory.REPARSE_POINT`）或 `os.path.islink` 為真就跳過清理並記 `hook-errors.log` 一行；清理只刪一般檔不進子夾；拒絕（exit 3）的呼叫不清。
18. **C1 高：開檔、讀檔、寫暫存的 `OSError`（含 `PermissionError`）→ exit 3 `讀不到：檔案被別的程式開著或沒有權限，關掉 Word／Excel 再試`**，不寫待處理（暫時狀態），`--json` 的 `unreadable` 帶這句。`run` 的例外處理補齊：`Refused`、`ValueError`、`OSError`、`MemoryError`（→ `讀不到：檔案太大`）、`zipfile.BadZipFile`／`ET.ParseError`（→ `讀不到：檔案壞了`）；其他例外仍 traceback（那是 bug）。`--json` 時所有失敗都印 JSON 不印句子（C10 第一項）。
19. **C2 中：開原檔對不上也算 `moved`**。`todo` 分桶改成：`validate` 只有「開原檔那行」不過（其他全過）→ 進 `moved`（`to` 同夾），`sync` 重算 `開原檔` 寫回；`broken` 只收開原檔以外的錯。這才對得上 spec「來源搬家與 B-050 改形式由 sync 整批重寫」。
20. **C3 中、B-051 一併收：同編號多張卡由 `sync` 收斂**。`scan_cards` 同編號多張時：`validate` 全過且路徑對的那張是正本；`sync` 把其餘的備進回合（`action="delete"`）後刪掉；沒有一張全過時留修改時間最新的一張、其餘刪，剩的那張照原分桶（stale／moved／broken）。`todo --json` 多一桶 `duplicates`（`[{id, keep, drop:[…]}]`），人讀第一行多印「同編號多張 N 組（跑 kb cards sync）」。`sync` 目的地已有同名檔時：同編號就照上面收斂，不同編號才跳過。B-051 改 done。
21. **S4 中：檔頭值的型別先驗**：`編號`、`指紋`、`內容指紋`、`出處`、`標題`、`卡型`、`文件日期`、`讀取`、`開原檔` 必須是字串，`原檔`、`敏感資料種類` 必須是清單，不對回「檔頭「X」的格式不對」；`problems()` 整段包住，任何例外都回 block 帶「檔頭解析不了」，不靜默放行。
22. **S5 低：`parse_front` 不遞迴**：清單只認一層 `[a, b]`，巢狀 `[` 直接 `ValueError`。
23. **S6 低：總目錄連結文字**：反斜線、`[`、`]` 跳脫，`<`、`>` 換成全形；夾名同樣處理。
24. **S7 低：抽字有上限**：gate 擋 `read == "too_large"`（`讀不到：檔案太大`）；`plain_text` 與 OOXML 的 sharedStrings、單一成員解壓超過 `fingerprint_max_bytes` 就 `Unreadable("檔案太大")`。
25. **C4 中低：xlsx 截斷就是大檔**：抽到上限停下時 `big` 為 true、印 `大檔：…`，暫存檔尾那行保留；`carding.md` 說大檔時讀取標「部分」並寫沒讀到的工作表。
26. **C5 中低：`render_index` 用 `FileLock(總目錄.md)` 包住讀寫**。
27. **C6 低中：docx 的 `w:txbxContent` 只抽一次（跳過 `mc:Fallback` 那份）、`w:br` 換成換行。**
28. **C7 低中：`todo` 的 `kind` 只看副檔名**，不開檔；`/Encrypt` 與 CFB 魔數只在 `convert` 查。
