狀態：approved（2026-10-19）

## 目的
知識庫到 v0.9.0 有檔案卡，但型別夾還是守門「任何非保留字的第一層夾」這種隱含定義，沒有地方記「這個客戶管哪幾類東西、每類是對象／事／物／主題」；製卡者的卡型與段落、不抄的個資種類都寫死在 `carding.md`，客戶改不了。這題生 `profile.json` 與 `系統/客戶設定檔.md`（D-052 一份三用：空白版是訪談表、填好的程式讀進 JSON、之後程式渲染回同格式），`kb profile check|apply` 把人改的 md 套進 JSON、建型別夾；製卡者從設定檔拿卡型、段落與個資種類；設定檔說「不整理」的種類用清冊記號跳過。對應使用者時刻：服務人員建置前跟林小姐談完，把「案子、客戶、廠商」填進設定檔跑一次 `apply`，知識庫第一層就多三個夾；林小姐哪天自己在設定檔加一列「工班」、或在檔案總管建了「工班」夾，下次開對話開場提一句，她說「套用」就好。B 題（實體與綜合卡）接著在型別夾底下長實體夾。

## 決策
D-108（A、B 兩題切法）；D-109（第一版只收三節：型別、卡型與段落、不整理與敏感）；D-110（兩條入口：人改 md 開場問套用、終端機 `check|apply`；對話裡說「加型別」這版不代改）；D-111（三節都是表格、同一支解析器、預設值由 `kb init` 寫進 JSON、`carding.md` 只讀設定檔、製卡者由 `cards todo --json` 的 `profile` 拿）；D-112（型別表對第一層夾四條對帳、守門不動）；D-113（「不整理」用清冊記號 `kb cards skip`）。既有：D-015／D-067（JSON 為真、渲染檔三行頭、格式住程式、範例住 fixtures）、D-027（鍵名英文、客戶看到的中文）、D-037（卡型是建議段落組：段落名加提示、必出現沒內容寫「未知」）、D-039（四大類）、D-041（每條帶日期與來源四選一）、D-042（型別名不撞四個保留字）、D-052（md 頂端那行「可以改，下次開對話我會問你要不要套用」；同一支解析器）、D-058（刪有東西的型別不准）、D-074（寫狀態檔先備進回合）、D-085（終端機跑記程式段）、D-087／D-060（開場 8 行 400 字）、D-078（`kb init` 不建型別夾；認既有第一層夾）、D-093（清冊 schema 2）。事故 I-046（狀態檔壞了開場仍印其他行）、I-063／I-066（既有檔不覆蓋）、I-097（解析器命中 0 筆要報錯）、I-098（測輸出不測旗標）。

本題釐清、不改 D 的點：
- **md 不住 skeleton，由程式渲染**：D-110 寫「`kb init` 從 skeleton 複製空白版」，實作上 `kb init` 寫 `profile.json`（預設值，D-111）後用同一支渲染函式寫出 md；提示句住渲染程式（D-067），`tests/fixtures/profile/客戶設定檔.md` 是 `kb init` 剛建完的期望輸出。skeleton 不放這個檔。
- **來源與日期兩欄永遠在**：渲染版就有這兩欄，人加列時留空，`apply` 填；D-111 的「空白版沒有這兩欄」因此不存在，解析時兩欄選填的規則不變。
- **「md 較新」用內容指紋不用 mtime**：`profile.json` 記上次渲染出的 md 的 `md_sha256`；現在 md 的 sha256 不等於它就是「有改」。同步夾、`cp -p` 都不會誤判（I-093 同類）。
- **「第一次套用」的判準**：`profile.json` 的 `applied` 是 null（`kb init` 寫的預設 JSON 還沒被人套用過）就是第一次，新列來源標 `interview`；之後標 `confirmed`。人在來源欄自己寫了四選一之一就照他的，寫別的字報錯。
- **D-113 的「`read` 多一個值」實作成 `skip_kind` 欄**：清冊條目多一個選填欄 `skip_kind`（字串或沒有），`read` 的值域不動（掃描每次重算 `read`，加值會被蓋掉）。`cards todo` 把 `skip_kind` 非空的條目算進 `skipped.skipped`，不列。
- **`validate` 不查 `卡型` 在不在表裡**：客戶從表裡拿掉一個卡型時，既有的卡不該一夕變 broken；卡型對不對表是 lint 題。製卡者照 `profile.card_types` 選是規則。
- **守門不動**：Z1／Z2／Z8 照舊只看路徑形狀，不讀型別表（D-112）。
- **刪列擋的是「夾裡有東西」**：型別夾底下有任何檔或子夾都算；空夾才能從表拿掉，夾本身留著不刪（既有不碰）。
- **改名這版走「少一列加一列」**（D-112）：人把「案子」改成「專案」，`check` 列「少了 案子、多了 專案」；`案子/` 空的就過（JSON 少一多一、建 `專案/`、`案子/` 留著），有東西就擋。
- **`apply` 對型別夾只建不刪、不改屬性**；建夾不備進回合（回合備份只管檔），`versions revert` 退掉 `apply` 時 JSON 與 md 回去、夾留著，印給人看的那句要講「建的夾還在」。
- **開場那行只讀不寫**：`check` 的邏輯跑一次，印一行；不寫 `profile.json`、不寫 md。
- **`kb cards skip` 的 kind 必須是第三節 `no_card` 的種類**，不在表裡 exit 3；條目要是 active 且 `read == "ok"`；已有卡就把卡備進回合後刪掉（像 `drop`），再標 `skip_kind`，重渲染 `總目錄.md`。
- **`apply` 放回待製卡**：第三節拿掉某種類（或它從 `no_card` 改成 `kind_only`）時，`skip_kind` 等於它的條目把 `skip_kind` 拿掉（清冊先備進回合）；印一句「N 份回到待製卡」。
- **既有知識庫補檔**：`kb init <既有路徑>` 的「缺的才建」會補 `profile.json` 與 md（init 的計畫多兩項）；`tests/fixtures/inventory/vault` 與 `tests/fixtures/vault` 這兩個 fixture 加 `profile.json`（預設內容）與渲染出的 md，讓既有測試的假總資料夾也是完整的。
- **開場 budget**：狀態行最多同時有 kb、變動、有變動、找不到來源、設定檔、摺疊六行；`test_budget` 要量「六行都在」的情況仍 ≤ 8 行 400 字。

### 實作疑義裁定（2026-10-19，設計 session 對實作 session 4 條的回答）

4. **merge 的「人填」判準**：來源或日期欄的值等於舊 JSON 同鍵那筆就當沒填（同鍵變了 → `confirmed`、today；沒變 → 保留）；跟舊值不同才算人填（要是四選一之一）。卡型的來源日期取該卡型第一列。另追認：`check --json` 的 `card_types` diff 元素是 `["報價", "日期與數字"]`；md sha 不同但沒有內容差異時 `apply` 重渲染、更新 `md_sha256` 與 `applied`，印 `已套用客戶設定檔：沒有內容上的差異，重寫了設定檔`。

## 要做的事

1. **`scripts/kb/_lib/profile.py`（新）**：設定檔的 JSON、解析、驗證、比對、渲染。
   - 常數：`PROFILE_POSIX = ".system/profile.json"`、`MD_POSIX = "系統/客戶設定檔.md"`、`SCHEMA_VERSION = 1`；`CATEGORIES = {"對象": "party", "事": "matter", "物": "asset", "主題": "topic"}`；`SOURCES = {"訪談": "interview", "推測": "inferred", "確認": "confirmed", "糾正": "corrected"}`；`ACTIONS = {"不整理": "no_card", "只記種類": "kind_only"}`；`RESERVED_TYPE_NAMES`：`AI 產出`、`收件匣`、`檔案索引`、`系統`、`CLAUDE.md`（比對不分大小寫、全半形 NFKC 後比）；點開頭一律拒。
   - `defaults(today)`：預設 JSON（格式見下）：`types` 空；`card_types` 八種（報價、合約、會議紀錄、型錄、進度表、範本、說明、其他），每種四段（重點、日期與數字、提到的人與單位、沒讀到的部分；`required` 全 false；提示照 `carding.md` 現在第三節的字句）；`exclusions`：身分證字號、護照號碼、銀行帳號、信用卡號、密碼、個人薪資金額 六種 `kind_only`，統一編號、電話、地址 三種 `kind_only`（這九種就是 carding.md 第五節現在的清單，全部搬過來）；`no_card` 預設沒有。全部 `source: "inferred"`、`date: today`。`applied: null`、`md_sha256: null`。
   - `load(vault)`：沒檔回 None（呼叫端決定要不要當錯）；形狀不對（不是物件、三個清單缺一、`schema_version` 比這版新）丟 `ValueError`。
   - `parse_md(text)`：回 `{"types": [...], "card_types": [...], "exclusions": [...]}`（跟 JSON 同形，`source`／`date` 沒填就是 None）或丟 `ProfileError(section, row, message)`。規則：三節以 `## 一、`、`## 二、`、`## 三、` 開頭的標題認（標題後面的字不比）；缺一節 → 「少了第 N 節」；每節只認第一張表（以 `|` 開頭的連續行），表頭列與分隔列（只含 `|-: `）跳過，其餘每列用 `|` 切、去頭尾空白，欄數不是 3／4／2 加選填的 2 → 「第 N 節第 M 列欄數不對（要 3 欄或 5 欄）」；大類不在 `CATEGORIES` → 「第 1 節第 M 列的大類要是 對象、事、物、主題 之一」；必出現欄 `✓`、`是`、`v`、`V`、`Y` 算 true，空算 false，其他字 → 錯；處理欄不在 `ACTIONS` → 錯；來源欄非空且不在 `SOURCES` → 錯；日期欄非空且不是 `YYYY-MM-DD` → 錯；型別名空、重複、命中保留字、含 `\ / : * ? " < > |` 或控制字元、以 `.` 開頭、以 `.` 或空白結尾 → 錯（各自一句）；卡型名空或同卡型同段落重複 → 錯；種類空或重複 → 錯。整份沒有任何表格列也算解析成功（三節都空），**但三節都少就是錯**（I-097：命中 0 節不回空）。
   - `diff(old, new)`：以鍵比（型別＝名稱；卡型＝卡型名＋段落名；排除＝種類），回 `{"types": {"added": [...], "removed": [...], "changed": [...]}, "card_types": {...}, "exclusions": {...}}`，`changed` 是同鍵但其他欄不同（來源與日期不算）。
   - `merge(old, new, today, first)`：新列補 `source`（人填的優先；沒填：`first` 就 `interview` 否則 `confirmed`）與 `date`（人填的優先，否則 today）；同鍵沒變的保留舊 `source`／`date`；同鍵變了的照新列規則；回合併後的 JSON（`types`／`card_types`／`exclusions`，順序照 md）。
   - `folder_check(vault, types)`：回 `{"to_create": [名稱], "unlisted": [第一層非保留字、不以點開頭、不是檔的夾名], "removed_empty": [...], "removed_nonempty": [(名稱, 項數)]}`；`removed_*` 以 JSON 現有型別對 md 型別算。
   - `md_sha256(vault)`：md 不存在回 None。
   - `render(vault, data)`：寫 `系統/客戶設定檔.md`（格式見下），回寫出的文字；呼叫端負責備份與更新 `md_sha256`。
   - `write(vault, data, turn_id)`：在 `FileLock(profile.json)` 裡 `turn.backup` 兩個檔（JSON、md）後原子寫 JSON、渲染 md、把 md 的 sha256 寫回 JSON 再寫一次（兩次寫都在同一把鎖裡；或先算渲染文字再寫，擇一，結果要是 JSON 的 `md_sha256` 等於磁碟上 md 的 sha256）。
   - `status(vault)`（開場與 `check` 共用，只讀）：回 `{"state": "ok"|"changed"|"error"|"missing", "diff": ..., "error": "第 N 節…", "unlisted": [...]}`；`missing` 是 JSON 或 md 不存在（開場不印、`check` 印「還沒有客戶設定檔，跑 kb init 補」）。

{"schema_version": 1,
