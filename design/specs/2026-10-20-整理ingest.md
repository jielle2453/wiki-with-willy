## 目的
ingest 的 SKILL 本文頂到 5000 字上限，大半是「看 todo 的哪個欄位、叫哪個指令、客戶答了什麼對哪個指令」的文字對照，加上一次次修事故留下的叮嚀。文字對照要靠模型記得，每加一個程式功能就多一段，日程題正要再加四種問題。這題照 D-132 把程式介面搬回程式：`kb cards todo --json` 多給 `plan`（照順序要做的事）、`asks`（排好序、編好號的問題與結果清單）、`tell`（回答末尾要講的現成句子）；ingest 本文只留分辨、原則與骨架，跟 carding.md 不再重複。程式行為不變：卡、實體、綜合卡、待處理怎麼寫都跟 v0.11.0 一樣。對應使用者時刻：林小姐開對話說「整理一下」，AI 回答末尾列「1. 跟著改名叫王宅 2. 改回信義王 3. 改成別的名字」，她回「1」或「就叫王宅」都行；原檔不見那題她只回「好」，AI 再問一次，不會直接刪。

## 決策
D-132（SKILL 內容住哪裡）、D-134（結果清單與編號、客戶回編號或說意思都行、strict）、D-135（一次最多 3 個問題、客戶這句需要的先問、整理問題照程式的順序）。既有：D-070（字數上限）、D-091（路由測試；這題描述不動、不重跑）、D-100（開場少量自動、多量先問）、D-104（程式算清單）、D-114～D-124（實體與綜合卡）、實體與綜合卡裁定 4、20。事故：B-051、B-058、I-082、I-083、I-089。

本題釐清、不改 D 的點：
- **行為不變**：所有既有桶（`new`、`stale`、`moved`、`duplicates`、`missing`、`unreadable`、`broken`、`orphans`、`skipped`、`unlinked`、`missing_types`、`synthesis_*`、`entity_drift`、`profile`、`entities`）的格式與內容照舊，只多三個鍵；人讀輸出照舊。既有測試一個都不改期望值。
- **`do` 裡的指令寫法**：一律以 `kb ` 開頭（例 `kb entity rename 信義王 --to 王宅`），AI 換成本文寫的完整前綴執行；參數值有空白或特殊字元時程式自己加引號；要客戶給的值寫成 `{新名字}`、`{客戶的話}` 兩種空格之一，`fill` 列出這一項有哪些空格。
- **編號接著編**：`asks` 全部的結果從 1 起一路編下去（不只前 3 題），AI 不管挑哪幾題，號碼都不撞（D-134）。AI 自己的問題不用編號（D-135）。
- **`strict` 標在結果上**：同一題裡「不要了」是 strict、「照檔案卡重寫一張」不是。
- **多量先問也是一題**：要整理的份數（`new`＋`stale`＋`unlinked`）超過 `ingest_auto_max` 時，`asks` 第一題是「有 N 份要整理，現在做嗎？大約 M 分鐘」，結果「現在做」「之後再說」；`plan` 只留 `sync` 一步。D-100 的告知與進度照舊。
- **客戶已經答過的不會再列**：原檔不見的答過「先留著」「不用管」照舊不列（裁定 31），實體與綜合卡的照舊靠清單本身消失。
- **補丁分類照下表**（D-132 第 4 條）。「留」的改寫成通則並帶一句理由加編號；「刪」的內容由程式輸出或 carding.md 承接；「交程式」的已在 backlog。

## 要做的事

1. **`scripts/kb/_lib/plan.py`（新）**：吃 `cards.todo` 的結果（與 `pending`、`entities` 已在裡面的資料），回三樣；只讀（`config` 取 `ingest_auto_max`），不寫任何檔。

   - **`plan`**：照這個順序、只列有項目的步驟，每步 `{"step", "items", "do", "read"}`：
     1. `sync`（`moved` 或 `duplicates` 有項目）：`do` 是 `kb cards sync`，`read` 是 null。
     2. `cards`（`new`＋`stale`＋有 `header` 的 `broken`）：`do` 是「照清單寫卡（new、stale、broken）」，`read` 是 `references/carding.md 一～六節`。
     3. `unlinked`：`read` 是 `references/carding.md 第七節`。
     4. `synthesis_broken`：`read` 是 `references/carding.md 第八節`（綜合卡放錯位置的處理，含 `kb entity clean`）。
     5. `synthesis_stale`、6. `synthesis_new`（只算 `confirmed` 的）：`read` 是 `${CLAUDE_PLUGIN_ROOT}/rules/synthesis.md`。
     多量先問時（見釐清）只留第 1 步。
   - **`asks`**：照 D-135 的順序：多量先問 → `entity_drift` 的 `missing` → `entity_drift` 其他 → 原檔不見（`missing`）→ `synthesis_new` 沒確認的。每題 `{"id", "kind", "question", "results": [{"n", "label", "do": [...], "strict", "fill": [...]}]}`；`id` 穩定（`drift:<e-…>`、`missing:<p-…>`、`name:<e-…>`、`batch`）。結果清單：
     - **drift `folder_renamed`／`both_renamed`**：「跟著改名叫 X」→ `kb entity rename <名> --to <X>`；「改回 <名>」→ `--to <名>`；「改成別的名字」→ `--to {新名字}`。
     - **drift `card_renamed`**：「用新檔名 Y」→ `--to <Y>`；「改回 <名>」；「改成別的名字」。
     - **drift `moved_type`**：「跟著改到 T」→ `--to <名> --type <T>`；「搬回 <原型別>」→ `--to <名>`。T 不在型別表時第一個結果改成「先把 T 加進設定檔」，`do` 空，標 `note`。
     - **drift `missing`**：「不要了」→ `kb entity remove <名>`（strict）；「刪錯了，我從資源回收筒還原」→ `do` 空；「刪錯了，照檔案卡重寫一張」→ `kb entity rebuild <名>`。
     - **原檔不見**：「刪了，卡也拿掉」→ `kb cards drop <f-…>`（strict）；「沒刪，先留著」→ `kb pending resolve <p-…> --how "{客戶的話}"`；「不用管」→ `kb pending dismiss <p-…>`。
     - **名字確認**（`synthesis_new` 沒確認）：「名字對」→ `kb entity confirm <名>`；「跟已有的 X 是同一個」→ `kb entity merge <名> --into {同一個}`（`fill` 是 `同一個`）；「名字改成別的」→ `kb entity rename <名> --to {新名字}`、`kb entity confirm {新名字}` 兩條。
     - **多量先問**：「現在做」→ `do` 空（AI 照 `plan` 做）；「之後再說」→ `do` 空，標 `note: "這個對話不再問"`。

   - **`tell`**：回答末尾要講的句子，照這個順序、0 的不列：讀不到（每份一句「<檔名> 讀不到：<原因>」，超過 5 份合成「另有 N 份讀不到」，最後加「記在 系統/待處理.md」）；不製卡的份數（照現在人讀第二行的字，只在雲端的多一句「請在檔案上按右鍵選保留在這台電腦上，我再整理」）；依設定不整理（「<種類>類 N 份依你的設定不整理」）；`missing_types`（「有 N 份看起來跟 <型別> 有關，但設定檔裡沒有『<型別>』這一類，要加的話在客戶設定檔第一節加一列，下次開對話我會問你要不要套用」）；PDF 元件裝好（`pdf_restored`）。
