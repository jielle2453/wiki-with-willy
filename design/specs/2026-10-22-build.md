## 目的
現在一個新客戶要用，得靠人一步一步打 `kb init`、`kb folders add`、手改設定檔再 `profile apply`、開對話整理；沒有環境檢查、沒有訪談、沒有抽樣給客戶看、沒有交付報告。這題做「服務人員到客戶那邊建置的那一天」：一個指令 `build`，程式記做到哪、照順序走：檢查這台電腦、訪談（有填好的設定檔就讀）、登記資料夾、盤點、抽樣給客戶看並改「我猜的」、全量整理（card-maker 那題的 `cards dispatch`）、確認名字、寫綜合卡、交付報告。另收兩件：本來就有舊 llm-wiki vault 的人接得進來（D-193）、新名字有把握的 AI 直接登記（D-202，平常整理也照這條）。客戶也可以自己建置（D-009）；沒有資料夾的客戶走短路（D-044）。

### 使用者時刻的起點狀態
| 起點 | 長什麼樣 | 程式怎麼指 |
|---|---|---|
| 全新 | 服務人員在桌面版開一個空資料夾的對話，打 build | `build status` 沒有建置紀錄、資料夾空 → 從「環境」開始，`build start` 建骨架 |
| 位置不是空的、也不是知識庫 | 選錯夾，或客戶自己選了有東西的夾 | `build status` 回 `not_empty: true`，AI 提一句（D-190 再補），服務人員決定換不換 |

| 已經是知識庫 | 有 `.system/` 但沒有建置紀錄，或建置做完了 | 擋下（D-190 補），那句一字不差 |

### 本題釐清、不改 D 的點
- **指令的形狀**：照 `plugin-dev:command-development` 與 `plugin-dev:skill-development` 判斷：要 references 就做成 `skills/build/`，frontmatter `disable-model-invocation: true`，叫法一樣 `/wiki-with-willy:build`；架構第九節的 `commands/build.md` 照實作改。本文只做：先跑 `kb build status --json`，照它的 `step`、`do`、`read` 做；每步做完跑它給的 `kb build done <步>`；帶一句（「重新抽樣」）就 `kb build redo <步>`。
- **建置在哪個資料夾**：在桌面版開對話時選的那個資料夾（cwd）建，hook 才管得到；`build start` 等於在 cwd 跑 `kb init` 再寫建置紀錄。
- **步驟與順序**（`.system/build.json` 的 `step`）：`env` → `setup` → `inventory` → `sample` → `cards` → `names` → `synthesis` → `adopt`（有舊 vault 才有）→ `finish` → `done`。沒有登記任何資料夾時 `setup` 之後直接 `finish`（D-044）。`done <步>` 由程式驗前提才放行，不過就回原因：`setup` 要設定檔讀得懂、`inventory` 要 `setup` 做完、`cards` 要 todo 沒有可派的也沒有在跑的批次、`names` 要沒有待確認的名字、`synthesis` 要沒有待建或在跑的綜合卡批次。
- **環境（D-189、D-133 補）**：`kb build env --json` 只讀、不碰 `build.json`，在任何資料夾都能跑（建好的知識庫也行，不受「已經是知識庫就擋」限制；第 (6) 題換電腦的開場檢查會呼叫它，D-208），逐項回 `ok｜warn｜fail` 與白話一句：Python 版本（3.10 以上）、kb 跑得起來（就是自己）、這個資料夾按過信任（讀 `~/.claude.json` 該路徑的信任欄，讀不到回 warn「看不出來」）、智慧型應用程式控制（`winreg` 讀 `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy` 的 `VerifiedAndReputablePolicyState`：0 關、1 開、2 評估中）、PDF 元件（在子行程實際 import pypdfium2 轉一頁測試 PDF，被擋就 fail 並說「PDF 會讀不到」）、Office 或 LibreOffice（`kb office check` 同一套）、磁碟剩餘（少於 1 GB warn）、舊 llm-wiki（讀 `~/.claude/plugins/installed_plugins.json` 與 `~/.claude/settings.json` 的 `enabledPlugins`，`llm-wiki@` 開著就 fail「要先在外掛頁把舊的 llm-wiki 停用」）。缺選配：AI 講缺什麼與後果，服務人員說好才跑既有的 `kb office setup`。
- **PDF 元件裝的位置要對齊（D-189 補的注意）**：`kb office setup` 裝在工具夾（`%LOCALAPPDATA%\wiki-with-willy\tools\`）；`_lib/extract.py` 讀 PDF 時，本行程 import 不到就改在子行程跑（`PYTHONPATH` 帶工具夾，跟 `office.render` 同一招；本行程不動 `sys.path`，CLAUDE.md 三）。`convert` 的「還沒裝 PDF 元件」那句只在兩處都沒有時印。跟密碼與守門的交界（a2 10-22，它在 `extract.py` 加了 `--password`／`--saved` 開加密 PDF 與「只有 owner 密碼不算加密」）：子行程也要守住三件：(1) 密碼經 stdin 傳給子行程，不放命令列參數或環境變數（命令列在工作管理員看得到，也會進 ledger、hook-errors.log）；(2) 子行程出錯時訊息與 traceback 不帶密碼，子行程的 stderr 先過 `credentials.mask_secrets` 再記；(3) owner 密碼的判法照密碼與守門那版，子行程回同樣的分類。
- **訪談（D-191、D-052）**：問資料夾在哪（逐個 `folders add`）、哪些不讀與理由（`folders exclude`）、關於你、只記種類不記值的（設定檔第三節，`profile add`）、幾個人用（`kb build set people "<她的話>"`）、以前有沒有用過別的 wiki 或筆記（有舊 llm-wiki vault 記 `kb build set adopt "<路徑>"`）。有事先填好的設定檔：`kb profile apply --from <路徑>`（程式把那份 md 複製成 `系統/客戶設定檔.md` 再照 apply 那條路，讀不懂照舊回節與列）。型別表與第四節不在這步問。
- **盤點**：`kb build facts --json` 只讀：每個來源的份數、格式分布、第一、二層夾名與份數、讀不到的份數與原因（加密、舊格式、只在雲端…）、估時（照 D-199 的算法）。AI 講給服務人員與她聽，說要做才 `done inventory`。
- **抽樣（D-192）**：AI 從 `facts` 挑 10 份左右、跨不同的夾與格式，`kb cards dispatch --ids f-…`（card-maker 題的 dispatch 多收 `--ids`），做完讀那幾張卡與 `facts`，列「我猜的」：型別表、事類狀態詞、卡型、哪些是同一個；她改的經 `kb profile add|type rename|merge`、`kb entity merge|rename` 寫；再問每類最想知道什麼（第四節）。
- **全量整理**：`cards dispatch` 照常派，同一個指令接著做。
- **名字（D-202）**：`cards todo` 的 `synthesis_new` 沒確認的：AI 讀它掛的卡判斷，有把握的 `kb entity accept <名>`（來源記 `ai_judged`），有疑慮的列進 asks。建置這步把有疑慮的一次全列；平常整理照 D-135 一次最多 3 題。
- **實體來源多一種（D-202）**：`entities.json` 的 `source` 多 `ai_judged`；`cards todo` 把 `ai_judged` 當確認（可建綜合卡、不出名字題）；`entity list` 人讀標「AI 判斷」；`entity confirm` 照舊改成 `confirmed`。`plan.py` 在名字題之前多一步 `names`（`do`：「到門檻的新名字：有把握的 kb entity accept，有疑慮的留給 asks」，`read` 指 carding.md 的新節）。
- **收舊 vault（D-193 與兩段補）**：`kb build adopt <路徑> --check` 只讀：認出 `raw/` 與 `raw/.manifest.json` 掛載的外部夾（可登記的清單）、`wiki/` 頁數、`hot.md`、`log.md` 大小、CLAUDE.md 規則段、`wiki/agenda.md`；登記照常 `folders add`。`adopt` 那步（綜合卡之後）：`kb build adopt <路徑> --extract` 把要讀的文字切成段寫進 `.system/temp/adopt/`（每段不超過 `adopt_chunk_chars`，D-022 照 convert 的暫存規矩、不印內容），回段落清單；交給 card-maker 的第四種工作 `adopt`（`cards dispatch --adopt`），每個子代理讀幾段、回報候選：口述（實體、日期、一句）、規則、有日期的事、還在等確認的，回報格式固定。AI 合併後列給她，說好的才經 `kb statement add`、`kb profile add 偏好`、`kb ruling add`、`kb agenda add` 寫；等確認的當場問。舊 vault 不寫、不搬（D-193 再補）。
- **交付報告（D-066、D-047）**：`kb build report --facts --json` 給數字與清單（份數、卡數、綜合卡數、讀不到的分類與檔名、AI 判斷登記的名字、合併了哪些、被擋掉的功能、幾個人用、花了多久）。AI 照 `templates/build-report.md` 六段寫成白話，用 Write 存到工作區 `.system/temp/office/<回合>/建置報告.md`（produce 已放行的位置），再 `kb build report --from <那份>`：程式驗六個標題、遮值（`credentials.mask_secrets`）、接上數字段，寫 `系統/建置報告.md`（備進回合），`done finish`。對話裡講三句重點，問「要不要現在試問一個問題」。沒內容的段不寫。
- **安全（D-194）**：`build.json` 寫入在鎖裡；同時兩個 build（另一個 session 正在某步）→ 第二個回「另一個建置正在跑」；每步 AI 先講要做什麼、說好才做；寫入照舊進回合備份。不做快照、不做 `--check` 預演。
- **建置紀錄怎麼記日誌**：每步 `done` 寫一段程式段（D-085）或併進對話回合，跟其他 kb 指令同一套。

## 資料與介面格式

### `.system/build.json`（schema 1）
```json
{"schema_version": 1, "step": "cards", "started": "2026-10-22T09:30:00",
 "done": {"env": "2026-10-22T09:35:10", "setup": "…", "inventory": "…", "sample": "…"},
 "people": "我跟助理兩個人", "adopt": "C:/Users/…/Desktop/小陳的wiki", "no_sources": false,
 "env": {"checked": "…", "items": [{"key": "pdf", "level": "fail", "text": "PDF 元件被擋，PDF 會讀不到"}]},
 "session_id": "…", "lock_until": "2026-10-22T09:40:00"}
```

### `kb build status --json`
```json
{"step": "sample", "not_empty": false,
 "do": ["kb build facts --json", "kb cards dispatch --ids <挑的編號> --json"],
 "read": "references/steps.md 抽樣", "after": "kb build done sample"}
```
已經是知識庫：exit 3「這裡已經是建好的知識庫，要加資料夾、整理檔案直接跟我說」。另一個建置在跑：exit 3「另一個建置正在跑（<哪一步>），等它做完或關掉那個對話再打一次」。

### `kb build env --json`
`{"items":[{"key":"python","level":"ok","text":"Python 3.12"},{"key":"trust","level":"warn","text":"看不出這個資料夾有沒有按過信任"},{"key":"sac","level":"warn","text":"智慧型應用程式控制開著；目前沒擋到我們的程式"},{"key":"pdf","level":"fail","text":"還沒裝 PDF 元件，PDF 會讀不到","fix":"kb office setup"},{"key":"office","level":"ok","text":"有 Microsoft 365"},{"key":"disk","level":"ok","text":"剩 120 GB"},{"key":"old_wiki","level":"fail","text":"舊的 llm-wiki 開著，要先在外掛頁停用"}]}`

### `kb build done <步> [--json]`、`redo <步>`、`set people|adopt "<值>"`
成功：`建置：<步名> 做完了，下一步 <步名>`；前提不過：exit 3 一句原因（例「還有 40 份沒整理完，整理完再往下」）。

### `kb entity accept <名> [--json]`
成功：`已登記：<名>（AI 判斷）`；沒登記：exit 3「實體清單沒有：<名>」；已確認：`已經確認過了：<名>`（exit 0）。

### `kb build adopt <路徑> --check|--extract [--json]`
`--check`：`{"raw":"…/raw","linked":[{"path":"D:/案子","exists":true}],"wiki_pages":38,"hot_chars":4200,"log_chars":210000,"rules":5,"agenda":7}`；不是舊 llm-wiki vault（沒有 `wiki/` 也沒有 `raw/.manifest.json`）：exit 3「這不像舊的 llm-wiki 資料夾」。`--extract`：`{"chunks":["<知識庫>/.system/temp/adopt/001.txt", …]}`，終端機不印內容。

### `kb build report --facts --json`、`--from <路徑>`
`--from` 成功：`建置報告寫好了：系統/建置報告.md`；六個標題缺或多：exit 3 一句是哪一段。
