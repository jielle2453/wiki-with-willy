### 本題釐清、不改 D 的點
- **歸 manage**：升級的話跟前一份的備份、還原一樣歸 manage（「環境」），寫進前一份新增的 `references/ops.md` 與本文「整個知識庫」那節；描述（≤150 字）加「升級、有新版嗎」。
- **版本號怎麼分**（D-217）：semver。小修 = 前兩位相同、第三位較大；大升級 = 前兩位較大；退回 = 清單版本比現在舊。`0.x` 時第二位當大版本。
- **背景查新版**（D-072、D-216、D-218）：
  1. 開場（`hooks/session.py`）讀這台電腦 `env.json` 的 `update_check`；日期不是今天就在背景開一個子行程跑 `kb upgrade --background`（不等它、不拖慢開場；Windows 用 `DETACHED_PROCESS|CREATE_NO_WINDOW`），開場只用上一次查的結果。
  2. `--background`：抓清單（`config` 的 `update_manifest_url`）與名單（`update_rollout_url`），逾時 `update_fetch_seconds`（5）秒；結果寫 `env.json` 的 `update_check`（日期、清單版本、種類、在不在名單、那版一句話、錯誤）。連不上只記錯誤、不印、不出錯（D-219）。
  3. 有她可以拿的**小修**：同一個子行程接著換版（見「換版」）；換好記 `auto_patched`。下一個對話開場認出換了版，走 `--finish`。
  4. 名單：`for` 是 `"all"`，或含這個知識庫的 `vault_id`（`ensure_vault_id`，密碼與守門那支）才算她可以拿；`"none"` 或不在名單就當沒有新版。
- **換版**（D-215，`kb upgrade` 與背景小修共用）：
  1. 找內建 Claude Code：`%LOCALAPPDATA%\Claude-Data\claude_*\claude-code\<版本>\<…>\claude.exe`，版本夾多個取版本號最大的；找不到用 PATH 上的 `claude`；都沒有回固定句（「這台找不到 Claude 的更新程式，請服務人員幫忙」）。用 `pathlib` 的萬用字元，不要遞迴掃整個 `Claude-Data`（spike：會很慢）。
  2. 市集名與範圍：從 `CLAUDE_PLUGIN_ROOT`（`…/cache/<市集>/<plugin>/<版本>`）取市集名；範圍從 `~\.claude\plugins\installed_plugins.json` 裡 `installPath` 等於目前 plugin 根的那筆取（客戶是 user；確認時是 local）。不寫死。
  3. 跑 `"<exe>" plugin update wiki-with-willy@<市集> --scope <範圍>`（一個指令就會重抓清單；**`plugin` 前面不加任何旗標**，spike：`--debug` 會開出一個對話）；逾時 `update_run_seconds`（60）秒。
  4. 驗：重讀 `installed_plugins.json` 那筆的 `version`；沒換到（GitHub 快取還給舊清單）就回「新版剛出來，幾分鐘後再說一次」，`pending` 清掉、快照留著。
- **`kb upgrade`（大升級、退回）**：
  1. 先 `--check` 同一套查一次（不用背景結果），沒有她可以拿的就回「目前是最新版」或不在名單那句。
  2. 大升級：照前一份拍快照（`backup.snapshot(vault, "upgrade")`）→ 寫 `upgrade-history.json` 的 `pending`（目標版本、快照檔名、開始時間）→ 換版 → 成功句「好了，開一個新對話就是新版（X）」。快照或換版失敗：`pending` 清掉、回那句、什麼都沒換。
  3. 退回（清單比現在舊，D-217；一律先還原升級前的快照再降版，所以舊程式讀到的是升級前的檔，不會看到新版才有的值，例如 D-202 的 `ai_judged`；能退回的舊版都在這份發行之後，已經認得 card-maker、build 的狀態檔）：先講清楚會怎樣再做：`--check` 回升級前那份快照（`upgrade-history.json` 最近一筆升到現在這版時記的快照）與 `restore check` 的結果，AI 照 D-205 講會不見什麼，她說好才 `kb upgrade --downgrade`：照前一份 `restore apply` 還原那份快照 → 換版（降版，spike 證實會降）→ 請她開新對話。升級前的快照已經被清掉：回固定句、不降版（新版格式給舊程式讀可能出錯，這種情況請服務人員處理）。
  4. 鎖：跟前一份同一把（`.system/revert.lock`）；背景整理在跑時擋（同前一份那句）。
- **`kb upgrade --finish`**（新對話開場叫）：
  1. 比 plugin 版本與 `upgrade-history.json` 的 `current`：一樣就回「已經是 X」不做事。
  2. 大升級、沒有對到 `pending` 的快照（她自己在畫面上更新的）：先拍快照。小修不拍。
  3. 補骨架（`kb init` 同一支，只補缺的）；骨架對帳（見下）。
  4. 狀態檔遷移寫回：各狀態檔用自己的 `load`（已有的遷移）讀，存的 `schema_version` 比現在舊就照它自己的寫法寫回（寫前備進回合）；`_lib/migrate.py` 收一張表：哪個檔、用哪支 `load` 與寫入。之後新增遷移的題，在這張表加一列。
  5. 卡的檔頭（D-054）：範本版本比現在舊、而且這版有檔頭遷移（表裡登記）的卡，只改檔頭機器欄位，寫前備進回合；這版沒有就跳過。
  6. 記 `upgrade-history.json`：`current` 換成新版、`history` 加一筆（從、到、日期、種類、快照、自動或她說的）、`pending` 清掉。
  7. 回：從、到、種類、那版的一句話（從新版自己的 `CHANGELOG.md` 讀，不靠網路）、遷移了哪些、骨架換了哪些、要問她的骨架檔。AI 講一句「已升到 X：一句話」（小修是「已自動套用小修正 X：一句話」），有要問的就問，然後回答她的問題。
  8. 有 `--finish` 要做時，開場的整理指示不印（跟前一份的 `kb moved` 同一套），免得轉格式前就開始整理。
- **骨架對帳**（例句 9）：`.system/skeleton.json` 記骨架每個檔（`skeleton/` 底下 `kb init` 會複製的檔）上一次寫進去時的 sha256；`kb init` 建殼與 `--finish` 換新時更新。換版時每個骨架檔：知識庫裡的跟記的一樣（她沒改過）→ 直接換新版；不一樣 → 列進 `skeleton_ask`，AI 問她，`kb upgrade skeleton <相對路徑> --keep|--replace`（換之前把她那份備進回合）。沒有 `skeleton.json` 的舊知識庫：跟 `config/skeleton_history.json`（發行程式每版追加：版本 → 每個骨架檔的 sha256）裡任何一版對得上就當她沒改過。新版沒改的骨架檔不問。
- **開場那行**（`line_version`，排在 kb 那行之後、變動那行之前）：(a) 要 `--finish` → 「已換到 X：先跑 kb upgrade --finish 再做別的。」；(b) 上次查到她可以拿的大升級 → 「有新版 X：一句話；說『升級』我帶你做。」；(c) 清單被指回舊版 → 「這一版 X 撤回了；用起來有問題的話說『退回舊版』。」；其他不印。整行守在開場預算裡（一句話截 `update_note_max` 字）。
- **給客戶的一句話**（例句 7）：`CHANGELOG.md` 每一版多一行 `- **給客戶的一句話**：…`（白話、一句、不寫編號）；發行程式抄進名單檔，開場用名單裡的、`--finish` 用新版自己 CHANGELOG 裡的。沒寫就不准發行。
- **發行程式**（`tools/release.py`，不進 zip，D-213 清單外）：
  - `build <tag>`：從 tag 用 `git archive` 取檔，照 D-213 清單（含 `agents/`，D-213 補）打 zip 到 `dist/`（`.gitignore` 加）；檢查：zip 裡只有清單上的、`plugin.json` 與 `hooks/hooks.json` 引用到的路徑都在、版本號等於 tag、CHANGELOG 最新一段有給客戶的一句話；小修規則（D-217）：跟上一個 tag 比，`config/skeleton_history.json` 以外的骨架檔、各狀態檔的 schema 版本常數、`_lib/migrate.py` 的表，有任何不同就拒絕標成小修；印 sha256；`config/skeleton_history.json` 追加這版（在打 tag 之前的發行 commit 裡做：`build --prepare` 先算好寫進去）。
  - `publish <tag> --public <公開 repo 的本機 clone> --for <vault_id>… | --all | --none`：zip 用 `gh release create` 傳到公開 repo；更新 `marketplace.json`（版本、網址、sha256）、推；每 30 秒從外面抓清單，直到抓到新版（最多 `--wait` 分鐘，預設 15，超過停下來說）才改名單檔、推（D-218）。
  - `rollout <版本> --for … | --all | --none --public <clone>`：只改名單、推。
  - 公開 repo 的名字與網址第一次發行時定，填進 `config/defaults.json` 的 `update_manifest_url`、`update_rollout_url`；在那之前是空字串，背景查新版看到空就不查。README（D-214）第一次發行時寫，之後只改版本相關的句子。
- **B-060**：`test_budget` 的開場長度改用客戶電腦上最長的合理路徑算 kb 那行（`C:/Users/<20 字的名字>/.claude/plugins/cache/<市集>/wiki-with-willy/<版本>/scripts/kb.py`），並把 `line_version` 三種句子的最長情況算進去。

## 資料與介面格式

### 公開 repo 的名單檔 `rollout.json`（schema 1）
```json
{"schema_version": 1, "versions": {
  "0.21.0": {"for": ["kb-1a2b3c4d"], "note": "日程可以匯出成 Excel"},
  "0.20.1": {"for": "all", "note": "修好日程匯出的日期錯誤"}}}
```
`for`：`"all"`、`"none"`、或 `vault_id` 清單。客戶端只看清單上那個版本那一筆。

### `.system/upgrade-history.json`（schema 1）
```json
{"schema_version": 1, "current": "0.20.1",
 "pending": {"to": "0.21.0", "snapshot": "快照 2026-10-23 1405（升級前）.zip", "started": "2026-10-23T14:05:00"},
 "history": [{"from": "0.20.0", "to": "0.20.1", "date": "2026-10-22", "kind": "patch", "snapshot": null, "by": "auto"}]}
```
`kind`：`patch｜minor｜major｜downgrade`；`by`：`auto｜customer｜outside`（outside = 不是經 `kb upgrade` 換的）。前一份還原時這個檔照還原（不在保留清單）。

### `.system/skeleton.json`（schema 1）
`{"schema_version": 1, "version": "0.21.0", "files": {"CLAUDE.md": "<sha256>", ".claude/settings.json": "<sha256>"}}`

### `config/skeleton_history.json`
`{"0.21.0": {"CLAUDE.md": "<sha256>", ".claude/settings.json": "<sha256>"}, "0.20.1": {…}}`

### `env.json` 每台電腦多 `update_check`
`{"date": "2026-10-23", "latest": "0.21.0", "kind": "minor", "allowed": true, "note": "日程可以匯出成 Excel", "auto_patched": null, "error": null}`

### `kb upgrade --check --json`
`{"plugin": "0.20.1", "vault": "0.20.1", "latest": "0.21.0", "kind": "minor", "allowed": true, "note": "日程可以匯出成 Excel", "snapshot_for_downgrade": null, "error": null}`；人讀：`現在 0.20.1；最新 0.21.0（日程可以匯出成 Excel），說「升級」就幫你升。`／`目前是最新版（0.20.1）。`／`現在連不上更新的地方，晚點再問。`

### `kb upgrade` 成功句與拒絕句（exit 3，一字不差）
- 成功：`好了，開一個新對話就是新版（0.21.0）。`；退回：`已回到 0.20.1 的知識庫，也換回 0.20.1；開一個新對話就好。`
- 拒絕：`目前是最新版（0.20.1）`、`新版剛出來，幾分鐘後再說一次`、`這台找不到 Claude 的更新程式，請服務人員幫忙`、`更新沒成功：<第一行錯誤>`、`升級前的快照已經不在，不能退回；請服務人員幫忙`、`背景整理還在跑，先停掉再升級`、`另一個備份、還原或退回正在跑，等它做完`、`現在連不上更新的地方，晚點再說一次`。

### `kb upgrade --finish --json`
`{"from": "0.20.1", "to": "0.21.0", "kind": "minor", "snapshot": "快照 2026-10-23 1405（升級前）.zip", "migrated": [".system/profile.json"], "cards_migrated": 0, "skeleton_replaced": [".claude/settings.json"], "skeleton_ask": ["CLAUDE.md"], "note": "日程可以匯出成 Excel"}`；人讀第一行 `已升到 0.21.0：日程可以匯出成 Excel`（小修：`已自動套用小修正 0.20.1：…`），之後一行一件，要問的最後。

### 開場三句（`line_version`）
`已換到 0.21.0：先跑 kb upgrade --finish 再做別的。`／`有新版 0.21.0：日程可以匯出成 Excel；說「升級」我帶你做。`／`這一版 0.21.0 撤回了；用起來有問題的話說「退回舊版」。`

### `tools/release.py`
`build <tag> [--prepare]`、`publish <tag> --public <路徑> (--for <id>… | --all | --none) [--wait 15]`、`rollout <版本> --public <路徑> (--for … | --all | --none)`；失敗印原因、exit 1。

## 驗收準則

2. [ ] 名單：`all`、`none`、含／不含這個 `vault_id` 各一；不在名單 → `--check` 回最新版、開場不提。
3. [ ] `--check`：替身清單 0.21.0、名單含她 → json 與人讀一字不差；清單連不上（逾時替身）→ 連不上那句、exit 0、什麼都沒寫。
4. [ ] 找 exe：兩個版本夾取大的；沒有就 PATH 上的；都沒有 → 固定句；不遞迴掃（替身目錄放深層假檔不會被找到）。
5. [ ] 市集名與範圍從 plugin 根與 `installed_plugins.json` 取（user、local 各一）；跑的指令列是 `[exe, "plugin", "update", "wiki-with-willy@<市集>", "--scope", "<範圍>"]`，`plugin` 前面沒有別的參數。

7. [ ] `--finish`：有 `pending` → 不再拍快照；沒有 `pending` 的大升級 → 先拍；小修 → 不拍；`current` 更新、`history` 一筆、`pending` 清掉；回的 `note` 是新版 CHANGELOG 那行；再跑一次 → 「已經是 X」。

10. [ ] 第一次跑的舊知識庫：沒有 `upgrade-history.json` → 開場不印換版那行、記成現在版本。
11. [ ] 開場：`current` 不等於 plugin 版本 → 換版那句、整理指示不印；`update_check` 有大升級 → 有新版那句；清單較舊 → 撤回那句；日期不是今天 → 背景子行程有被叫（替身記下參數）、開場沒有等它（時間 < 1 秒）。

## 確認情境
跟「備份還原與換電腦」併一次（D-133 10-22 補），在桌面版，plugin 只裝在測試資料夾（local，process.md 六）；開始前先停用舊 `llm-wiki`。要一個**公開的測試 repo**（使用者同意後建、做完刪），放這版的三份快照：X、X+小修、X+大升級（設計 session 打好 zip、改好版本號與一句話），清單網址先填進測試快照的 `config/defaults.json`。這份的步驟：
1. 裝 X（local，指令裝），在測試知識庫開對話 → 開場沒有換版那行；`upgrade-history.json` 記 X。
2. 清單換成 X+大升級、名單含這個知識庫，開新對話（背景查）、再開一次 → 「有新版」那行；說「好，升級」→ AI 先講要等、拍快照、換版、請她開新對話；**記花多久、有沒有跳「允許嗎」**。
3. 開新對話問一件事 → 開場換版那行、AI 先 `--finish`、說「已升到…」再回答。**順便試 `/reload-plugins`**：在第 2 步之後不開新對話、請使用者打 `/reload-plugins`，看是不是就換成新版（D-215）。
4. 先在知識庫 `CLAUDE.md` 加一行，再發一個改了 `CLAUDE.md` 的大升級 → `--finish` 問她要保留還是換新。
5. 清單換成 X+大升級的小修、名單含她，開新對話（背景）→ 再開一次：開場說「已自動套用小修正…」；**驗背景子行程在桌面版真的換得了版**（D-217）。
6. 清單指回 X（撤回）→ 開場撤回那句；說「退回舊版」→ AI 先講會不見什麼、她說好 → 還原加降版 → 新對話是 X。
7. 剛推清單就說「升級」（5 分鐘內）→ 快取那句或正常升；記哪一種。
8. 收尾：`uninstall`、`marketplace remove`（local），比對使用者範圍檔（判準照 B-409：local 那筆出現又消失、`settings.json` 雜湊不變）；刪測試 repo。
9. 全程記：給客戶看的字有沒有英文或編號、`hook-errors.log` 不存在。

## 不做
自動更新（`autoUpdate`，D-215）；連不上 GitHub 的客戶的路（D-219）；從 zip 升級；偵測 Claude 本身的版本（D-172）與 hook 失敗即擋（B-016，密碼與守門）；清 Claude 的 plugin cache 舊版夾（App 自己清）；卡的正文重做（D-054，B-106）；試用期間同時給其他人另一個小修（一份清單一次只有一個版本）；公開 repo 的 README 內容本身（第一次發行時寫）。
