# 找資料：六個指令怎麼叫、輸出怎麼讀

六個都只讀。`lookup`、`cards list`、`asks`、`entity list --tag` 帶 `--json` 讀（核對與加總要編號）；`agenda list`、`journal recent` 讀人讀輸出（日期帶星期、「改了」分好類，`--json` 沒有這些）。指令前綴照 SKILL.md。

## 一、查一個實體：`kb lookup <名稱或別名> --json`

客戶問的話裡有案子、人、公司、廠商的名字就先查它。名稱、別名、合併過的舊名都認得：「王董」會回王先生那一包。

回的欄位：

- `entity`：名稱、型別、大類、別名、`self`（是不是客戶自己）、`progress`（事類的 ongoing／closed／paused，其他是 null）。
- `synthesis`：綜合卡的相對路徑，沒有是 null。有就先讀它，它是整理好的現況。
- `read_ranges`：綜合卡要讀的行號範圍 `[[起行, 行數], …]`，檔頭、相關檔、紀事不在裡面。
- `cards`：掛著的檔案卡，新的在前。每張有 `title`、`card_type`、`date`（沒寫日期的是「未載」）、`entities`、`read`（完整／部分）、
  `path`（卡在哪，給 Read 用）、`stale`（原檔改過還沒重做，或客戶說過讀錯了；`redo` 是 true 的是後面那種）、`ruled_out`（客戶說過別信）、`archived`（封存的，排在後面）、`rulings`（卡上有口述為準的裁示才有）。
- `statements`：客戶說過、還有效的口述（只看到最新的，被取代或收回的不會出現）。
- `rulings`：裁示，口述為準（`spoken_wins`）排在前面；`cards` 是它掛的卡，`date` 是客戶說的那天（短標用）。
- `findings`：之前記下的推算。`stale` 是 false 的直接用（短標〔我算的〕）；true 的沒有 `text`，只有 `redo`（算法），照材料重算，不要提舊結果。
- `agenda`：掛著它、還沒結束的日程。
- `in_progress`：算在它底下的製作中檔（她放了、改了還沒說整理，D-525）：`name`、`path`（原檔）、`mtime`。問到的事跟它有關就讀那份原檔答（Word、Excel 用 `kb convert`），標「還沒整理，照原檔」。沒登記也沒卡提到時，這裡是全部製作中的檔（檔名有問的詞的在前），像的照樣讀。
- `unsorted`：整個知識庫還有幾份沒整理成卡；回答用不到就不提，客戶問才講。
- `mentions`：名稱沒登記時才有，見第六節。
- `verify_max`：要逐份核對的份數上限，超過先問（`verify.md` 第二節）。

讀法：先讀綜合卡，照 `read_ranges` 用 Read 的 offset、limit 讀那幾段（同一輪一起讀），檔頭與紀事不讀；問到時間、經過、「上次」「什麼時候」「改過幾次」才用 Grep 在那張卡撈紀事（`- YYYY-MM-DD` 開頭的條，帶關鍵字或日期），不整張讀。再只讀回答要用到的那幾張卡（看標題與卡型挑）。`spoken_wins` 那件先講客戶說的，再講「原檔寫 X」。

出處是「對話收件」的卡（檔頭有 `收件` 那行）短標照它說（D-242、D-048）：有「從 X」說〔10/26 從 X 取回的〕；沒有說〔你 10/26 貼進來的〕或〔你 10/26 放進來的〕。寫著「對話裡的版本」的是從對話紀錄取的圖，可能縮過：要核對小字、列印或存證時建議她把原圖給我（拖進對話，或說原檔在哪），我放進相關的夾再整理（D-243；桌面版拖圖片進對話也只是這一版，裁定 8）。

## 二、列卡：`kb cards list --json`

不是問某個實體、要窮舉的時候用（「今年報了幾次價」「哪幾個案子還沒收尾款」）。篩法可疊加：

- `--type <卡型>`：照字面，可重複；`--year <YYYY>`：照文件日期；`--entity <名>`：掛的實體，可重複、別名也認；
  `--source <別名>`：原檔在哪個來源。
- `--entity` 給了沒登記的名字會被拒絕（「實體清單沒有…」）：改用 lookup 的 `mentions`，不要為了查詢去登記實體（登記歸 note）。

回 `cards`（每張同 lookup 的欄位）、`types`、`undated`、`verify_max`：

- `types` 是卡型以外的篩法篩完後，庫裡實際有的卡型與份數；`in_profile` 是 false 的是設定檔第二節沒有的卡型，多半是改過名的舊名
  （「估價單」其實就是報價）。按卡型統計時先不帶 `--type` 看一次 `types`，判斷要算哪幾種，再帶多個 `--type` 列；回答講範圍：
  「今年報價 15 次：報價 12 份、估價單 3 份」。
- `undated`：沒寫文件日期的份數；帶了 `--year` 時它們沒列進 `cards`，回答要說「另有 1 份沒寫日期，沒算進去」。
- 份數題（「今年報了幾次價」「哪幾個案子還沒收尾款」）照程式列出的張數答，扣掉不採用的（`ruled_out`），不自己數卡、不憑印象補。

## 三、日程：`kb agenda list`（人讀）

「這週有什麼要交」「下個月有什麼會」。`--from <YYYY-MM-DD>`、`--to <YYYY-MM-DD>` 只收這種寫法，先把「這週」「下個月」自己換成
日期（換算完在回答裡複述），`--entity <名>` 只看某個案子，可重複；預設只列還沒完成的，`--all` 含完成與取消。
期間條目跟那段有重疊就會列。人讀每行已經帶星期，照抄，不自己算。

## 四、工作日誌：`kb journal recent`（人讀）

- 「你最近幫我改了什麼」：帶 `--changed`，只講有改的、改了什麼（綜合卡、檔案卡、日程…）。
- 「上次我問內湖李你怎麼說」：帶 `--find <詞>`，比對問、結果、做了三欄（這一句自己不算）。比的是字面：客戶用別名問找不到時，
  用 lookup 給的名稱與別名再找一次。
- 「這週」「昨天」：帶 `--since <YYYY-MM-DD>`。三種可以疊加；`--n` 預設 5 段，不夠再加大。
- 第二次問的建議怎麼說看 `verify.md` 第七節。

## 五、要問客戶的事：`kb asks`

- **回答末尾**：這句跑過 `kb lookup` 就用它帶的 `asks`（同下面的格式），不再跑；沒跑 lookup 才叫 `kb asks --about <這一句講到的實體>…（可以重複，別名也認）--json`。程式另外把這一回合查過的（`kb lookup`、
  `kb convert`、`kb cards` 碰過的）與改到的卡算進範圍。回 `asks`：跟範圍有關的與有時間性的（逾期、明後天到期），最多 1 題、已排好，當下問；
  `later`：跟這一句無關、最急的一題（沒有是 null），等一段事說完在回答最後帶一句；`others`：其餘件數，客戶問「還有多少要我決定」才照實答。
  一次一件，沒回不追問。
- **「有沒有要我確認的」「看待處理」**：`kb asks --all --json`，`asks` 是全部、照急的排；先問前 3 件（結果清單照抄編號），
  其餘講還有幾件；`set_aside` 大於 0 就最後帶一句「另外有 N 件先放著」（D-226）。
- 每題有 `key`（穩定的鍵）、`about`（對象的實體與檔編號）、`urgent`（有時間性）；`kind` 是 `pending_` 開頭的是待處理裡的事
  （讀不到、兩份寫法不同、健檢查到的、手改過的檔、健檢報告），結果照 `do`、`note` 做；健檢那幾種怎麼講看 lint skill。
- 她說「這個先不要」「暫不處理」：`kb asks set-aside <那題的 key>`，照成功句說（「有變化或快到期會再拿出來」）。
  有時間性的（逾期、快到期）程式不收、exit 3：照它回的那句改問，答法用它附的結果（D-226 補）；她要拿回來的
  先放著的事，`p-` 開頭的用 `kb pending back <key>`；其他的（名字確認、逾期這類）沒有指令拿回，對象一變就自己回來。
- 題目本身帶 `note` 的（`credential_same_kind`）先照它判斷再問，判斷不是就跳過那題。客戶怎麼回答歸 note 或 ingest（`pending_lint`、`pending_handedit`、`pending_report` 歸 lint），這裡不跑結果的指令。

## 六、名稱沒登記：`mentions`

lookup 回 `entity: null` 時，`mentions` 列標題或正文出現這個詞的卡（`where` 是標題或正文），`mentions_total` 是全部份數。
升級前做的舊卡（沒有實體欄）也找得到。讀那幾張卡回答，並說「這個名字還沒登記成案子」；客戶要登記交 note。
`mentions` 的卡沒帶 `ruled_out`：引用前跑一次 `kb cards list --json`，照編號找那張的 `ruled_out`。
最後一招：完全沒提到實體、也不是按卡篩得出來的問題（「誰的報價寫過防水保固」），才用 Grep 搜 `檔案索引/`，引用前一樣查 `ruled_out`。

## 七、起點三種怎麼說

- **全新**（還沒加資料夾、沒有卡）：lookup 回「沒有登記這個名稱，也沒有卡提到它」、`cards list` 是 0 張。照實說還沒有資料，
  建議先把資料夾加進來（manage）。
- **升級前就有資料**（舊卡沒有實體欄、沒有綜合卡）：lookup 走 `mentions`；`cards list` 照舊卡的卡型與日期列。照卡答，
  說「之後整理一次，這些卡會補上掛的案子」。
- **做到一半**（還沒整理的、原檔改過卡還沒重做、客戶按過停止）：照 `unsorted` 與 `stale` 說（見第一節、`verify.md` 第四節）；
  按過停止的對話，程式會在那一句帶提醒，照它做。

## 八、問密碼

- **她要我記的那種**（「工地大門密碼多少」）：`kb unlock get --name <她的叫法>`（名稱拿不準先 `kb unlock list`），只回她問的那一組。
  印「這台電腦沒有記「X」」就照講；換過電腦的話要她再給一次（只存在原來那台）。
- **「可以讀」的密碼檔裡的**（「建材商訂貨網的密碼是什麼」）：先找那份的編號——`kb lookup <她說的名字> --json`，沒登記時看
  `mentions`（提到它的卡，每筆的 `id` 就是原檔編號）；知道是哪個實體的就 `kb cards list --entity <實體> --json`，從 `cards` 找標題對的那筆的 `id`。
  不用 Grep 搜知識庫（卡上只寫這份是什麼、列了哪些項目，沒有值；Grep 會把別的檔一起讀進來）。
  再 `kb convert <那份的編號>` 讀原檔暫存，只回她問的那一行；其餘幾組不貼、不摘要。
- 這兩種回答程式都記成「這句回答有密碼」，工作日誌不留回答；這句只讀，不跑 `kb turn note`。
- 檔名像密碼、還沒說可以讀的：照實說「那份檔名像密碼，我預設不讀；要讓我讀跟我說「X 可以讀」」，不改檔名、不用別的方法讀。

## 九、照條件找：`kb entity list --tag 欄=詞 --json`

「在意醫療、還是準客戶的有誰」「做水電的廠商有哪些」：條件是設定檔第八節的標籤（有哪些欄與詞看 `kb profile show --json` 第八節）。

- 先篩：`kb entity list --tag 在意=醫療 --tag 階段=準客戶 --json`。不同欄要同時符合；同一欄寫好幾個詞（逗號分開）是任一個就算。名單照 `entities` 答，每個名字句尾帶短標〔照綜合卡的標籤〕（標籤是整理時照卡判斷的，R-03）；要講為什麼符合或細節，讀那幾個的綜合卡（每個先 `kb lookup <名稱> --json` 取 `read_ranges`，照第一節的讀法讀、紀事不讀），照 `verify.md` 第五節換成卡標題的短標。不要一張一張讀那一類全部的卡。空著的「在意:」算還沒標過，不算符合。
- 她的說法照字典的詞換（她說「怕生病」、字典是「醫療」就用醫療），回答講一句照「醫療」找的。
- `counts` 每個型別一筆（同名的欄不同型別各算各的，只講她問的那一類）：回答第一句照實說「客戶 200 個中 12 個符合」；`untagged` 大於 0 加一句「另有 15 個還沒照字典標過（有的剛整理、還沒標），可能漏」，問她要不要先整理補標。
- 條件不在字典裡（「有養寵物的」）：照第一、二節讀卡答，答完問一句要不要把這個條件定成標籤（她說好交 note），不自己加。
- 拒絕句（「第八節沒有…這個標籤欄」「…的字典沒有…」）會列出有的：照它改用字典裡的，或照上一點讀卡答。

## 十、找檔：`kb find "<要找的字>" --json`

「王先生的報價上個月」「中山林 會議」「油漆那份估價」：程式自己拆成實體（名稱、別名、合併過的舊名）、卡型、設定檔第八節的標籤詞、時間詞，剩下的字照空白拆開、**每個字都要在卡標題或內文**才算。所以先想一下再交：
- 名字、卡型、時間詞照她說的（不先換名字）；拿掉「幫我、放在哪、那份、的」這類不是要找的字。
- 型號、料號、編號連成一個字，不要中間留空白（「GS 1V UE 的spec」交 `GS-1V-UE spec`）；不確定檔上的寫法，0 筆再換一種寫法試一次。
- 她用的外文字照留，不翻譯。

- 結果：`parsed` 是怎麼拆的，回答第一句講一句「照 實體 王大明、卡型 報價、時間 9/1～9/30 找」；`files` 每筆有卡標題、卡型、日期、掛的實體，`open` 是原檔路徑（link 條目是網址）；`hit` 是 title（標題命中，排前面）、body（內文命中）或 filter（只照條件篩）；`entities` 是認到的實體與綜合卡內文提到的。
- `more` 為真：只列了前面的（`total` 是全部幾份），說一句加幾個字可以縮小，不自己挑。
- 不同種類的條件是「而且」；實體、卡型、標籤同一種是「或」（「信義王 大安陳 報價」＝這兩案的報價）；剩下的字要全中。結果有 `some_words: true`：沒有一份每個字都中，列的是中了部分字的，回答說一句「沒有完全對上的，列出有對到部分字的」。
- 只讀卡與綜合卡、不讀原檔（卡上沒有她要的細節，照 `verify.md` 第六節讀原檔）。
- 找不到：照實說用了哪些條件，把時間或卡型拿掉再找一次；不編。還是沒有，結果帶的 `in_progress`（還沒整理的檔，同 lookup）有像的讀原檔答、標「還沒整理，照原檔」。
- `files` 每筆（`lookup` 的 `cards` 也一樣）可帶 `archived: true`、`rulings`：封存的不拿來答「現在」的事，問歷史或明說要舊的才用，引用標「（已封存的舊資料）」；帶了 `rulings` 的先講客戶改的。
- 結果有 `fallback: true`：第一次照條件拆是 0 筆，程式已把整串（去掉時間詞）當字再找了一次，`parsed` 是第二次的；照 `parsed` 說。還是 0 筆就照實說找不到，問她換個說法或少幾個字，不說「沒有這份」。
- 要引用內容、算數字：回原檔核對，照 `verify.md`；答案句尾短標用卡標題。人讀模式（不加 `--json`）一行一筆，貼給她前改成白話。

## 十一、錢的加總：`kb statement sum`

設定檔的偏好說錢的事交給別的工具，就照偏好查，不用 `kb statement sum`。

「這個月收了多少」「今年第三季跟去年比」「幫公司收了王先生多少」：數字叫程式算，照它給的答，不心算、不從卡上的字加（D-284）。

- `kb statement sum --from <YYYY-MM-DD> --to <YYYY-MM-DD> --json`，可加 `--entity <名>`、比較另一段 `--vs-from … --vs-to …`（`diff` 給差與百分比）。回 `in` 收、`out` 付、`net` 淨、`items` 逐筆；照她講過、標了錢的話加。「這個月」「第三季」先換成日期、回答裡複述。
- 答法：先給數字，再附逐筆；逐筆的出處是她說的，就說「你 10/30 說的」，不用回原檔找。
- 沒有逐筆的錢（庫存、還欠多少、誰還沒付）程式沒有帳可查：照一般找卡、口述回答（`lookup`、`find`），卡上沒有就照實說沒記。
