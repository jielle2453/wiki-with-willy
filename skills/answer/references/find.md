# 找資料：五個指令怎麼叫、輸出怎麼讀

五個都只讀。`lookup`、`cards list`、`asks` 帶 `--json` 讀（核對與加總要編號）；`agenda list`、`journal recent` 讀人讀輸出（日期帶星期、「改了」分好類，`--json` 沒有這些）。指令前綴照 SKILL.md。

## 一、查一個實體：`kb lookup <名稱或別名> --json`

客戶問的話裡有案子、人、公司、廠商的名字就先查它。名稱、別名、合併過的舊名都認得：「王董」會回王先生那一包。

回的欄位：

- `entity`：名稱、型別、大類、別名、`self`（是不是客戶自己）、`progress`（事類的 ongoing／closed／paused，其他是 null）。
- `synthesis`：綜合卡的相對路徑，沒有是 null。有就先讀它，它是整理好的現況。
- `cards`：掛著的檔案卡，新的在前。每張有 `title`、`card_type`、`date`（沒寫日期的是「未載」）、`entities`、`read`（完整／部分）、
  `path`（卡在哪，給 Read 用）、`stale`（原檔改過還沒重做，或客戶說過讀錯了；`redo` 是 true 的是後面那種）、`ruled_out`（客戶說過別信）。
- `statements`：客戶說過、還有效的口述（只看到最新的，被取代或收回的不會出現）。
- `rulings`：裁示，口述為準（`spoken_wins`）排在前面；`cards` 是它掛的卡，`date` 是客戶說的那天（短標用）。
- `findings`：之前記下的推算。`stale` 是 false 的直接用（短標〔我算的〕），true 的（依據卡改過、被說別信或多了新卡）照材料重算。
- `agenda`：掛著它、還沒結束的日程。
- `unsorted`：整個知識庫還有幾份沒整理成卡；大於 0 就在回答末尾講一句「還有 N 份沒整理，整理完可能有更新的資料」。
- `mentions`：名稱沒登記時才有，見第六節。
- `verify_max`：要逐份核對的份數上限，超過先問（`verify.md` 第二節）。

讀法：先讀綜合卡，再只讀回答要用到的那幾張卡（看標題與卡型挑）。`spoken_wins` 那件先講客戶說的，再講「原檔寫 X」。

## 二、列卡：`kb cards list --json`

不是問某個實體、要窮舉的時候用（「今年報了幾次價」「哪幾個案子還沒收尾款」）。篩法可疊加：

- `--type <卡型>`：照字面，可重複；`--year <YYYY>`：照文件日期；`--entity <名>`：掛的實體，可重複、別名也認；
  `--source <別名>`：原檔在哪個來源。
- `--entity` 給了沒登記的名字會被拒絕（「實體清單沒有…」）：改用 lookup 的 `mentions`，不要為了查詢去登記實體（登記歸 note）。

回 `cards`（每張同 lookup 的欄位）、`types`、`undated`、`verify_max`：

- `types` 是卡型以外的篩法篩完後，庫裡實際有的卡型與份數；`in_profile` 是 false 的是設定檔第二節沒有的卡型，多半是改過名的舊名
  （「估價單」其實就是報價）。按卡型統計時先不帶 `--type` 看一次 `types`，判斷要算哪幾種，再帶多個 `--type` 列；回答講範圍：
  「今年報價 15 次：報價 12 份、估價單 3 份」。
- `undated`：沒寫文件日期的份數；帶了 `--year` 時它們沒列進 `cards`，回答要說「另有 1 份沒寫日期，沒算進去」。
- 份數題（「今年報了幾次價」「哪幾個案子還沒收尾款」）照程式列出的張數答，扣掉不採用的（`ruled_out`），不自己數卡、不憑印象補。

## 三、日程：`kb agenda list`（人讀）

「這週有什麼要交」「下個月有什麼會」。`--from <YYYY-MM-DD>`、`--to <YYYY-MM-DD>` 只收這種寫法，先把「這週」「下個月」自己換成
日期（換算完在回答裡複述），`--entity <名>` 只看某個案子，可重複；預設只列還沒完成的，`--all` 含完成與取消。
期間條目跟那段有重疊就會列。人讀每行已經帶星期，照抄，不自己算。

## 四、工作日誌：`kb journal recent`（人讀）

- 「你最近幫我改了什麼」：帶 `--changed`，只講有改的、改了什麼（綜合卡、檔案卡、日程…）。
- 「上次我問內湖李你怎麼說」：帶 `--find <詞>`，比對問、結果、做了三欄（這一句自己不算）。比的是字面：客戶用別名問找不到時，
  用 lookup 給的名稱與別名再找一次。
- 「這週」「昨天」：帶 `--since <YYYY-MM-DD>`。三種可以疊加；`--n` 預設 5 段，不夠再加大。
- 第二次問的建議怎麼說看 `verify.md` 第七節。

## 五、要問客戶的事：`kb asks --json`

「有沒有要我確認的」：照 `asks` 的順序問最多 3 題（結果清單照抄編號）；其餘講還有幾件、都在 `系統/待處理.md`。
兩份寫法不同的那種不在 `asks`，`tell` 會說還有幾件。客戶怎麼回答歸 note 或 ingest，這裡不跑結果的指令。

## 六、名稱沒登記：`mentions`

lookup 回 `entity: null` 時，`mentions` 列標題或正文出現這個詞的卡（`where` 是標題或正文），`mentions_total` 是全部份數。
升級前做的舊卡（沒有實體欄）也找得到。讀那幾張卡回答，並說「這個名字還沒登記成案子」；客戶要登記交 note。
`mentions` 的卡沒帶 `ruled_out`：引用前跑一次 `kb cards list --json`，照編號找那張的 `ruled_out`。
最後一招：完全沒提到實體、也不是按卡篩得出來的問題（「誰的報價寫過防水保固」），才用 Grep 搜 `檔案索引/`，引用前一樣查 `ruled_out`。

## 七、起點三種怎麼說

- **全新**（還沒加資料夾、沒有卡）：lookup 回「沒有登記這個名稱，也沒有卡提到它」、`cards list` 是 0 張。照實說還沒有資料，
  建議先把資料夾加進來（manage）。
- **升級前就有資料**（舊卡沒有實體欄、沒有綜合卡）：lookup 走 `mentions`；`cards list` 照舊卡的卡型與日期列。照卡答，
  說「之後整理一次，這些卡會補上掛的案子」。
- **做到一半**（還沒整理的、原檔改過卡還沒重做、客戶按過停止）：照 `unsorted` 與 `stale` 說（見第一節、`verify.md` 第四節）；
  按過停止的對話，程式會在那一句帶提醒，照它做。

## 八、問密碼

- **她要我記的那種**（「工地大門密碼多少」）：`kb unlock get --name <她的叫法>`（名稱拿不準先 `kb unlock list`），只回她問的那一組。
  印「這台電腦沒有記「X」」就照講；換過電腦的話要她再給一次（只存在原來那台）。
- **「可以讀」的密碼檔裡的**（「建材商訂貨網的密碼是什麼」）：`kb lookup` 找到那張卡（卡上只寫這份是什麼、列了哪些項目，
  沒有值），`kb convert <那份的編號>` 讀原檔暫存，只回她問的那一行；其餘幾組不貼、不摘要。
- 這兩種回答程式都記成「這句回答有密碼」，工作日誌不留回答；你的 `kb turn note` 也不要寫密碼（寫「回了工地大門的密碼」）。
- 檔名像密碼、還沒說可以讀的：照實說「那份檔名像密碼，我預設不讀；要讓我讀跟我說「X 可以讀」」，不改檔名、不用別的方法讀。
