# 核對與出處：數字怎麼對、對不上怎麼辦、出處怎麼寫

## 一、先答那句

答案有數字、日期、金額時，不超過 `verify_max` 份的先答，標「還沒逐份核對」，背景核完補一句；不先報粗估時間：

- 「今年報價的卡有 15 張卡，正在逐份對原檔，合計等一下給你。」（不自己加總，合計等 `kb tally`。）
- 單一個數字照卡上的講：「卡上寫 128 萬，正在對原檔。」

要合計的只講份數：「15 張卡，正在逐份對」，不報加出來的數。

## 二、核對

每一份都回原檔對，不挑：

- 卡上寫數字的那句結尾有〔位置〕（〔第 3 頁〕〔工作表「總表」第 12 列〕）。跑 `kb convert <卡編號>`，只讀暫存檔裡那一頁、那一列：
  PDF 每頁前面一行 `<!-- 第 N 頁 -->`、Excel 每列開頭「第 N 列：」，用 Grep 找到那一行再 Read 那一段；Word 沒有頁，Grep 那個數字或那句話。
- 掃描頁、圖片是 PNG（暫存檔裡「圖：…（第 N 頁）」那行是路徑），用 Read 看那一頁。讀不到照實說「這份讀不到，用卡上的數字，沒核對」，
  並在逐筆表那列的位置欄寫「沒核對」。
- 要核的份數超過 `lookup` 或 `cards list` 的 `--json` 給的 `verify_max`：先用卡上的數字答、標還沒核對，再問一句：「要逐份核對這 35 份嗎？會用掉不少額度」，
  順便問「以後這種就這樣做嗎」，說好記成偏好、之後不再問；客戶說「不用問」記偏好照做。

## 三、加總：`kb tally`

- 合計前，對每個要算進去的實體跑一次 `kb lookup "<名稱>" --json`：`statements`（口述）或 `rulings`（裁示）改過某一份的數字，就用改過的數字進 `kb tally`，那一筆短標〔你 X 說的〕；沒有改過的照原檔。

不心算，全部交程式。每一筆一個 `--row`：

```
kb tally --row "<卡編號> <數字> <位置>" --row "<卡編號> <數字> <位置>"
```

- 數字只留半形數字、千分位逗號、小數點、負號，萬寫成緊貼的「萬」（`1,280,000`、`54萬`、`-3.5`）；元、NT$、全形數字先去掉或換掉，
  「約一百萬」這種換成數字再算。位置可省。
- 不帶 `--json` 跑，回的表與最後一行「共 N 筆，合計…，平均…」原樣貼進回答（表上只有卡標題，不放編號），不自己重排、不重打數字。
- 比較題（兩案木作比一比）兩邊各跑一次 `kb tally`，各自的合計再比，不自己減。
- 不採用的卡不放進 `--row`；回答說一句「合約.docx 你說過別信，沒算進去」。

## 四、對不上的三種

回答裡用卡標題與短標講，不貼〔f-…〕這類編號（D-160、B-089）；綜合卡、檔案卡、設定檔一律不改。

1. **卡抄錯**（原檔寫 5,800、卡上寫 8,500）：照原檔答，跑 `kb cards redo <卡編號>`，回答說「卡上抄錯了，原檔寫 5,800，我照原檔改好」；輸出第二行「連帶要更新的綜合卡：…」有名字就加一句「信義王的綜合卡會跟著更新」。
2. **兩份原檔寫法不同**（報價表寫每坪 5,800、合約寫 6,000）：兩邊並列、各帶短標（R-08），只有客戶正要靠這個數做決定時才問哪個對；記一筆待處理：
   ```
   kb pending add --kind conflict --card <卡編號> --card <卡編號> --entity <名> --text "報價表寫每坪 5800、合約寫 6000"
   ```
   回「已經記過了」就是之前記過，不用再講一次。說「這兩份寫法不同，兩邊我都列了，你跟我說哪個對我再記下來」。
   客戶之後說哪個對：那句歸 note（記口述或裁示）；記好之後跑 `kb pending list --json` 找那一條、`kb pending resolve <編號> --how "<客戶怎麼說>"`
   關掉。
3. **原檔改過、卡還沒重做**（卡 `stale`）：照原檔答，說「這份原檔改過了，我照原檔答，卡會跟著更新」；不跑 redo。

標重做（`kb cards redo`）、記待處理（`kb pending add`）程式會自己記進工作日誌，不用跑 `kb turn note`（R-13）；其他問題不寫檔。

拒絕句（exit 3，第一行就是原因）：

- `kb tally`：`看不懂這個數字：…`（照第三節換成數字）、`至少要一筆`、`清冊沒有 f-…`、`這份還沒有檔案卡`（編號抄錯就重查 lookup）。
- `kb pending add`：`兩張要是不同的卡`、`這份還沒有檔案卡`、`實體清單沒有「X」，先 kb entity add`（拿掉那個 `--entity` 再記，不登記）；
  `--text` 一句、200 字內，不放 `"`、`$`、反引號、反斜線（金額寫「5800 元」）。

## 五、句尾短標

每句結尾一個，不印編號，回答末尾不列出處清單：

- 檔案：卡標題加位置〔報價第二版，第 3 頁〕。
- 口述：〔你 10/20 說的〕；裁示也一樣：〔你 10/21 說的〕（lookup 的 `rulings` 帶 `date`）。
- 推算：〔我算的，依據報價第二版〕；這次 `kb tally` 加出來的合計也是〔我算的〕。
- 綜合卡與檔案卡正文裡的〔f-…〕〔s-…〕〔r-…〕〔c-…〕不照貼：lookup 的 `cards`、`statements`、`rulings`、`findings` 帶了每個編號的標題
  與日期，照它換成上面三種。
- 逐筆表的每一列就是出處，表下面不用再標。
- 「那份在哪」只給檔名（卡標題）與日期；客戶說「打開給我看」才給卡上的開原檔連結（D-160）；她要你直接打開，用 `start "" "<連結>"`（PowerShell 用 `Start-Process`）開那個 `obsidian://` 連結，不寫 python 開（守門會當成寫 willy 的檔擋）。

## 六、找不到、一般知識

- 卡上（檔案卡、綜合卡、口述）找不到問的細節（地址、條款、某個數字、會議裡的某句話），先順著卡讀原檔，不直接說沒有：`kb lookup "<實體>" --json` 的 `cards`（名稱沒登記用 `mentions`；從 `kb find` 來的用 `files` 的 `card`）逐份 `kb convert <卡編號>`，`ruled_out` 的跳過、不算份數；卡上有「各部分在哪」先讀那段，沒有就在暫存檔 Grep 關鍵字（地址找「地址、住址、路、號」）再 Read 那一段。只找那個實體掛的卡的原檔，不翻整個資料夾、不找沒製卡的檔；設定檔說不抄進卡的種類（電話、統編）卡上一定沒有，直接這樣找。
- 原檔找到照原檔答，短標用那張卡的標題與位置（第五節）；卡不改、不標重做。
- 原檔也沒有才說找不到，講查了哪裡：「查了大安陳的 6 張卡和它們的原檔，都沒有寫電話。」
- 資料裡沒有的一般知識（法律、行情）另起一段：「下面是一般的說法，不是出自你的資料：」，不加短標。

## 七、第二次問

`kb journal recent --find <詞>` 看得到客戶以前問過同一件事、而那個實體的綜合卡（lookup 的 `synthesis`）沒有寫這件事的那一段時，
回答末尾建議一句：「要不要以後案子的綜合卡都固定寫『尾款收了沒』？」客戶說好交 note 加第四節。查不到就不建議。

## 八、卡上沒寫的細節

問到卡上沒寫的細節，先看那張卡的「各部分在哪」（有的話）決定 `kb convert` 後讀暫存檔的哪一段，不整份讀。
卡是指路卡（檔頭有 `卡式: 指路`）的，要用的數字直接 `kb convert` 讀原檔現查，不照卡上寫的。
