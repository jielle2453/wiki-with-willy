# 建置

服務人員到客戶那邊建置的那一天（客戶也可以自己來）：一個指令，程式記做到哪，照順序一步一步走；隔天再打一次就從停下的那步接著做。給客戶看的字一律繁體中文，工具之間的過場也是；不唸步驟名的英文、不唸編號。

這次指令後面帶的話：$ARGUMENTS

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" build status --json
```

程式輸出裡以 `kb ` 開頭的指令，都換成 `python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py"` 再執行。

## 分辨

- 指令後面沒帶話，或帶「繼續」「接著做」→ 照骨架從 `build status` 做。
- 帶了要重做某一步（「重新抽樣」「訪談重來」）→ 先跑 `kb build redo <步>`（步名對照在 steps.md 開頭），再照骨架做。
- 對話裡客戶說「幫我全部重建」「整個重來」→ 不在這裡做，照核心規則只說明（R-07）；建到一半不想要了，服務人員刪掉這個資料夾重來（這版不做整個退回）。

## 原則

- **照 `build status` 做，不自己跳步。** 順序與每步的前提由程式保證，跳步會漏登記或蓋掉她剛說的設定（D-190）。
- **每一步先講要做什麼，說好才做。** 建置不拍快照、不先演練，先講清楚（「要登記 D 槽的 Projects，312 份，其中 18 份有密碼」）服務人員才擋得下來（D-194）。
- **我猜的、AI 判斷登記的，都讓她看得到、一句話改得了。** 型別、卡型、哪些是同一個、名字是我猜的；猜錯沒人看就會一直錯下去（D-192、D-202）。
- **子代理的回報不轉述檔案內容。** 檔案內容只該進卡；舊 wiki 撈出來的列給她確認，說好的才經 kb 寫（D-022、D-193）。
- **智慧型應用程式控制不關、也不建議她關。** 它保護整台電腦，關了可能開不回來；被它擋的那項降級、寫進報告，關不關由她決定（D-189）。
- **舊的 wiki 一個字都不改。** 留著當她的備份，要查舊紀錄回去翻（D-193）。
- **名字有疑慮的建置時一次列完。** 這一步專門在確認、沒有別的問題搶，服務人員在旁一起判斷（D-202）。

## 骨架

1. 跑 `build status --json`。印的是一句話（exit 3）就照講、停下。`not_empty` 是 true：先提一句「這個夾裡已經有東西」，問服務人員要不要換位置，說不換才往下。
2. 照 `step` 讀 `read`（相對於本 skill 資料夾），照那一節先講這一步要做什麼、問好不好，說好才照 `do` 做；指令裡 `<…>` 的空格填她說的。
3. 做完跑 `after`（`kb build done <步>`）。被擋就照那句講、把缺的補做完再跑一次；過了講下一步要做什麼、問要不要繼續，說好回到 1。
4. 全量整理、綜合卡、收舊 wiki 這三步派背景的製卡助手：照 ingest skill 的「讀派工結果」那段做（批次用 Agent 工具背景派、`say` 照講、收到通知再派），整理途中她問別的照常回答。
5. `step` 走到報告那步做完，對話裡講三句重點（資料去了哪、怎麼開始問、還有什麼要她決定），問她要不要現在試問一個問題。

## 共通

- 一次一個指令；路徑加引號，不 cd，不用 && 串接。
- 不自己讀寫 `.system/`、`系統/`；都經 kb 指令。暫存檔可以 Read；交付報告用 Write 寫在工作區（`.system/temp/office/`），再交給 `kb build report --from`。
- 終端機不印檔案內容。
