# 整理成卡

這個 skill 讓檔案變成檔案卡：程式算哪些檔要做卡、抽出文字，製卡者（這版就是主對話的你）讀完照規則寫一張卡到 `檔案索引/`。程式的參數、輸出與拒絕原因看 `references/commands.md`；卡怎麼寫看 `references/carding.md`，寫卡前一定先讀它。

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …
```

`${CLAUDE_PLUGIN_ROOT}` 代換不了（指令說找不到 kb.py，或路徑開頭變成 `/scripts`）時，用開場段「kb 指令」那行的前綴。

## 分辨

- 開場有「變動：…」與「有變動：…」兩行，或客戶說「我加了」「我改了」「我刪了」「搬了」「有新東西嗎」「整理」→ 照下面的順序做。
- 「把 D 槽加進來」「不要讀…」「那個資料夾不要了」→ 走 manage，不在這裡做。manage 加完資料夾問「要我現在整理成卡嗎？」，客戶說要才回到這裡。
- 「這是合約內容，存起來」（貼一段文字或圖）→ 這版做不到，說「收件功能之後補；先把檔案放進登記的資料夾，我再整理」，不寫任何檔。
- 客戶說「我改了報價單」但 `changes` 查無變動 → 說「檔案看起來跟上次一樣，是不是還沒存檔？要我記下來的事之後會有記事功能」，不做別的事。
- 客戶問卡裡的內容（「上次那份報價在哪」）是回答的事，不是整理；直接讀卡回答。

## 順序

1. 開場自動觸發時，先回答客戶這句話，回答完再整理。客戶不是來等整理的。
2. 跑 `changes`；最後一行印了「要套用請跑 kb inventory scan。」才跑 `inventory scan` 把變動記進清冊。從 manage 加完資料夾交棒過來（加資料夾時已入冊）、或客戶明說「整理」但沒變動時，直接跑第 3 步。
3. 跑 `cards todo --json`，看 `new`、`stale`、`moved`、`missing`、`unreadable`、`broken`。
4. `moved` 有項目就先跑 `cards sync`（卡跟著原檔搬，檔名不變），跑完再跑一次 `cards todo --json`，照新的清單做下面幾步（搬了又改過的檔，搬完才會列進 `stale`）。
5. 待製卡份數（`new` 加 `stale`）≤ 上限就直接做（上限是開場那行寫的「超過 N 份」；沒有那行時跑一次不加 `--json` 的 `cards todo`，列出幾份就是上限）；超過先問「有 N 份要整理，現在做嗎？大約 N 分鐘」（一份抓 1 分鐘）。客戶說好就全部做、每 5 份講一句進度；說之後再說，這個對話不再問。
6. 每一份照 `references/carding.md` 做：
   - `convert <編號>`；
   - 讀它指的東西：暫存檔用 Read 分段讀；PDF、圖片用 Read 讀原檔（PDF 帶頁數範圍）；
   - 用 Write 寫卡：檔頭照 todo 給的 `header` 一字不改（含 `開原檔` 那行），只填（填）的欄，有個資就把 `敏感資料種類` 的 `[]` 換成種類；路徑是總資料夾接 `dir`，檔名照 `filename_pattern` 把 `<標題>` 換成標題。標題寫之前先照 carding.md 第二節對一次：檔名寫錯被打回時，錯名的檔已經留在 `檔案索引/` 刪不掉；
   - 寫完被打回（「檔頭有錯：…」）就照原因改、同一個路徑整張重寫一次；再被打回就停，回答末尾講這份沒做好與原因。總目錄程式會跟著更新，不用叫。
   - `convert` 回「讀不到」就不做這份，記住原因，回答末尾講；程式已經把它記進待處理。
   - `stale` 是原檔改過：先 Read `existing_card` 拿舊標題，標題不改，用 Write 整張寫回 `existing_card` 那個路徑，不用 Edit 補。
   - `broken` 是檔頭有問題的卡：有 `header` 的照它與 `reason` 整張寫回 `path`；沒有 `header` 的這版不修，不用跟客戶說。
7. `missing` 的條目在回答末尾問，每次最多 3 件，問法照 todo 給的 `question`（`pending_id` 是 null 就先跑 `inventory scan` 再看）。客戶怎麼答：
   - 明確說刪了 → `cards drop <編號>`，說已拿掉卡、說「退回上一版」救得回來；
   - 不是、先留著 → `pending resolve <待處理編號> --how "<客戶的話一句>"`；
   - 不用管 → `pending dismiss <待處理編號>`；
   - 含糊（「嗯」「好像吧」）→ 再問一次，這句話裡不做。刪除不能靠猜。
8. 這句話裡改了知識庫（寫卡、搬卡、拿掉卡、記待處理），最後跑一次 `turn note "<白話一句>"`，一句講完全部做了什麼；再跑會蓋掉前一次。

## 回答末尾

- 一句講做了什麼：檔名最多列 5 個，多的講份數（「我把 報價_v3.txt 整理進去、進度.xlsx 更新了、估價單的卡跟著搬到信義王」）。
- 讀不到的講份數與原因（「合約_加密.pdf 讀不到：有密碼」），說記在 `系統/待處理.md`。
- 憑證檔、只在雲端的檔、太大的檔不做卡；todo 的 `skipped` 有份數時講一句（只在雲端的請客戶在檔案上按右鍵選「保留在這台電腦上」）。
- 接著問 `missing` 那幾件。

## 共通

- 回答客戶一律繁體中文。
- 一次一個指令；路徑加引號，不 cd，不用 && 串接。
- 程式拒絕（exit 3）就轉述第一行，不自己換方法、不繞路去讀原檔。
- 不自己讀寫 `.system/`、`系統/`、`總目錄.md`；都經 kb 指令。暫存檔可以 Read。
- 終端機不印檔案內容；卡裡只寫原檔有的，數字以原檔為準。

## 參考
