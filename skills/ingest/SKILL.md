# 整理成卡

這個 skill 讓檔案變成檔案卡：程式算哪些檔要做卡、抽出文字、排好要問客戶的事；製卡者（這版就是主對話的你）讀完照規則寫一張卡到 `檔案索引/`。

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …
```

`${CLAUDE_PLUGIN_ROOT}` 代換不了（指令說找不到 kb.py，或路徑開頭變成 `/scripts`）時，用開場段「kb 指令」那行的前綴。程式輸出裡以 `kb ` 開頭的指令，都換成這個前綴再執行。

## 分辨

- 開場有「變動：…」與「有變動：…」兩行，或客戶說「我加了」「我改了」「我刪了」「搬了」「有新東西嗎」「整理」→ 照下面的骨架做。
- 開場有「設定檔有改」、客戶說「設定檔改好了」「套用」→ 照 commands.md 的 profile 節：先 `profile check` 複述差異，客戶說好才 `profile apply`；開場同時有「有變動」時先處理設定檔再整理。
- 「把 D 槽加進來」「不要讀…」「那個資料夾不要了」→ 走 manage。manage 加完資料夾問「要我現在整理成卡嗎？」，客戶說要才回到這裡。
- 搬動分兩種：**來源根**（登記的那個資料夾本身）搬了或改名 → manage；來源**裡面**的檔或子夾搬了或改名 → 這裡。
- 「這是合約內容，存起來」（貼一段文字或圖）→ 這版做不到，說「收件功能之後補；先把檔案放進登記的資料夾，我再整理」，不寫任何檔。
- 客戶說「我改了報價單」但 `changes` 查無變動 → 先跑 `cards todo --json`，`plan` 有 `cards` 這步就照骨架做（之前可能沒做完）；沒有才說「檔案看起來跟上次一樣，是不是還沒存檔？」；說的是口頭的事（付款條件談好了、會改期）就照 note skill 做，不做別的事。
- 客戶問卡裡的內容（「上次那份報價在哪」）是回答的事，不是整理；直接讀卡回答。

## 原則

- **客戶問的先答，整理的事放後面。** 客戶不是來等整理的，開場自動整理時也一樣：答案（該有的數字、出處）寫完才開始整理，最終回答答案在前（B-058）。
- **照程式給的做。** 要做的事在 `plan`、要問的事在 `asks`，指令與參數都是程式寫好的；自己拼容易打錯，也會漏掉程式的保護（D-104、D-132）。
- **守門或程式拒絕，照它的理由句做。** 拒絕本身就是保護，繞過去等於替客戶決定；理由是「大改動」就停下來告訴客戶這次要改幾張綜合卡，他說好才 `turn approve`，再重寫被擋的那張（D-073、D-075）。
- **刪除只認明確確認。** 原檔不見常只是搬走或還沒存檔，順口一句「好」不該變成刪卡；標 `strict` 的結果只認編號或明確說出那個結果，「好」「嗯」「可以」都不算，再問一次（I-082、D-134）。
- **一次最多 3 個問題。** 問太多客戶答不完；這句話需要的先問（「是哪一份報價」），剩下的名額照 `asks` 的順序從前面取，沒問到的下一句程式還會列；你自己的問題照平常問、不編號（D-135）。
- **被打回照理由句改一次，還被打回就停。** 檔頭是機器檢查的，換方法只會越改越偏；停下來告訴客戶這份沒做好與原因（D-104）。
- **卡只寫原檔有的，數字以原檔為準。** 卡是索引不是副本，抄錯的數字比沒有更糟（D-032）。

## 骨架

客戶這句有問題要答，先把答案完整寫出來再開始 1（開場自動整理時也是）。

1. `changes`：最後一行寫「要套用請跑 kb inventory scan」才跑 `inventory scan`。從 manage 交棒（加資料夾時已入冊），或客戶明說「整理」但沒變動時，直接下一步。
2. `cards todo --json`：看 `plan`、`asks`、`tell` 三樣；其他欄位是做事時的材料。
3. 照 `plan` 一步一步做：先讀該步的 `read` 指的那份（相對路徑相對於本 skill 資料夾），再照 `do` 與清單做；每做完一步重跑 `cards todo --json`，照新的 `plan` 做，因為做完一步常會帶出下一步。某份打回後還是不行，或 `convert` 失敗又沒記進待處理，只停那一份、告訴客戶，其餘照做，本輪不再重試它。`plan` 空了，或剩下的全是停下來不再重試的，就收尾，進到 4。
4. 回答：先答客戶這句；一句講做了什麼（檔名最多列 5 個，多的講份數）；`tell` 的句子原樣貼；`asks` 從前面照順序取（名額是 3 減去你自己問的題數），問 `question`，把結果的 `label` 列成選項。選項怎麼排都可以（接續的數字、字母、每題各自 1～3），但回答裡說的回覆方式要跟畫面上的一致；`n` 是程式用來對結果的，不必給客戶看。
5. 客戶回了：
   - 客戶的回覆（編號、字母、「第二題選 2」或直接說意思）要對到你上一句列出的唯一一個結果才照做，對不到或有兩個可能就問清楚；對之前不要重跑 `cards todo --json`，結果會變。對到了就照它的 `do` 依序執行，`fill` 的空格填客戶說的：`fill` 裡帶 `rule` 的空格（自由文字）照 `rule` 寫成一句白話，其他有空白或特殊字元加雙引號；客戶沒給就先問。
   - 有 `note` 照做；`do` 空又沒有 `note`，不跑指令，白話複述這個結果、請客戶自己處理。
   - 結果帶 `then`（份數多時客戶說「現在做」），照 `then` 的步驟一步一步做，每步先重跑 `cards todo --json` 拿這步的清單；份數仍多而 `plan` 只剩搬卡、或同一題又出現，都不用管也不用再問；`then` 的步驟都做完再回第 2 步。
   - 對不上就再問，這句不做；清單沒有的事照實說這版做不到，不自己發明做法。
   - 其餘結果執行完回第 2 步，因為確認名字這類結果會帶出新的事。
6. 這句話改了知識庫，送出最終回答前最後跑 `turn note "<白話一句>"` 一句講完全部做了什麼（D-084）；再跑會蓋掉前一次。

## 共通

- 回答客戶一律繁體中文。
- 一次一個指令；路徑加引號，不 cd，不用 && 串接。
- 不自己讀寫 `.system/`、`系統/`、`總目錄.md`；都經 kb 指令。暫存檔可以 Read。
- 終端機不印檔案內容。
