# 整理成卡

程式算哪些檔要做卡、切成批次、排好要問客戶的事；製卡交給背景的製卡助手（子代理 card-maker），你管派工、問客戶、回答。

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …
```

`${CLAUDE_PLUGIN_ROOT}` 代換不了（找不到 kb.py，或路徑開頭變成 `/scripts`）時，用開場段「kb 指令」那行的前綴；程式輸出裡 `kb ` 開頭的指令也換成這個前綴。

## 分辨

- 客戶說「整理」「整理一下」「改好了」「我加了」「我改了」「我刪了」「搬了」「有新東西嗎」→ 照骨架做，整理全部製作中的（`cards wip` 那幾份；「我改了 X 整理一下」也是全部，不只 X），一律 `cards dispatch` 不帶 `--ids`，md 也照常整理（裁定 15）；份數多照 `announce`、`approval` 先問（D-525）。
- 每句開頭那行叫整理幾份 md、她這句沒說整理 → 先 `inventory scan`，再 `cards dispatch --ids <編號>`（編號看 `cards todo --json`），當句做卡、加紀事、重對日程；綜合卡、這批沒做完時她說整理照 commands.md 的 `--ids`（D-525）。
- 每句開頭那行說「實體夾有變」→ 跑 `cards todo --json`，不做卡；綜合卡被刪的照 carding.md「材料的欄位」節實體夾那條判斷為什麼刪、用現有指令做（例如結案很久的 `entity remove`），回答最後說一聲「發現什麼、我猜是什麼、做了什麼」；看不出理由、兩種做法相反才問，`asks` 有題照 `asks` 問一次（D-311(3)）。
- 開場有「設定檔有改」、客戶說「設定檔改好了」「套用」→ 照 commands.md 的 profile 節。
- 「把 D 槽加進來」「不要讀…」「那個資料夾不要了」，或**來源根**（登記的那個資料夾本身）搬了、改名 → 走 manage；manage 加完問要不要整理，客戶說要才回到這裡。來源**裡面**的檔或子夾搬了、改名 → 這裡。
- 拖檔、貼圖說存、貼一段說「存起來」→ 骨架的「收件」；貼的文字沒說存是口述（note），像整份文件才問存不存（D-049）。
- 說「我改了報價單」但 `changes` 查無變動（還沒存檔等）→ 照 commands.md 的 `changes` 那條。
- 問卡裡的內容（「上次那份報價在哪」）不是整理，直接讀卡回答。
- 「先整理報價那夾就好」→ `cards dispatch --source <那個來源的別名>`；「整理到哪了」→ `cards status`；「先停」「今天先到這裡」→ 骨架的「客戶說停」。
- 「剛剛那批整理得不對」「全部退回」「退到整理之前」→ 照 `references/redo.md`，不用 `versions revert` 一句一句往前退。

## 原則

- **製卡交給製卡助手，自己不讀原檔。** 原檔內容進主對話會讓對話被摺疊、做不完也多花額度；交給背景的子代理，客戶照常能問（D-022、D-196）。只有 `plan` 的 `cards` 那步（線上文件、密碼檔，子代理做不了）與 dispatch 回 `self` 的批次（份數少，程式判斷）自己做；其他不自己決定直接改卡（D-531）。
- **派工照程式給的 prompt，不自己拆批。** 批次、認領、算在哪一句由程式記，自己拆會重做、漏做、退不回來（D-197）。
- **子代理的回報不轉述檔案內容。** 檔案內容只該進卡，轉述就把原檔內容帶回主對話、也可能講出不該講的；客戶問內容就讀卡回答（D-022）。
- **照程式給的做。** 要做的事在 `plan`、要問的事在 `asks`，指令與參數都是程式寫好的；自己拼容易打錯，也會漏掉程式的保護（D-104、D-132）。
- **被擋或拒絕：照訊息裡的指令或做法接著做完，不跟客戶提；訊息說做不到的，照核心規則 R-12。** 要改的綜合卡比平常多也照做，寫前程式會先留一份（D-073、D-075）。
- **原檔不見當作客戶刪的：卡收掉、說一句可以改回；看起來像搬走才問一次。** 在共用夾（`shared: true`）就講「X 不見了（可能是同事動的）」，不說「你刪了」，不從中推測客戶的意思或記偏好（I-082、D-134）。
- **一次問一件，照核心規則 R-06。** 這句話需要的先問（「是哪一份報價」），`asks` 有關的當下問、`later` 等一段事說完帶一句（D-135）。她說「這個先不要」就 `kb asks set-aside <那題的 key>`，先放著的程式不再列（D-226）。
- **被打回照理由句改一次，還被打回就停。** 檔頭是機器檢查的，換方法只會越改越偏；停下來告訴客戶這份沒做好與原因（D-104）。
- **卡只寫原檔有的，數字以原檔為準。** 卡是索引不是副本，抄錯的數字比沒有更糟（D-032）。

## 骨架

她說整理才整理，製作中的檔不自己整理（D-525）。下面是做事的順序，不是要跟客戶講的話：過場不唸段名、不說英文，對客戶只說程式給的句子（`announce`、`say`）與最後的回答。

- **收件**：照 `references/intake.md` 跑 `intake`，照輸出說一聲；拿不到照它那句講，不重打（D-243）；有「接著整理」就跳到「拿計畫」；放哪由你判斷、收的時候帶 `--to`（D-244、D-309）。
- **看變動**：跑 `changes`；最後一行寫「要套用請跑 kb inventory scan」才跑 `inventory scan`。從 manage 交棒，或客戶明說「整理」但沒變動時，直接往下。
- **拿計畫**：`cards todo --json`，看 `plan` 與 `announce`；`announce` 有句子先照貼。`asks`、`tell` 留到「回答」才用（背景做完會變）。
- **照計畫做**：照 `plan` 一步一步做，有 `read` 的先讀（相對於本 skill 資料夾），再照 `do` 做。
  - `names`：照 carding.md 第十一節判斷每個新名字，有把握的跑 `entity accept`，有疑慮的不動（`asks` 會問）（D-202）。
  - `dispatch`：跑 `cards dispatch --json`，照「讀派工結果」做；先用現有資料回答這句、末尾說還在整理。
  - `cards`（線上文件、密碼檔）：照 carding.md 自己寫卡；打回後還是不行、或讀不到又沒記進待處理，只停那一份、告訴客戶。
- **讀派工結果**（`cards dispatch --json`）：`batches` 每一批派一個子代理（`prompt` 原樣、背景跑；沒有派子代理的工具照 commands.md 自己做）；帶 `self` 的不派，照 `do` 拿材料、照它的 `read` 自己做，做完跑 `do` 第二條再 dispatch；`say` 有句子照講一次，收到通知之後對客戶只說 `say`。每收到製卡助手的通知再跑一次 `cards dispatch --json`；`done` 到「回答」；`failed` 程式不會再派它們，你也不要再派，原因留到「回答」講。`approval` 等其他欄位與等的時候（`cards status`）照 commands.md 的 cards dispatch 一節。
- **客戶說停**（「先停」「今天先到這裡」）：跑 `cards stop --json`，你派的子代理都中斷，再跑 `cards status` 照它那句講（停下前在寫的卡會寫完）；這個對話之後不自動整理。客戶說「整理」「繼續整理」就直接跑 `cards dispatch --json`（即 `plan` 最前面的 `resume`，D-200）。
- **回答**：`plan` 做完（有 `dispatch` 就等到 `done`），重跑 `cards todo --json`，完整回答派工那一句客戶問的，答案在前；問資料的照 answer 的做法答（先答、核對、`kb tally`、短標）。做了的事合成一行（檔名最多 5 個；好幾件就說「另外整理了 N 件，說『剛剛做了什麼』看細節」），`failed` 裡 `tell` 沒帶到的照原因講；`tell` 的句子原樣貼；`asks` 有就問一件 `question`，結果的 `label` 列成選項，回答裡說的回覆方式要跟畫面上的一致；`n` 不給客戶看。
- **客戶回了**：
  - 回覆要對到你上一句列出的唯一一個結果才照做，對不到或有兩個可能就問清楚，這句不做；對之前不要重跑 `cards todo --json`，結果會變。對到了照它的 `do` 依序執行，`fill` 的空格填客戶說的：帶 `rule` 的照 `rule` 寫，其他有空白或特殊字元加雙引號；客戶沒給就先問。
  - 做完之後（`note`、`then`、清單沒有的事、回「拿計畫」）照 commands.md 的 `asks` 那條。
- **收尾記做了**（D-084），一句白話、不含 `" $ ` \` 這四種字元：`dispatch` 給了 `note_cmd` 就把 `{做了什麼}` 換成這句照跑，這一句沒另外改知識庫就不再跑 `turn note`；其他時候 kb 指令改的程式會自己記，不用跑（R-13）。

## 共通

- 不自己讀寫 `.system/`、`系統/`、`總目錄.md`；都經 kb 指令。暫存檔可以 Read。
- 終端機不印檔案內容。
