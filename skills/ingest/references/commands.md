# 整理成卡用到的指令

前綴一律 `python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py"`。exit 0 是做完；exit 3 是程式拒絕，第一行是原因，照下面的說法轉述，不繞路。

## changes、inventory scan

- `changes`：跟清冊上次掃描比，只看不改。沒變動印「跟上次掃描時相同，沒有變動。」；有變動先一行「跟上次掃描比（還沒套用）：」，每種一行「- 新增 N 份：…」「- 修改 N 份：…」「- 搬動或改名 N 份：…」「- 不見 N 份：…」「- 之前就不見、還沒處理 N 份：…」「- 這台電腦找不到來源：…」。最後一行「要套用請跑 kb inventory scan。」出現才跑 `inventory scan`（只剩之前就不見、找不到來源時不印這行，scan 也不會變）。
- `inventory scan`：全掃並記進清冊；原檔不見會自動記進待處理，找回來會自動關掉。

## convert <目標>

目標寫清冊編號（`f-3f9a1b2c`，最常用，照 todo 給的 `id`）、uri（`file://客戶案件/信義王/報價_v3.pdf`）或磁碟路徑都可以。

成功（exit 0）第一行三種：

```
暫存檔：<絕對路徑>
格式：xlsx；工作表 3；字數 4120
```
- text 多一行 `編碼：<utf-8｜utf-8-sig｜cp950｜big5hkscs｜utf-16>`；字數超過上限多一行 `大檔：照 carding.md 摘要加定位`；字數 0 多一行 `轉換結果是空的`。
- `PDF：12 頁；用 Read 讀原檔：<絕對路徑>`（頁數數不出來寫「頁數不明」）；頁數超過上限多一行 `超過 20 頁：先讀前 20 頁，卡的讀取標「部分」`。
- `圖片：用 Read 看：<絕對路徑>`。

讀不到（exit 3）第一行「讀不到：<原因>」；記進待處理的第二行 `已記進待處理（p-…）`。

| 原因 | 記待處理 | 跟客戶說 |
|---|---|---|
| 檔名像密碼或金鑰，預設不讀 | 不記 | 「檔名像密碼或金鑰的預設不讀，這版還不能開放。」 |
| 只在雲端、還沒下載到電腦 | 記 | 「這份只在雲端，請在檔案上按右鍵選保留在這台電腦上，我再整理。」 |
| 舊格式（.doc／.xls／.ppt，照檔案），請另存成新格式 | 記 | 「這是舊格式，用 Word／Excel 另存成新格式就讀得到。」 |
| 有密碼 | 記 | 「這份有密碼，另存一份沒密碼的，或跟我說先跳過。」 |
| 不支援的格式（.zip） | 記 | 「這種格式還讀不了，跟我說先跳過，或換一份檔。」 |
| 檔案壞了：… | 記 | 「這份檔案打不開（壞了或沒下載完），換一份或跟我說先跳過。」 |
| 編碼 | 記 | 「這份文字檔的編碼認不出來，跟我說先跳過，或換一份檔。」（跟 `系統/待處理.md` 的說法一樣） |
| 找不到原檔 | 不記 | 「找不到這份檔，可能剛被搬走或刪掉；我重新比一次。」接著跑 `inventory scan` |
| 這個位置你說過不讀 | 不記 | 「這個夾你說過不讀，我不整理它。」 |
| 不在登記的資料夾裡 | 不記 | 「這份不在我讀的資料夾裡；要的話先把它所在的資料夾加進來。」 |
| 這不是要製卡的檔 | 不記 | 不用跟客戶說，是你給錯目標；照 todo 給的編號重跑 |
| 清冊沒有 f-… | 不記 | 不用跟客戶說；重跑 `cards todo --json` 拿現在的編號 |
| 狀態檔壞了（…） | 不記 | 「知識庫的狀態檔讀不了，我先停下來；說「檢查」我看原因。」 |

`--json`：`{"id","uri","path","kind","temp","chars","parts","encoding","pages","big","unreadable","pending_id"}`，沒有的欄是 null；`kind` 是 docx｜xlsx｜pptx｜text｜pdf｜image｜legacy_office｜encrypted｜unsupported。

## cards todo [--json] [--limit N]

不寫任何檔。人讀第一行：

```
待製卡 N 份（新 N、重做 N）；搬動 N；讀不到 N、原檔不見 N（見 系統/待處理.md）
```
全部 0 印 `卡都是最新的`；有檔頭壞的卡第一行尾多「；檔頭有問題 N 張」。不製卡的份數不為 0 時第二行 `不製卡：檔名像密碼或金鑰 N、只在雲端 N、太大 N`（0 的項不印）。之後每份一行 `- 新 f-… 客戶案件/信義王/報價_v3.pdf → 檔案索引/客戶案件/信義王/<標題>-3f9a1b2c.md`（重做的是 `- 重做 f-… <原檔> → <舊卡路徑>`），`--limit` 預設是開場的份數上限，多的印 `……還有 N 份`。

`--json`（做卡時用這個）：
- `new`、`stale`：每項 `id`、`uri`、`path`（原檔絕對路徑）、`origin`、`kind`、`dir`（卡放的夾）、`filename_pattern`（`<標題>-八碼.md`）、`existing_card`（stale 才有，舊卡路徑）、`created`（條目產出那天，AI 產出的卡寫起草日用）、`header`（照抄的檔頭）。
- `moved`：`{"id","from","to"}`，用 `cards sync` 處理。
- `missing`：`{"id","uri","missing_since","pending_id","question"}`，回答末尾問 `question`。
- `unreadable`：`{"id","uri","reason","pending_id"}`，已在待處理，講份數與原因。
- `orphans`：卡的編號不在清冊或原檔已不在；這版不處理，不用動它。
- `broken`：`{"path","reason"}`，檔頭有問題的卡；編號對得到清冊的多帶 `id`、`header`，照 `reason` 與 `header` 整張寫回 `path`；沒有 `header` 的這版不修，不用跟客戶說。
- `skipped`：`{"credential","placeholder","too_large"}` 份數。

## cards sync [--json]

把 `moved` 的卡搬到原檔現在的位置（檔名不變；同夾改名只改檔頭的原檔清單與開原檔）。印 `搬了 N 張卡、更新 N 張卡的原檔位置`；新位置已有同名的卡就跳過並印一行原因，照原因告訴客戶。

## cards drop <編號> [--json]

原檔不見、客戶明確說刪了才用。印 `已拿掉「<標題>」的卡；說「退回上一版」救得回來`；沒有卡的印 `已記下「<檔名>」刪了（這份沒有卡）…`。拒絕：

- `原檔還在：<路徑>，不能拿掉卡`（exit 3）→ 告訴客戶檔還在，不刪卡。
- `只能拿掉原檔不見的卡（…）`、`清冊沒有 f-…`（exit 3）→ 重跑 `cards todo --json` 看 `missing`。

## cards index [--json]

手動重寫總資料夾根的 `總目錄.md`，印 `總目錄：N 張卡`。寫卡、搬卡、拿掉卡之後程式會自動重寫，平常不用叫。

## pending list|resolve|dismiss

- `pending list [--json]`：列還沒處理的，每行 `- p-… 原檔不見 「會議紀錄_1.docx」（客戶案件/大安陳）不見了`；沒有就印 `目前沒有等你決定的事`。
- `pending resolve <p-…> --how "<一句>"`：客戶說不是刪的、先留著；印 `已記下`。
- `pending dismiss <p-…>`：客戶說不用管、先跳過；印 `已記下`。
- 拒絕（exit 3）：`沒有這條待處理：p-…`、`這條已經處理過了：p-…` → 重跑 `pending list` 看現在的。
