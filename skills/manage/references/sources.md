# kb folders 參考

## 共通

- 叫法：`python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" folders <子子命令> …`，代換不了時用開場段的 kb 指令前綴。
- 對話開在總資料夾裡，不加 `--vault`。每個子子命令都可以加 `--json`，印一行 JSON，不印給人的句子。
- exit code：0 做了，第一行是給人的句子，照轉述；3 拒絕、什麼都沒寫，第一行是原因，照「常見拒絕」說、不換方法；
  2 參數寫錯（印 usage），對照本頁改參數再跑；其他（印出 Traceback）轉述、說這次沒有改到，不重試。
- 路徑一律加引號；相對路徑以目前目錄（總資料夾）為準。

## add：登記一個來源資料夾

`folders add "<路徑>" [--alias "<別名>"] [--check]`

- `--check` 只印報告、不寫。別名預設是資料夾名，結尾的空白與點會去掉。
- 第一行：`會登記「客戶案件」（../raw/客戶案件，12 份）`（`--check`）／`已登記「客戶案件」（../raw/客戶案件，12 份）`。
- 之後可能有 `- 其中 3 份檔名像密碼或金鑰，不會讀：…`（最多列 10 個）與 `- 提醒：<一句>`。
- `--json`：`id`（`--check` 時是 null）、`alias`、`spec`、`path`、`files`、`credential_files`、`warnings`、`check`、`inventory`（`added`、`restored`、`credential`）。

### `--check` 報告怎麼轉白話

- 份數：「這個資料夾裡有 12 份檔。」
- 檔名像密碼或金鑰的檔：列檔名（最多 10 個），說「檔名像密碼或金鑰的預設不讀，這版還不能開放，之後會有。」
- 提醒句照印，不改寫、不省略（份數 0、存的是絕對路徑換電腦會找不到、整個 Desktop 範圍很大）。
- 最後問別名：「名字就叫「客戶案件」可以嗎？」客戶要換就用 `--alias`。

## exclude：不讀來源裡的一個夾或檔

`folders exclude "<路徑>" --kind hidden|unused [--reason "<一句>"]`

- 問法：「①不想讓 AI 看到（之前讀過的已送過雲端）②只是用不到，選哪一種？」只認「1」「不想讓 AI 看到」「用不到」這種明確的選擇。
- 對象要真的存在、在某個登記的來源裡面。兩種之後都不讀，那夾的檔案卡一起拿掉：`unused` 退回救得回；`hidden` 清掉殘留（purge）之後，
  卡的舊版也清了，退回救不回，只能取消排除後重新整理。
- 第一行：`已排除「行政/薪資」（不想讓 AI 看到）。卡拿掉 5 張。`；第二行清冊的數字。
- `hidden` 之後兩種情形：
  - 有綜合卡寫著那夾的內容：多一行 `接著要重寫的綜合卡：王宅、信義王（拿掉「日記」等 5 張卡的內容），寫完跑 kb folders purge "行政/薪資"`。
    同一句話裡照 `rules/synthesis.md` 改那幾張綜合卡（拿掉那些卡的內容、「整理到」照 `cards todo --json` 的檔頭），再跑那個 purge。
  - 沒有：同一個指令接著清，多一行 `清好了：…`（見 purge）；沒清完多一行 `還沒清完：…`，照 purge 那條做。
    夾名同時有 $ 或反引號和單引號時，指令給不出來，那一行改說請她先改夾名。
- `unused`：綜合卡照一般整理列待更新，下次整理時寫。
- `--json`：`source_id`、`alias`、`spec`、`kind`、`reason`、`added`、`purge`（hidden 才有：`pending` 或清完的日期；同指令清了的話
  另帶數字）、`purge_ids`、`purge_names`（記下的範圍，清完拿掉）、`inventory`、`cards_removed`、`rewrite`（要重寫的綜合卡名稱）、
  `removed_titles`、`purge_command`。

## purge：清「不想讓 AI 看到」那夾的殘留

`folders purge "<別名/相對路徑>"`（也收路徑）

- 清卡的舊版、引用那些卡的綜合卡舊版、備份裡的清冊與待處理等舊版、暫存、推算、工作日誌與留痕裡指到那夾的路徑；她自己的問句不動。
- 成功：`清好了：卡 5 張、備份 12 份、暫存 3 份、推算 1 條、工作日誌 4 段；之前讀過的已送過雲端，Claude 自己的對話紀錄也還有，這兩處清不掉`（推算 0 條不印）。
  照念最後那句；清完的回答不提那夾的檔名與內容。
- `「X」沒有要清的`（exit 0）：那條不是「不想讓 AI 看到」或已經清過，不用再做。
- `還沒清完：暫存 1 份；關掉開著的檔再跑一次 kb folders purge …`（exit 3）：有檔開著或鎖等不到；範圍已經記在那條排除裡，
  請她關掉 Word、預覽這類開著的檔，再照那個指令跑一次。
- `--json`：成功 `cards`、`backups`、`temp`、`journal`、`findings`、`remaining`、`purged`、`name`；被擋或沒清完 `purged` 是 false，
  另帶 `blocked` 或 `remaining` 與 `error`（就是人讀那句）。
- `cards todo` 的 `plan` 最前面有 `purge_synthesis` 與 `purge` 兩步時，代表上次排除後沒做完，先做這兩步。

## remove：拿掉一個來源

`folders remove "<別名>"`

- 先分清是以後不讀還是要刪檔。以後不讀再問一次：「確定拿掉「<別名>」？檔案不會動。」只認「對，拿掉」「確定」。
- 連它的排除一起拿掉、卡拿掉；客戶的檔不動。別名照 `list` 印的，一字不差。
- 第一行：`已拿掉來源「客戶案件」；你的檔案沒動，從現在起不讀它；卡拿掉 12 張；說「退回上一版」救得回。`
- `--json`：`id`、`alias`、`spec`、`inventory`、`cards_removed`。

## include：取消排除

`folders include "<路徑>"`

- 路徑要跟當初排除的那個夾或檔一樣；夾已經被刪掉也可以（只比路徑）。原本是「不想讓 AI 看到」的，複述時講出來。
- 第一行：`已取消排除「行政/薪資」，從現在起讀得到。`；`--json`：`source_id`、`alias`、`spec`、`kind`、`inventory`（`added`、`restored`、`credential`）。

## list：列出登記的來源與排除

`folders list`

- 沒有登記：`還沒有登記任何來源`。每個來源一行：`「客戶案件」 ../raw/客戶案件 → <完整路徑>`，找不到的結尾加 `（這台電腦找不到）`。
- 排除在來源底下一行一條：`  - 排除 薪資（hidden，薪資個資，2026-10-12）`；`hidden` 說「不想讓 AI 看到」、`unused` 說「用不到」。
- `--json`：`{"sources": [{"id", "alias", "spec", "path", "exists", "excludes": [{"spec", "kind", "reason", "added", "path", "exists"}]}]}`
- 組路徑：`include` 用 `excludes[].path`；`exclude` 用來源的 `path` 接夾名；組不出來或有兩個可能就請客戶貼。

## relocate：登記的資料夾搬家或改名了

`folders relocate "<別名>" "<新路徑>" [--check]`

- 新路徑請客戶從檔案總管貼。只換登記的位置：別名、不讀的設定、卡都不用重做。
- `--check` 印（不動）：
  ```
  新位置：<新路徑>（換電腦會找不到，建議放在知識庫旁邊）
  抽樣 40 份：38 份對得上，2 份不在原本的位置（例：信義王/報價_v1.pdf）
  不讀的夾：私人 在新位置找到了
  ```
- 怎麼講：照實講幾份對得上、舉例子；部分對不上就問「搬的時候整理過嗎？要換過去嗎？」；幾乎全對不上就問是不是貼錯夾；
  不讀的夾在新位置找不到的逐條講，問她那夾現在在哪。不設門檻，她說要才不帶 `--check` 再跑。
- 清冊裡還沒有這個來源的檔時第二行是 `清冊裡還沒有這個來源的檔，沒有抽樣`：不是對不上，是沒得比，照實講。
- 成功第一行：`已把「報價」換到新位置：<新路徑>；說「退回上一版」換得回來`，下面同 `--check` 的報告。
- 不想讓 AI 看到的夾在新位置找不到，不帶 `--check` 也拒絕：`不想讓 AI 看到的「X」在新位置找不到；先說它現在叫什麼，或重新設不讀，再換過去`；
  問她那夾現在叫什麼，她講了就照新名字先 `exclude --kind hidden`（排除的對象在新位置），或請她確認不用再設，才換過去。
- 換過去後不在原位的照一般整理處理（搬動、新增）。`--json`：`alias`、`spec`、`path`、`sampled`、`matched`、`misses`、`excludes`（`spec`、`found`）、
  `check`；`--check` 多 `lines`，換過去的多 `old_spec`、`cards_updated`。

## 常見拒絕與怎麼跟客戶說

第一行含什麼 → 怎麼做。「」裡是跟客戶說的話；由上往下找，先對到的算。

| 第一行含 | 怎麼做 |
|---|---|
| `sources.json 讀不了`、`等不到`、`沒有寫入`、`清冊讀不到` | 轉述那一行，說「這次沒有改到，請稍後再試；還是不行請服務人員看。」 |
| `來源已改、清冊沒跟上` | 登記已經改了：跑 `kb inventory scan` 補上清冊，再照原本那句講。 |
| `還有綜合卡寫著那夾的內容：X（先重寫再清）` | 先照 `rules/synthesis.md` 重寫 X，再跑一次 purge；不跟客戶多說。 |
| `找不到 …；排除的對象要真的存在` | 「那個夾或檔找不到，請確認名稱，或從檔案總管貼路徑。」 |
| `找不到 …` | 「這個路徑在這台電腦找不到，請從檔案總管位址列再複製一次。」 |
| `是檔案，不能當來源` | 「要的是資料夾，請給那個檔所在的資料夾。」 |
| `整顆磁碟不能當來源`、`系統資料夾` | 「不能整顆磁碟或 Windows 的系統資料夾，請指定放工作檔案的資料夾。」 |
| `總資料夾和來源不能互相包含`、`是另一個知識庫`、`裡面有另一個知識庫` | 「知識庫自己的資料夾（或另一個知識庫）不能當來源。」 |
| `和既有來源「X」重疊` | 「這個資料夾跟已經在讀的「X」重疊；要分開管請在來源裡建子夾。」 |
| `別名「X」已經有了`、`保留字`、`保留的裝置名`、`不能含`、`別名不能是空的、「.」或「..」` | 「名字「X」不能用，換一個好嗎？」客戶給了新名字再用 `--alias` 跑。 |
| `別名不能是空的；先用 folders list 看有哪些來源` | 跑 `list`，把別名念給客戶，問是哪一個。 |
| `是知識庫自己的，不用換位置` | 「這是知識庫自己的，不用換。」 |
| `不在任何登記的來源裡` | 「那個夾本來就沒在讀。要先把它所在的資料夾加進來嗎？」客戶說要，照加資料夾做。 |
| `已經在排除裡` | 「那個夾已經不讀了，不用再做。」 |
| `整個來源用 folders remove X` | 「這是整個來源；要拿掉整個「X」嗎？檔案不會動。」確認了照拿掉來源做。 |
| `沒有叫「X」的來源` | 跑 `list`，把別名念給客戶，問是哪一個。 |
| `在排除「X」裡面；要恢復就取消那條` | 「這個在不讀的「X」裡面；要讀它得把整個「X」恢復讀，要嗎？」客戶說要，`include` 那條。 |
| `不在排除清單裡，本來就讀得到` | 「那個夾本來就讀得到，不用取消。」 |
| `這裡不是知識庫` | 「程式找不到知識庫，請在總資料夾開對話。」停下來。 |
