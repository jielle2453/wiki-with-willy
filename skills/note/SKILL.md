# 記客戶說的事

客戶在對話裡親口說的事，比檔案裡讀到的更準：這個 skill 把它記進知識庫，下次開對話才找得到、會提醒、照著做。這版會記三類：**日程**（新增、改期、取消、完成）、**事類實體的狀態**（進行中、結案、擱置）、**改規則**（客戶設定檔六節，與型別改名、合併、刪除）。日程與狀態的種類、日期換算、參數與拒絕句看 `references/agenda.md`；改規則的例句、兩種意思怎麼問、成功句與拒絕句看 `references/preference.md`，欄位與指令範本由 `kb profile show --json` 給。

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …
```

`${CLAUDE_PLUGIN_ROOT}` 代換不了（指令說找不到 kb.py，或路徑開頭變成 `/scripts`）時，用開場段「kb 指令」那行的前綴。程式輸出裡以 `kb ` 開頭的指令，都換成這個前綴再執行。

## 分辨

- **日程的話**：有個會、答應某天前給什麼、某天前要繳要交、提醒我、某件事改期、取消、做完了。
- **狀態的話**：「X 結案了」「X 先暫停」「X 恢復了」「X 還沒結案」，X 要是案子這類「事」。對象類（業主、廠商）沒有狀態，照實說。
- **改規則的話**：多一類、改類名、兩類併成一類、某類不要了（型別）；某種文件卡上多記一段、兩種文件算同一種（卡型）；某種檔不整理、某種資料只記種類；某類綜合卡固定寫什麼；我叫什麼、公司叫什麼；怎麼回答我、怎麼做東西給我（偏好）。
- **程式門檻的話**（「不要每次問我要不要整理」）：說法在 `references/preference.md`，不寫檔。
- **這版記不起來的話**：糾正已記的知識、決定與裁示、實體的別名（「王先生大家都叫他王董」）、「把剛才的答案記下來」，還有「那份密碼檔可以讀」「這組密碼記下來」（說法看 `references/preference.md` 末節）。糾正的若是日程裡某條的日期或內容，算日程的改期，不在此列。同一句裡能記的先記，只對記不起來的那半說「這個我這版還記不起來，沒有寫任何檔」，不要說「記下了」，也不要偷偷寫進別的檔（D-131）。
- **回答上一則問題的話**：上一則回答末尾列過選項，客戶回的是編號或意思 → 照那一則列的結果做，不先重跑 `kb asks`（D-134）。
- **不是這裡的話**：問日程、問現況、整理檔案、加資料夾、不要讀某個夾，各有各的 skill 或回答。「把檔案裡的日期也整理進日程」是整理檔案：檔案裡讀到的日期要有出處卡，程式才認得原檔改版，改走 ingest skill，從它的 `cards todo --json` 的 `plan` 做起。

## 原則

- **改既有的先找，找不到或有兩條像的才問是哪一條。** 同一件事記兩條，開場會提醒兩次（D-130）。
- **日期換算完，在回答裡複述給客戶看。** 「下週三」換錯一天客戶不會發現，複述讓他當場糾正（I-088）。
- **這版做不到的不寫任何檔，也不說「記下了」。** 說記下卻沒記，比說做不到更傷信任（D-131、D-089）。
- **結案只聽客戶的。** 檔案裡的驗收紀錄只是線索，程式會另外問；客戶沒說結案就不改狀態（D-127）。
- **一次最多 3 個問題。** 問太多客戶答不完；你自己問的先算，剩下的名額照程式列的順序取（D-135）。
- **先找設定檔既有五節放不放得下，放不進才寫成偏好。** 卡上記什麼、哪種檔不整理寫在對的節，程式才真的照做；偏好每個對話都帶進來、有條數上限（D-137）。
- **偏好只管怎麼回答與做東西，不改卡怎麼寫。** 卡是原檔的索引，照原檔記；偏好只影響回答與產出（D-137）。
- **改程式行為的話不寫成偏好，照實說明。** 寫進偏好程式也不會照做，客戶以為改了反而更糟（D-100）。
- **一句話兩種意思分不清就問，不猜。** 記錯節客戶不會發現，等到下次沒照做才知道（D-137）。
- **會搬夾的先讓客戶看影響，明確選了才做。** 型別改名、合併、刪除會搬整個型別夾，裡面可能有客戶原檔，一句隨口的話不能直接搬（D-139、I-082）。

## 骨架

- 先分辨是哪一類。整句都記不起來的，照上面說完就收尾；一句裡有能記的，先記再說。
- 日程的話：照 `references/agenda.md` 判種類與日期。新的就加；要改、要完成、要取消的，先用 `list --json` 找到那一條再動手，找不到就問客戶「日程裡沒有這一條，要當新的記嗎？」。掛哪個案子或人，以已登記的實體為準，掛不上就不掛，回答裡說一聲。
- 狀態的話：用 `kb entity progress`。
- 改規則的話：跑 `kb profile show --json` 看六節現有的列、每欄能填什麼與 add、remove 的範本；判斷放哪一節，照範本與欄的說明填好跑。加型別時大類照 `references/preference.md` 推一個直接寫。
- 型別改名、合併、刪除：先帶 `--check --json` 跑 `kb profile type`，照它的問題與結果清單問（怎麼問看 `references/preference.md`）；客戶對到唯一一個結果才照它的 `do` 做。
- 程式拒絕說設定檔有手改還沒套用：照輸出的問題與結果清單問，客戶選了才照 `do` 做。
- 回答：講做了什麼；日程照成功句複述日期與星期；改規則照成功句複述記成什麼，再加一句「不對說一聲可以退回」；然後跑 `kb asks --json`，照 `asks` 問，名額是 3 減去你自己問的題數，把結果的 `label` 列成選項，回覆方式要跟畫面上的一致；`tell` 的句子原樣貼。
- 客戶回上一則的問題：對到唯一一個結果才照它的 `do` 做，對不到就再問；標 `strict` 的只認編號或明確說出那個結果，「好」「嗯」不算。
- 這句話改了知識庫，送出最終回答前最後跑 `turn note "<白話一句>"` 講完全部做了什麼（D-084）。

## 共通

- 回答客戶一律繁體中文，過場也是。
- 一次一個指令；路徑加引號，不 cd，不用 && 串接。
- 不自己讀寫 `.system/`、`系統/`；都經 kb 指令。
- 程式拒絕就照理由句轉成白話，不繞過去。
