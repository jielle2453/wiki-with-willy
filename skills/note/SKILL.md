# 記客戶說的事

客戶親口說的事比檔案準：記進知識庫才找得到、會提醒。四類：**日程**與**事類狀態**（`references/agenda.md`）、**改規則**（`references/preference.md`）、**改知識**（`references/correction.md`、`references/ruling.md`）；記剛才的回答另有 `references/record-answer.md`。

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …
```

`${CLAUDE_PLUGIN_ROOT}` 代換不了時用開場段「kb 指令」那行的前綴，輸出裡 `kb ` 開頭的指令照換。

## 分辨

- **日程的話**：有個會、答應某天前給什麼、某天前要繳要交、提醒我、改期、取消、做完了。糾正日程的日期或內容也算。
- **狀態的話**：「X 結案了」「先暫停」「恢復了」「還沒結案」，X 要是案子這類「事」；對象類（「這個廠商不合作了」）先在綜合卡寫一句「不再往來（客戶 11/5 說）」，等 B-525 才有狀態。
- **改規則的話**：多一類、改類名、併類、某類不要了；卡上多記一段、兩種文件算同一種；某種檔不整理；某類綜合卡固定寫什麼；照什麼條件找（第八節標籤）；我叫什麼；怎麼回答、做東西、寫卡的習慣（偏好）。程式門檻的話（「不要每次問我要不要整理」）不寫成偏好，用 `kb config set` 改（`references/preference.md`，D-307）。
- **改知識的話**：事實與決定（「內湖李改用系統櫃」）、糾正（「你記的單價有誤」「這份是大安陳的」）、別名（「王先生大家都叫他王董」）、只有這件這樣的裁示（「以口述為準」「合約.docx 是舊的別信」）。
- **密碼的話**：「那份密碼檔可以讀」記成可以讀的裁示（`references/ruling.md` 第三節）；「門禁密碼記下來」「密碼多少」「忘掉」經 `kb unlock`（`references/password.md`）。提醒不要把檔名改掉來讓程式讀（D-145）。登入、API 金鑰還存不了：說這次用完就丟，不說「記下了」，也不偷寫進別的檔（B-526、D-179）。
- **封存**（過時、收起來）：`references/archive.md`。
- **手改的卡**：開場說「客戶在 Obsidian 改了 N 張卡」。她改的算她說的，先照 `references/hand-edit.md` 處理完再回答（D-270）。
- **記的是剛才的回答**（「把剛才的答案記下來」，我推導出來的結果）：記成推算，照 `references/record-answer.md`；要存成檔走 produce；客戶剛說的事記口述（D-151）。
- **回答上一則問題的話**：照那一則列的結果做，不先重跑 `kb asks`（D-134）。
- **不是這裡的話**：問事情、整理檔案（含「我改了報價單」「把檔案裡的日期整理進日程」，走 ingest）、加資料夾、不讀某個夾。

## 原則

- **改既有的先找，找不到就當新的記、有兩條像的才問。** 同一件事記兩條，會提醒兩次、綜合卡寫兩遍（D-130、D-146）。
- **日期換算完在回答裡複述。** 換錯一天客戶不會發現，複述讓他當場改（I-088）。
- **做不到的不寫任何檔，也不說「記下了」。** 說記下卻沒記更傷信任（D-131）。
- **結案只聽客戶的。** 檔案裡的驗收紀錄只是線索，程式會另外問（D-127）。
- **一次問一件，照核心規則 R-06。** 問太多客戶答不完，也不知道先答哪個（D-135）。
- **設定檔前五節放得下就不寫成偏好。** 寫在對的節程式才照做（D-137）。
- **一句話兩種意思先照最可能的做、說出猜測。** 記錯地方客戶不會發現，說出來他才能糾正（D-137）。
- **會搬夾的先看影響；原句講明結果就算選了。** 會搬整個夾，但備進回合、退回整批回得去（D-139、D-239）。
- **糾正先查錯在哪，才知道改哪裡。** 卡抄錯、原檔就這樣寫、卡掛錯、綜合卡寫錯，修法各不同（D-147）。
- **客戶說的不寫進檔案卡。** 寫進去就跟原檔對不上，沒法重做（D-147）。
- **「以後都這樣」是改規則，「只有這件」才是裁示。** 規則每次都照做，裁示只蓋那一件，記錯地方範圍就錯（D-041）。
- **回答講做了什麼結果，不講內部名詞。** 「我照原檔改好」跟「兩個都留了」是兩回事（D-147）。
- **密碼只進憑證管理員，不進任何檔與 `turn note`。** 進了檔就跟著備份與日誌留下（D-180）。

## 骨架

- 先分辨是哪一類。整句都記不起來的照上面說完就收尾。
- 日程：照 `references/agenda.md` 判種類與日期；要改、完成、取消的先用 `list --json` 找那一條，找不到就當新的記、說一聲。掛哪個案子或人以已登記的實體為準，沒登記的看得出是新的就登記（`references/agenda.md` 第三節）。
- 狀態：`kb entity progress`（`references/agenda.md` 第四節）。
- 改規則：跑 `kb profile show --json`，判斷放哪一節、照範本填。型別與標籤的改名、合併、拿掉先帶 `--check --json` 跑 `kb profile type`／`tag`，原句講明結果就直接做，沒講清楚照最可能的做、說出猜測；改設定檔用 Edit、再 `kb profile apply`（D-307）。
- 事實與決定：照 `references/correction.md` 第一節記口述（`kb statement add`）。
- 糾正：讀那張卡，需要時 `kb convert` 對原檔，照 `references/correction.md` 四種走。
- 別名用 `kb entity alias`；裁示 `kb ruling add`（`references/ruling.md`）。
- 拒絕時帶了問題與結果清單（別名撞名）：先講猜測，沒回就照猜的做；設定檔有手改就先 `kb profile apply`。
- 回答：講做了什麼合成一行、照成功句複述（日期帶星期；改名合併拿掉講影響），改規則與改知識加一句「不對說一聲可以退回」；再跑 `kb asks --about 實體 --json`，照 `references/agenda.md` 第五節。

## 共通

- 一次一個指令；路徑加引號，不 cd、不用 && 串接。
- 不自己讀寫 `.system/`、`系統/`。
- 被擋或拒絕：照訊息裡的指令或做法接著做完，不跟客戶提；訊息說做不到的，照核心規則 R-12。
