# 記客戶說的事

客戶親口說的事比檔案準：這個 skill 把它記進知識庫，下次開對話才找得到、會提醒、照著做。四類：**日程**與**事類狀態**（`references/agenda.md`）、**改規則**（`references/preference.md`）、**改知識**（`references/correction.md`、`references/ruling.md`）；記剛才的回答另有 `references/record-answer.md`。

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …
```

`${CLAUDE_PLUGIN_ROOT}` 代換不了時，用開場段「kb 指令」那行的前綴；程式輸出裡以 `kb ` 開頭的指令都換成這個前綴再跑。

## 分辨

- **日程的話**：有個會、答應某天前給什麼、某天前要繳要交、提醒我、改期、取消、做完了。糾正日程某條的日期或內容也算這裡。
- **狀態的話**：「X 結案了」「先暫停」「恢復了」「還沒結案」，X 要是案子這類「事」；對象類沒有狀態，照實說。
- **改規則的話**：多一類、改類名、併類、某類不要了；卡上多記一段、兩種文件算同一種；某種檔不整理；某類綜合卡固定寫什麼；我叫什麼；怎麼回答我（偏好）。程式門檻的話（「不要每次問我要不要整理」）不寫檔，說法在 `references/preference.md`。
- **改知識的話**：事實與決定（「內湖李改用系統櫃」）、糾正（「你記的單價有誤」「這份是大安陳的」）、別名（「王先生大家都叫他王董」）、只有這件這樣的裁示（「以口述為準」「合約.docx 是舊的別信」）。
- **這版記不起來的話**：「那份密碼檔可以讀」「這組密碼記下來」（明說沒寫任何檔，提醒不要把檔名改掉來讓程式讀（守門只看檔名，D-145）；說法看 `references/ruling.md`）。同一句裡能記的先記，只對記不起來的那半說「這個我這版還記不起來，沒有寫任何檔」，不要說「記下了」，也不要偷偷寫進別的檔（D-131）。
- **記的是剛才的回答**（「把剛才的答案記下來」，我推導出來的結果）：記成推算，照 `references/record-answer.md`；要存成檔（Word、Excel、給人看的）走 produce；記的是客戶剛說的事照上面的改知識記口述（D-151）。
- **回答上一則問題的話**：照那一則列的結果做，不先重跑 `kb asks`（D-134）。
- **不是這裡的話**：問事情、整理檔案（含「我改了報價單」「把檔案裡的日期整理進日程」，走 ingest）、加資料夾、不讀某個夾。

## 原則

- **改既有的先找，找不到或有兩條像的才問。** 同一件事記兩條，會提醒兩次、綜合卡寫兩遍（D-130、D-146）。
- **日期換算完在回答裡複述。** 換錯一天客戶不會發現，複述讓他當場糾正（I-088）。
- **做不到的不寫任何檔，也不說「記下了」。** 說記下卻沒記，比說做不到更傷信任（D-131）。
- **結案只聽客戶的。** 檔案裡的驗收紀錄只是線索，程式會另外問（D-127）。
- **一次最多 3 個問題。** 問太多客戶答不完；你自己問的先算，剩下的照程式的順序（D-135）。
- **設定檔前五節放得下就不寫成偏好，偏好只管怎麼回答。** 寫在對的節，程式才真的照做（D-137）。
- **改程式行為的話不寫成偏好，照實說明。** 寫進偏好程式也不會照做，客戶以為改了反而更糟（D-100）。
- **一句話兩種意思分不清就問，不猜。** 記錯地方客戶不會發現，等到下次沒照做才知道（D-137）。
- **會搬夾的先讓客戶看影響，明確選了才做。** 型別改名、合併、刪除會搬整個夾，裡面可能有客戶原檔（D-139、I-082）。
- **糾正先查錯在哪，才知道改哪裡。** 卡抄錯、原檔就這樣寫、卡掛錯、綜合卡寫錯，修法各不同，修錯地方會把對的改壞（D-147）。
- **客戶說的不寫進檔案卡。** 檔案卡只照原檔，寫進去就跟原檔對不上，以後沒法照原檔重做（D-147）。
- **「以後都這樣」是改規則，「只有這件」才是裁示。** 規則每次都照做，裁示只蓋那一件，記錯地方範圍就錯了（D-041）。
- **回答講清楚是哪一種修法。** 「我抄錯了，重做那張卡」跟「原檔寫 5800，兩個都留著」對客戶是兩回事（D-147）。

## 骨架

- 先分辨是哪一類。整句都記不起來的，照上面說完就收尾。
- 日程：照 `references/agenda.md` 判種類與日期；要改、完成、取消的先用 `list --json` 找到那一條，找不到就問要不要當新的記。掛哪個案子或人以已登記的實體為準，沒登記的先問（`references/agenda.md` 第三節）。
- 狀態：用 `kb entity progress`（`references/agenda.md` 第四節）。
- 改規則：跑 `kb profile show --json`，判斷放哪一節、照範本填。型別合併先只問一句為什麼要併（D-143），再帶 `--check --json` 跑 `kb profile type`，照它的問題與結果清單問。
- 事實與決定：照 `references/correction.md` 第一節記成口述（`kb statement add`）。
- 糾正：讀那張卡，需要時 `kb convert` 對原檔，照 `references/correction.md` 的四種走。
- 別名用 `kb entity alias`；裁示用 `kb ruling add`（看 `references/ruling.md`）。
- 程式拒絕時帶了問題與結果清單（設定檔有手改、別名撞到已登記的實體）：照它問，客戶選了才照 `do` 做。
- 回答：講做了什麼、照成功句複述（日期帶星期），改規則與改知識加一句「不對說一聲可以退回」；再跑 `kb asks --json`，照 `asks` 問（欄位怎麼讀看 `references/agenda.md` 第五節），`tell` 原樣貼。
- 客戶回上一則的問題：對到唯一一個結果才照它的 `do` 做；標 `strict` 的只認編號或明確說出那個結果。
- 這句話改了知識庫，送出最終回答前最後跑 `turn note "<白話一句>"`（D-084）。

## 共通

- 回答客戶一律繁體中文，過場也是。
- 一次一個指令；路徑加引號，不 cd，不用 && 串接。
- 不自己讀寫 `.system/`、`系統/`；都經 kb 指令。
- 程式拒絕就照理由句轉成白話，不繞過去。
