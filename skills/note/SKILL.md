# 記客戶說的事

客戶在對話裡親口說的事，比檔案裡讀到的更準：這個 skill 把它記進知識庫，下次開對話才找得到、會提醒。這版會記兩類：**日程**（新增、改期、取消、完成）與**事類實體的狀態**（進行中、結案、擱置）。其他類的話先明說還記不起來，見下面「分辨」。程式是 `kb agenda`、`kb entity progress`、`kb asks`，種類怎麼判、日期怎麼換算、參數與拒絕句怎麼說，看 `references/agenda.md`。

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …
```

`${CLAUDE_PLUGIN_ROOT}` 代換不了（指令說找不到 kb.py，或路徑開頭變成 `/scripts`）時，用開場段「kb 指令」那行的前綴。程式輸出裡以 `kb ` 開頭的指令，都換成這個前綴再執行。

## 分辨

- **日程的話**：有個會、答應某天前給什麼、某天前要繳要交、提醒我、某件事改期、取消、做完了。
- **狀態的話**：「X 結案了」「X 先暫停」「X 恢復了」「X 還沒結案」，X 要是案子這類「事」。對象類（業主、廠商）沒有狀態，照實說。
- **這版記不起來的話**：偏好（「以後報價一律附日期」）、糾正已記的知識、決定與裁示、「把這個記下來」、加型別、改型別名。糾正的若是日程裡某條的日期或內容（「那個會是下週不是這週」），算日程的改期，不在此列。同一句裡能記的先記（日程、狀態），只對記不起來的那半說「這個我這版還記不起來，沒有寫任何檔」，不要說「記下了」，也不要偷偷寫進別的檔（D-131）。
- **回答上一則問題的話**：上一則回答末尾列過選項，客戶回的是編號或意思 → 照那一則列的結果做，不先重跑 `kb asks`（D-134）。
- **不是這裡的話**：問日程、問現況、整理檔案、加資料夾，各有各的 skill 或回答，不在這裡記。「把檔案裡的日期也整理進日程」是整理檔案不是口述：檔案裡讀到的日期要有出處卡，程式才認得原檔改版，所以照 ingest 的 `cards todo --json` 的 `plan` 做。

## 原則

- **改既有的先找，找不到或有兩條像的才問是哪一條。** 同一件事記兩條，開場會提醒兩次；先列出現有的再改最省客戶的力氣（D-130）。
- **日期換算完，在回答裡複述給客戶看。** 「下週三」換錯一天客戶不會發現，複述讓他看得到、當場糾正（I-088）。
- **這版做不到的不寫任何檔，也不說「記下了」。** 說記下卻沒記，比說做不到更傷信任（D-131、D-089）。
- **結案只聽客戶的。** 檔案裡的驗收紀錄只是線索，程式會另外問；客戶沒說結案，就不改狀態（D-127）。
- **一次最多 3 個問題。** 問太多客戶答不完；你自己問的先算，剩下的名額照程式列的順序取（D-135）。

## 骨架

- 先分辨是哪一類。整句都記不起來的，照上面說完就收尾；一句裡有能記的，先記再說。
- 日程的話：照 `references/agenda.md` 判種類與日期。新的就加；要改、要完成、要取消的，先用 `list --json` 找到那一條再動手，找不到就問客戶「日程裡沒有這一條，要當新的記嗎？」。掛哪個案子或人，以已登記的實體為準，掛不上就不掛，回答裡說一聲。
- 狀態的話：用 `kb entity progress`。
- 回答：講做了什麼，日期與星期照成功句複述一次；然後跑 `kb asks --json`，照 `asks` 問，名額是 3 減去你自己問的題數，把結果的 `label` 列成選項，回覆方式要跟畫面上的一致；`tell` 的句子原樣貼。
- 客戶回上一則的問題：對到唯一一個結果才照它的 `do` 做，對不到就再問；標 `strict` 的只認編號或明確說出那個結果，「好」「嗯」不算。
- 這句話改了知識庫，送出最終回答前最後跑 `turn note "<白話一句>"` 講完全部做了什麼（D-084）。

## 共通

- 回答客戶一律繁體中文，過場也是。
- 一次一個指令；路徑加引號，不 cd，不用 && 串接。
- 不自己讀寫 `.system/`、`系統/`；都經 kb 指令。
- 程式拒絕就照理由句轉成白話，不繞過去。
