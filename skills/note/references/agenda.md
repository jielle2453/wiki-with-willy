# 日程與狀態：怎麼判、怎麼叫、怎麼說

本檔寫給記日程與狀態的人（這版就是主對話的你）。程式輸出裡以 `kb ` 開頭的指令，換成開場段的 kb 指令前綴再跑。

## 一、種類怎麼從話判

| 客戶的話 | 種類 | 備註 |
|---|---|---|
| 「9/25 下午有個會」「週五跟王先生看磁磚」 | 會議 | 過了日期就算已過去，不追 |
| 「答應王先生 10/10 前給報價」「我說下週給他」 | 承諾 | 過了還沒做會被追問 |
| 「10/20 前要繳第二期款」「12/10 交屋」 | 到期 | 同上 |
| 「提醒我 10/5 寄發票」 | 提醒 | 過了就算已過去；有一定要做完的動作（寄發票、繳款）就改用到期，才會被追 |
| 「設計期 9/1 到 10/15」「施工到 11 月底」 | 期間 | 要有開始日，而且只掛一個案子 |

一句話裡有兩件事（「週五開會，週一交報價」）就分成兩條加。分不出是承諾還是到期時，問「這是你答應人家的，還是對方規定的期限？」；問不出來就用到期。

## 二、日期怎麼換算

- 今天的日期從系統提示取，不猜。程式只收 YYYY-MM-DD，而且要是真的日期。
- 沒說年份的未來日期：取今天（含）之後最近的那天。「12/10」在 10 月講，是今年；在 12 月 15 日講，是明年。已經開始的事（「設計期 9/1 到 10/15」，9/1 已過）不套這條，年份看上下文，看不出來就問。
- 只說星期（「週五跟王先生看磁磚」）：取今天之後最近的那個星期五。
- 民國年加 1911：民國 115 年 → 2026 年。
- 「明天」「後天」從今天算。「這週三」是這週一到週日裡的週三；「下週三」是下一個週一到週日那週的週三。
- 「月底」是那個月最後一天；「下個月初」是下個月 1 號；「月中」是 15 號。說得含糊（「年底前」）就問一個確切的日子。
- 時間：上午、下午換成 24 小時制（下午兩點 → 14:00）。只說「下午」沒說幾點就不填時間，回答裡說「時間先沒記」。
- 加或改日期之後，照成功句的日期與星期複述：「記成 2026-09-25（週五）14:00」。星期是程式算的，不要自己推；客戶用星期說的（「下週三」），對得上才算換算對。

## 三、`kb agenda`

| 要做的事 | 指令 | 成功句 |
|---|---|---|
| 加一條 | `agenda add --kind <種類> --date <日期> --text "<一句>"`，可加 `--time HH:MM`、`--entity <名稱>`（可重複）、`--start <開始日>`、`--lead-days N` | `已加進日程：2026-11-30（週一）交屋（到期，信義王）`；製卡抽的多 `（推測，出處：卡標題）`；已有同一條印 `日程裡已經有這條：…` |
| 找現有的 | `agenda list --json`（`--all` 含完成與取消；要重開的先用 `--all` 找；編號只在 `--json` 裡） | 一行一條 `- 2026-11-30（週一）到期 交屋（信義王）〔推測〕`，或 `日程是空的` |
| 改 | `agenda edit <編號> --date <新日期>`；也能改 `--time`、`--text`、`--start`、`--lead-days`，`--entity` 是整份換掉；不能改種類（要改就取消再加）、也不能清空欄位 | `已改：交屋 2026-11-30（週一）→ 2026-12-15（週二）` |
| 完成 | `agenda done <編號>` | `已記成完成：第二期款` |
| 取消 | `agenda cancel <編號>` | `已取消：10/5 開會` |
| 重開 | `agenda reopen <編號>` | `已重開：…` |

- 成功句裡沒有編號，客戶也不需要看編號；要編號（`edit`、`done`、`cancel` 用）從 `list --json` 取，不要唸給客戶。
- 整理檔案時（製卡者）用：`agenda scanned <卡編號>`，一張卡的日期抽完（沒抽到也算）跑一次，成功印 `已記下：「卡標題」的日期抽過了`；`清冊沒有 f-…`、`這份還沒有檔案卡，先寫卡再抽日期`、`這張卡的原檔已不在` 是你給錯編號或卡還沒寫，重跑 `cards todo --json` 看現在的。客戶說的口述日程不用它。
- 客戶親口說的，來源程式自己記成「確認」；客戶改了程式從檔案讀到的（標〔推測〕的），來源變「糾正」。你不用管。
- 掛實體：先 `kb entity list` 看登記了哪些名稱；客戶說的人或案子對得到就掛，對不到就不掛。不要為了掛日程替客戶登記新實體。
- 時段（設計期、施工期）加成「期間」，一定要 `--start`，而且只掛一個實體。

### 拒絕句怎麼跟客戶說

| 程式說 | 轉成白話 |
|---|---|
| 日期要寫 YYYY-MM-DD，而且是真的日期 | 「2/30 不存在，是 2/28 還是 3/2？」 |
| 時間要寫 HH:MM | 「幾點？我用 24 小時制記」 |
| 開始不能晚於日期 | 「開始日比結束日晚，哪個寫反了？」 |
| 期間要有 --start，而且只掛一個實體 | 「這段時間從哪天開始？是哪個案子的？」 |
| 實體清單沒有「X」，先 kb entity add | 「知識庫還沒有『X』這個案子或人，先不掛，日程照記」 |
| 日程沒有 a-… | 重新 `list --json` 找；找不到就說「日程裡沒有這一條」 |
| 等不到鎖，沒有寫入 | 「別的程式正在改，我稍後再試」，不重複硬跑 |
| 日程要有一句說明、沒有給要改的欄位、提前天數要是 0 以上的整數 | 是你漏給了，補上再跑 |
| 種類要是 到期、會議、承諾、提醒、期間 之一 | 重新判種類 |
| 狀態檔讀不到：… | 照實說讀不到，請服務人員看 |

## 四、`kb entity progress`

`entity progress <名稱> <進行中|結案|擱置> [--note "<一句>"]`

| 客戶說 | 做法 | 成功句 |
|---|---|---|
| 「信義王結案了」 | `結案`；它還沒結束的期間會一起結束 | `已記成結案：信義王（期間 1 條一起結束）` |
| 「大安陳先暫停」 | `擱置`，客戶講原因就放 `--note` | `已記成擱置：大安陳` |
| 「恢復了」「繼續做」 | `進行中` | `已記成進行中：大安陳` |
| 「信義王還沒結案」 | `進行中`，`--note "客戶說還沒結案"` | `已記下：信義王還在進行中（客戶說還沒結案）` |

- 結案改回進行中時，程式會多說「期間條目沒有重開，要的話說改期」；照轉述，客戶要就用改日程的方式把期間的日期改掉。
- 對象類實體（業主、廠商）沒有狀態，程式說「X 不是『事』類，沒有狀態」；白話說「業主沒有進行中或結案，案子才有」。
- 程式說「實體清單沒有『X』」：這個案子還沒登記，狀態記不了；白話說「知識庫還沒有『X』這個案子」，不要為了記狀態替客戶登記新實體。
- 程式說「X 已移除，不能改狀態」或「X 是你自己（關於你）」：照實說這個不能改。

## 五、`kb asks`

- `kb asks --json` 回 `asks`（要問客戶的事）與 `tell`（回答末尾要說的話）；不寫任何檔，隨時可以跑。這裡的 `tell` 只有這一回合做了什麼（加進日程、照新版改了），讀不到、不製卡這些整理狀態只在整理時（`cards todo`）才講（D-141）。
- 每題有 `question`，每個結果有 `n`、`label`、`do`（要跑的指令）、`strict`、`fill`（要客戶給的值）。
- `fill` 的空格每個都有 `rule`：照 `rule` 寫，名字類不含 `" $ ` \`，日期是 YYYY-MM-DD。
- 結果的 `do` 是空的又有 `note`，照 `note` 做（例：這個對話不再問）；`do` 空又沒有 `note`，不跑指令，白話複述請客戶自己處理。
- 逾期題：開場有「日程：逾期 N」時，回答末尾就問；每個結果要做什麼看它的 `do`（完成、取消、改到某天、下次再問都在裡面），`strict` 的只認編號或明確說出那個結果。
