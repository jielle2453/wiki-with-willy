# 改知識：事實、決定、糾正、別名

本檔寫給記客戶口述與糾正的人（這版就是主對話的你）。程式輸出裡以 `kb ` 開頭的指令，換成開場段的 kb 指令前綴再跑。

## 一、事實與決定記成一句口述

客戶說的事實（「王宅的聯絡人改成王太太了」「大成磁磚上個月漲價，每坪貴兩百」）與決定（「內湖李那案改用系統櫃，不做木工了」）記成一條口述：

```
kb statement add --entity <名稱> --text "<一句>"
```

- **一句、自己看得懂**：主詞寫出來（「內湖李改用系統櫃，不做木工」，不寫「改用系統櫃」）；有日期就寫進句子、換成 YYYY-MM-DD（換法同 `references/agenda.md` 第二節）。最多 200 字，不含 `"` `$` `` ` `` `\`（金額的 `$` 寫成「元」）。
- **掛哪個實體**：掛這件事屬於的那個登記過的實體，可以掛兩個（`--entity` 重複）。講整間公司的事（「公司下個月搬家」）掛客戶自己。實體清單沒有的，照平常的規則判斷要不要先 `kb entity add`；不確定是哪個案子就問。
- 口述跟原檔寫的不同（「付款條件談好改 30 天了」，報價單寫 60 天）照樣記一條；綜合卡會兩句並列，不用改檔案卡。
- 記了以後掛的實體會列進待更新綜合卡，下次整理時寫進現況與紀事，出處是這條口述。

**改既有的先找**：先跑 `kb statement list --entity <名稱> --json` 看有沒有講同一件事的。有 → 用 `--replaces <舊的編號>` 記新的，舊的會標成被取代（紀錄留著）；有兩條像的才問客戶是哪一條。客戶說「沒這回事」「那條記錯了，不用記」→ `kb statement withdraw <編號>`。

## 二、糾正：先分辨錯在哪

客戶說「不對」，先讀那張檔案卡（`總目錄.md` 或綜合卡的 `檔案卡` 欄找得到），需要時 `kb convert <卡的編號>` 讀原檔對照（它印的暫存檔路徑可以直接 Read），再分四種：

| 錯在哪 | 怎麼認 | 怎麼修 | 回答怎麼說 |
|---|---|---|---|
| 卡讀錯原檔 | 原檔寫的跟客戶說的一樣，卡抄錯了 | `kb cards redo <卡的編號>`，下次整理照原檔重寫 | 「是我抄錯了，原檔寫 8500，已標成要重做那張卡」 |
| 原檔本來就這樣寫 | 原檔跟卡一樣，客戶說的不同 | 記一條口述（第一節），兩個都留著 | 「原檔寫 5800，我記下你說的 8500，兩個都留著」 |
| 卡掛錯實體 | 「這份報價是大安陳的，不是內湖李的」 | `kb cards mount <卡的編號> --entity <對的名稱>` | 「改好了，這份現在掛在大安陳」 |
| 綜合卡寫錯 | 卡都對，綜合卡那句寫錯 | 先讀 `rules/synthesis.md`，直接改綜合卡那一句，出處照舊 | 「綜合卡那句我寫錯了，改好了」 |

- 原檔讀不到、或分不出是哪一種：當成「原檔本來就這樣寫」記口述並列，不猜。
- 客戶要口述贏過原檔（「以我說的為準」）是裁示，看 `references/ruling.md`。
- 實體本身錯（兩個其實是同一個、型別放錯）走 `kb entity merge`、`kb entity rename --type`。

## 三、別名

「王先生大家都叫他王董」：

```
kb entity alias <名稱> --add <別名>
```

- 加了以後，整理新檔時讀到別名就會掛到那個實體；綜合卡檔頭的別名欄程式會改。
- **撞到已登記的實體**（王董之前被登記成另一個實體）：程式不加、拒絕，`--json` 帶問題與結果清單（「是同一個，合併」「不是，先不加」）。照它問，客戶選合併才照 `do` 跑。
- 撞到別的實體的名稱或別名：照拒絕句講是跟誰撞了，問客戶是不是同一個；是就合併，不是就換個叫法。

「王董不是王先生，是他哥哥」：

```
kb entity alias <名稱> --remove <別名>
```

- 程式列出掛在這個實體、內文提到那個別名的檔案卡（`--json` 的 `suspect_cards`）。逐張讀，講的是別人的就 `kb cards mount` 改掛；分不出來就問客戶。
- 那個別名代表的人要不要登記成新的實體，照平常整理的規則。

## 四、成功句與拒絕句

成功句照它複述記成什麼。拒絕句轉白話、不繞過去：

| 程式說 | 跟客戶說 |
|---|---|
| 已記下：…（…） | 記下了：…，掛在… |
| 已改：舊 → 新 | 把之前記的「舊」改成「新」了 |
| 已收回：… | 那條拿掉了 |
| 已標成要重做：「…」 | 那張卡下次整理會照原檔重寫 |
| 連帶要更新的綜合卡：… | 那幾張綜合卡也會跟著改 |
| 已改：「…」掛在 X（原本是 Y） | 照念 |
| 已加別名：X 也叫 Y | 以後看到 Y 就當成 X |
| 已拿掉別名…；有 N 張卡內文提到… | 照念，再說逐張看了哪幾張要改掛 |
| 實體清單沒有「X」，先 kb entity add | X 還沒登記；照整理的規則判斷要不要登記，不確定就問是哪一個 |
| 口述要一句話，最多 200 字 | 換成一句短一點的再記（不用跟客戶講字數） |
| 口述裡不能有 " $ ` \ 這四種字元 | 換個寫法再記（「$」寫成「元」） |
| 沒有這條口述／這條已經被取代了，改最新的那條 | 重跑 `list --json` 找最新的那條再改 |
| 清冊沒有…／這份還沒有檔案卡 | 這份還沒整理成卡，先整理再改 |
| 「X」跟「Y」的別名撞了 | X 已經是 Y 的別名，問是不是同一個 |
| 「X」已經登記成一個實體了，是同一個就合併 | 照 `--json` 的問題問 |
| 「X」沒有「Y」這個別名 | X 本來就沒有叫 Y，不用拿掉 |
| 等不到鎖，沒有寫入 | 「別的程式正在改，我稍後再試」，不重複硬跑 |
