note 改客戶設定檔的細節（D-136～D-139、D-143、D-144）。欄位、每欄能填什麼、指令範本都由 `kb profile show --json` 給，這裡不列參數。

## 先找設定檔的其他節，放不進才是偏好

「以後……」「都要……」先想：是卡上要記的段落（第二節）、哪種檔不整理或只記種類（第三節）、某類綜合卡固定寫什麼（第四節）、我是誰（第五節）、要多一類（第一節）、要照什麼條件找（第八節標籤）？都不是、講的是怎麼回答、怎麼做東西、寫卡時照做的習慣，才寫成偏好。上限分兩組（以 `show --json` 偏好那節的 `limits` 為準）：整理成卡以外的開場都帶進來（`opening`），整理成卡的只給製卡（`card`）；滿了自己合併精簡，說一聲改成什麼。改既有的一條用 `序號=N`（照 `show --json` 的序號），不另加一條。

## 用在哪與先比對

- 用在哪（能填的值在 `show --json` 偏好那節的 `choices`）：每次回答都要的填全部；只在做報價單、文件時要的填做文件；只在寫卡時要的（「卡上人名用連結」）填整理成卡；只在某個客製功能用的填那個功能的名字。分不清就填全部，不問。
- 加之前先帶 `--check --json` 跑同一句：`compare` 是同組加全部的每一條、`similar` 是字面很像的序號、`over_limit` 是加了會超過。不只看 `similar`，整張 `compare` 自己讀一遍：意思一樣、可以併成一句、或互相矛盾的（「講重點就好」對「回答先講結論」字面不像也算），自己併進那條（`序號=N` 改那條）、說一聲改成什麼；都沒有就直接加。
- 成功句照念用在哪（「記下了，只在做文件時用：…」「記下了，每次都照做：…」），她聽了說不對就用 `序號=N` 當場改。

## 偏好月檢（待處理）

健檢每月開一件「每月看一次偏好」，`data.rows` 是第六節全表（序號、偏好、用在哪），`data.similar` 是字面很像的配對。下次開對話照待處理處理時：自己讀全表判斷有沒有重複、可以合併、互相矛盾的。有就自己 `序號=N` 或 remove 併好，說一聲（「第 1 條跟第 3 條意思一樣，我併成『回答先講結論、簡短』了」），不問；改完 `kb pending resolve <編號> --how "<改了什麼>"`；沒有就直接 `kb pending resolve <編號> --how "看過沒有要改的"`，回答裡不提。「用在哪的功能不在了」「偏好快滿了」是另外兩件，照那件的結果問。

## 偏好跟系統規則打架

偏好只管 AI 怎麼回答與做東西。卡、日程、綜合卡照規則寫：客戶說「金額講萬元」，回答時換成萬元，卡上仍照原檔寫到個位數。客戶問起就這樣說：「卡上照原檔記，跟你講的時候用萬元。」

要 AI 換個做法的話（「以後不用問我直接刪」「指令可以串在一起跑」）記成偏好照做，說一聲記成什麼；開場的偏好段跟核心規則衝突時照客戶的，只有刪掉、蓋掉之前先留一份不讓。程式門檻的數字走 `kb config set`，不寫成偏好。

## 一句話兩種意思

例句 16 這類，兩種都說得通、放的地方不同，先照最可能的寫、說出猜測：「先記成幫你做報價單時要附報價日期；如果是要每張卡上都記，說一聲我改。」兩種都要就兩節各寫一列。「客戶要記介紹來源」也是：每張客戶的綜合卡寫一段（第四節），還是要能照它找人（第八節標籤），先猜一個。

## 程式門檻那類話

「不要每次問我要不要整理」「整理不用先跟我說」：整理的門檻是程式的數字（設定值），不是偏好，寫進偏好程式不會照做。用 `kb config set <鍵> <值>` 改（鍵與現值看 `kb config show`；「不要每次問我要不要整理」改 `ingest_auto_max`，調到夠大），說一聲改成什麼、想改回說一聲（`kb config reset <鍵>`）：「改成 1000 份以內直接整理，不再問；想改回說一聲。」不寫偏好。

## 加型別時大類怎麼推

大類四選一：對象（人或公司：業主、廠商、工班）、事（有開始有結束的工作：案子、工地、商空）、物（被管理的東西：設備、材料、車）、主題（規則與知識：法規、工法）。推一個直接寫，回答只講加了什麼型別，不講「大類」「對象」這些詞：推錯了退得回來，所以不先問（D-139）。客戶說大類錯了：還是剛加的那句就說退回再照對的大類加；已經過了幾句、底下還沒有實體，就直接刪掉這一類再重加（刪型別照下節）；同名再加一次只能改一句說明，大類這版改不了（程式會拒絕）。

## 會搬夾的三種：改名、合併、刪除

先帶 `--check --json` 跑，程式回影響（幾個實體、幾張檔案卡與綜合卡、哪些夾從什麼改成什麼）、問題與結果清單，不動任何檔。她原句已講明結果（「工班併進廠商」、空的「設計師那類不用了」）就算確認：照結果的 `do` 直接做，做完講影響、說不對可以退回（D-239）；原句沒講清楚（只說「整理一下類別」、要併到哪裡沒講）也先照最可能的做、說出猜測，沒回就照猜的，不 strict。

- 改名：原句講明新名字（「工班改叫師傅」）就直接做；只說名字不好、沒講改成什麼才問。
- 合併：原句講明併進哪一類就直接做，做完照念影響（大類不同時多一句狀態怎麼變）。原句沒講清楚、像是誤會（例：「工班跟廠商好像差不多」）也先照最可能的做、說出猜測，不先問為什麼要併、不 strict。
- 刪除：空的照原句直接刪、講可以退回；底下還有實體，先講猜測併到最像的一類，沒回就照猜的合併，空了才刪。刪客戶的原檔不在這條（照 R-04 先留一份就做）。
- 調順序（「把業主排第一個」）：`kb profile add 型別 名稱=業主 序號=1`，先帶 `--check --json` 講哪些夾會改名（`renames`），她說好才做；型別夾照型別表順序編號（`01`、`02`…），新加的型別排最後、不問放第幾個（D-248）。合併、刪掉之後後面的夾往前補號，做完的句子會講。
- 開場有「型別夾「X」你改名叫「Y」了」那行：她自己把夾改了名，照指示跑 `kb profile apply`，照念成功句（`照你改的名字記下了：…`），不問、不改回去（D-247）。

## 成功句與拒絕句怎麼說

成功句（「記下了，每次都照做：……」「已把型別「工班」改名叫「師傅」：……」）照它複述記成什麼，加一句「不對說一聲可以退回」。被擋或拒絕：照訊息裡的指令或做法接著做完，不跟客戶提；訊息說做不到的，照核心規則 R-12。常見的怎麼接著做：

| 程式說 | 怎麼接著做 |
|---|---|
| 設定檔有你改過還沒套用的地方，先套用再改 | 先跑 `kb profile apply` 套用（`add` 會自動先套用，回 `applied_first`），再做原本那句，說一聲；不問 |
| 設定檔有你改過但讀不懂 | 自己修那一列（Edit）再 `kb profile apply`，改不好退上一版；再做原本那句 |
| 偏好最多 N 條／合計最多 N 字（整理成卡的另算） | 自己合併精簡同組現有的，說一聲改成什麼，再記這一句 |
| 偏好的用在哪要是 … 之一 | 照列出的值挑一個重記；說不出是哪個就記成全部 |
| 沒有第 N 條偏好 | 先用 `show --json` 看序號自己對；對不上才問她指哪一條 |
| 偏好裡不要放密碼；要記的話跟我說『記下來』… | 偏好裡不放密碼，這句沒有寫任何檔；她要記那組密碼就照 `references/password.md` 存進這台電腦的憑證管理員 |
| 偏好裡不能有 " $ ` \ 這四種字元 | 換個說法、不用那幾個符號再記（例：「$」寫成「元」） |
| 型別「X」已經有了，大類不能這樣改 | X 已經有了，大類這版改不了 |
| 「X」已經有同名的資料夾或檔 | 把那個舊的夾或檔先改名（`kb source-edit rename`），再用這個名字，說一聲 |
| 「X」底下還有 N 個實體 | 照最可能併到最像的一類，說出猜測，再做原本那句 |
| 型別表沒有「X」、沒有這一列 | 先用 `show --json` 看現有的自己對；對不上才問客戶指哪個 |
| 退不回去：…什麼都沒動 | 把擋住的那個資料夾用 `kb source-edit` 搬開（先留一份），再退回 |

「那份密碼檔可以讀」不是偏好，看 `references/ruling.md` 第三節；「這組密碼記下來」看 `references/password.md`。

## 標籤（第八節）：照什麼條件找

字典的欄與詞由她定；字典外的詞看得出是新的一類就直接加進字典、說一聲（D-231、D-310）；標籤記在實體清單，改字典時程式直接改實體清單與每張綜合卡檔頭那一行（D-237、D-505）。

| 客戶說的話 | 怎麼做 |
|---|---|
| 客戶加一個在意的：寵物 | `kb profile add 標籤`（照 `show --json` 第八節的範本填型別、欄名、詞）：已有這一欄就把詞加進去 |
| 以後客戶也照介紹來源分／我想照工種找廠商 | 同上加一欄；候選的詞先讀一輪那類的綜合卡提出來、各有幾張（一個型別讀到 50 張就夠），她刪改說好才加，不自己編；一張卡能同時有好幾個就問要不要可多選 |
| 張志明改成準客戶／王小姐也在意醫療 | `kb entity tag <名稱> 階段=準客戶 --said`（多選的欄寫那一欄全部的詞：先 `kb lookup <名稱> --json` 看現在的 `tags`、加上她說的）；她說的詞不在字典，照上一列直接加進字典、說一聲；成功句照念。之後重寫卡也照她說的留著 |
| 開場段說綜合卡上的標籤她改了（她在 Obsidian 改的） | `kb entity tag --from-card`：合字典的照她改的記進去，成功句照念；詞不在字典的直接加進字典、說一聲；她要改回就 `kb entity tag <名稱> 欄=原本的詞 --said` |
| 流失改叫停保 | `kb profile tag rename` 先帶 `--check --json`，原句講明了就直接做，做完講幾個跟著改、可以退回 |
| 把健康跟醫療併成一個叫醫療 | `kb profile tag merge` 先帶 `--check --json`，原句講明併成哪個就直接做，做完照念幾個標了、幾個兩個都有、可以退回；只說「健康跟醫療差不多」也先照最可能的併、說出猜測 |
| 把旅遊拿掉 | `kb profile tag remove` 先帶 `--check --json`，直接做：標了旅遊的一起拿掉（卡上也是），做完講幾個、可以退回 |

- 欄改名、拿掉整欄同一套，不帶詞。加了欄或詞，那一類每個都會標成要補標籤（成功句帶張數與個數，沒有綜合卡的也補）：跟她說有 N 個要補標、要不要現在補；她說好就照 ingest 的派工做（`kb cards dispatch --json`，照 `../ingest/SKILL.md`（相對 note 這個 skill 的資料夾）「讀派工結果」，背景補、她照常可以問別的），說等一下就留到下次整理。
- 成功句照複述（「已把「健康」併進「醫療」：23 個只剩醫療；不對可以說退回」）。
- 她手改了設定檔第八節、拿掉的詞或欄有實體用到：套用會被擋並給結果清單（改名卡上一起換、卡上一起拿掉、其實要併、先不套用），照它問；選「其實要併」的，自己用 Edit 把那格改回去，再照合併做。

| 程式說 | 跟客戶說 |
|---|---|
| 「X」已經在「欄」的字典裡；要併在一起用… | X 已經有了，要把它們併成一個嗎？（照指令帶 `--check` 再問） |
| 第八節沒有「X」這個標籤欄／「欄」的字典沒有「X」 | 字典裡沒有 X（照「有：」後面列的問她指哪個） |
| 「欄」只剩「X」這個詞 | 這一欄只剩它，要整欄拿掉嗎？ |
| 拿掉標籤的詞或欄用 kb profile tag remove… | 不說出來，改走上面拿掉那條（先 `--check`） |

- 多人用時（`kb who` 說 multi）偏好 `kb profile add 偏好` 預設記成這台的人的；她說「我們大家都…」才多帶 `--whose 全隊`，拿不準歸說的人。開場只帶全隊的加這台的人的。
