# 把剛才的答案記下來（推算，D-151、D-154）

客戶說「把剛才的答案記下來」「這個算好的存起來」：記的是我上一則回答推導出來的結果（合計、比較、還沒收的款），
記成一筆推算。客戶自己剛說的事（「內湖李改用系統櫃」）不是這裡，照 `correction.md` 記口述。

## 怎麼記

```
kb finding add --entity <名> --text "<結果一句>" --how "<算法一句>" --basis <卡編號> <卡編號> …
```

- `--entity`：那件事掛的實體，可以多個；講整個公司的（「今年報價總共多少」）掛客戶自己（`kb profile show --json` 第五節的名稱，
  或 `kb lookup` 回 `self` 是 true 的那個）。
- `--text`：結果一句，照上一則回答的數字寫（「大安陳尾款 32 萬還沒收」），不重算、不改寫數字。
- `--how`：算法一句（「合約尾款對三張請款單」「今年報價 12 份加估價單 3 份，程式加總」）。
- `--basis`：依據卡，取那則回答用到的卡：有 `kb tally` 的就是 `--row` 裡的那幾張；只引用一兩張卡的就是句尾短標那幾張。
  編號從那一則 `kb lookup`、`kb cards list` 或 `kb tally` 的 `--json` 取；對話裡找不到就重跑那個查詢拿編號，不猜。
- 同一件事之前記過（`kb lookup` 的 `findings` 有一筆講同一件事的，或 `kb finding list --entity <名> --json`）：帶
  `--replaces <c-…>`，舊的記成被取代，不另記一筆。過期的（`stale`）重算後也是用 `--replaces` 記新的。
- 上一則回答裡的數字還沒核對過（只有粗估）：先核對再記：每份 `kb convert` 讀卡上〔位置〕那頁對過，再 `kb tally` 加總，記的是核對過的結果。

## 成功句怎麼轉述

- `已記下推算：大安陳尾款 32 萬還沒收（大安陳；依據 3 份）` → 「記下來了：大安陳尾款 32 萬還沒收，依據那 3 份檔；下次整理時會寫進
  大安陳的綜合卡。不對說一聲可以退回。」掛的是客戶自己（沒有綜合卡）就說「下次問我會先拿這筆出來，依據的檔改了我會重算」。
- `已改：<舊> → <新>` → 「之前記的 <舊> 改成 <新> 了。」
- 記完照 SKILL.md 跑 `turn note "<白話一句>"`。

## 拒絕句（exit 3，第一行就是原因）

- `實體清單沒有「X」，先 kb entity add`：先問「X 是新的案子／對象嗎？」，客戶說是才登記。
- `依據至少要一張卡（--basis）`：那則回答沒有出自卡（一般知識、只有口述）就說「這個是一般的說法，不是從你的檔算的，沒有記」。
- `清冊沒有 f-…`、`這份還沒有檔案卡`：編號抄錯或卡還沒做；重跑查詢拿對的編號，卡還沒做就說整理後再記。
- `推算要一句話，最多 200 字`、``推算裡不能有 " $ ` \ 這四種字元``：縮成一句、把金額的 $ 換成「元」再記。
- `沒有這筆推算：c-…`、`這筆已經被取代了，改最新的那筆`：重查 `kb finding list --entity <名> --json` 拿最新那筆。
- `等不到鎖，沒有寫入`：稍後再跑一次；`狀態檔讀不到：…`：照實說推算清單壞了、沒有寫入，不自己改檔。
