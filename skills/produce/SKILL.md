# 做成文件

給客戶看的字一律繁體中文，工具之間的過場也是；不唸步驟、不寫自言自語。

客戶要我做一份東西。內容與版面交給我自己的判斷與文件技能；這裡只管做不穩的事：工具、原檔先拿副本、成品放進知識庫、跨對話的草稿、數字、資料離開電腦。

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …
```

`${CLAUDE_PLUGIN_ROOT}` 代換不了時，用開場段「kb 指令」那行的前綴；程式輸出裡以 `kb ` 開頭的指令都換成這個前綴再跑。

## 分辨

- **新做**（「幫我做一份內湖李的進度報告給業主」「把王宅的報價整理成 Excel」「做一份提案簡報」「幫我寫一封信給王先生」）：先收資料；簡單的直接做成檔，複雜的先給草稿。
- **照舊的寫新的、套範本**（「照去年信義王的合約幫大安陳寫一份」「用我的報價單範本」）：舊檔或設定檔第七節的範本當底；範本只有一份就直接用，多份才問。
- **轉格式**（「這份估價單轉成 PDF」）：拿副本轉。
- **把剛才的回答存成檔**（「剛才那個表存成檔案」「這個做成 Excel」）：剛才的回答就是草稿，不再給一次。
- **草稿與定稿**（「草稿可以了，定稿吧」「再改一下」「不要了」）：照草稿那一題做；「定稿放到王宅那個夾」定稿時直接 `kb output save --to` 放那個夾。
- **不是這裡的話**：問資料、問數字走 answer；「以後報價單一律附日期」「那份報價總價是 128 萬」「記下來」走 note；「我存了新報價進去」「整理一下」走 ingest；搬檔、加資料夾走 manage；「幫我寄給王先生」這版做不到，照實說、給她草稿自己寄。

## 原則

- **內容簡單、資料齊的直接做成檔，說「不對我再改」；筆記、討論紀錄這類 md 本身就是成品的，直接存成定稿、不標草稿；要做成 Word、Excel、簡報的複雜內容，先用檔案工具（Write）把 md 草稿寫進暫存區給她看，她說可以才做成檔；剛回答過的算草稿。她說「這份先不要整理」才標草稿。** 簡單的多一輪草稿是白等；複雜的檔做完再改很費工；標了草稿就不做卡、之後問不到（D-163、D-322、D-519）。
- **做成什麼看用途：要 Excel 的做 Excel；說了寄出、印出、套範本的做本機檔；其餘（給業主、同事看都算）一律推薦線上文件。這個知識庫第一次做線上文件，建之前講一次三件事：存在她的 claude.ai 帳號、預設只有她看得到、要檔怎麼拿；講過記成偏好「線上文件三件事講過了」，之後客戶問才講。** 不講清楚她以為檔在電腦裡（D-165、D-166）。
- **成品用 `kb output save --to` 放到相關的檔旁邊（案子的夾、客戶的夾）；不屬於任何案子的與草稿才進暫存區。** 程式放的才有備份與登記，說退回可以退這一步（成品先留著、要刪再說）、下次問才找得到（D-170、D-317、B-081）。
- **工作區用檔案工具寫：腳本、解開的 XML 都寫在 `kb office` 印的工作區，做檔叫 `kb office run`；腳本只讀副本、只寫 OUT_DIR（工作區），不碰原檔與其他位置。** office run 跑的腳本守門管不到，寫到別處程式擋不住也沒有備份；成品留在工作區，再經 output save 放進來（實作回報裁定 1、B-401）。
- **草稿裡的數字逐份回原檔核對，合計交 `kb tally`；Excel 有公式的 `kb output save` 會重算、有錯誤值就不放，要讀算好的數核對用 `kb office recalc`；重算不了就不報公式算出來的數。** 抄錯與心算錯只有核對與程式擋得住，沒重算的公式格是空的（D-159）。
- **成品不附出處與連結，出處在回答裡講用了哪幾份。** 成品是要給業主、廠商看的，內部的卡與檔名不該出現在上面（D-169）。
- **草稿帶句尾短標，給她看依據；照片辨識的要標明，看不清的寫看不清。** 她核對草稿時要知道哪句從哪來（D-160）。
- **定稿放到相關的檔旁邊、說在哪；她要換夾，用 `kb source-edit move` 搬。** 搬、退回與卡跟上程式會做（D-164 補）。
- **工具不夠先 `kb office check`；要裝工具先問她，她說好才 `kb office setup`。** 裝東西會動她的電腦、要等一兩分鐘，要她知道（D-170）。
- **不替她寄、不分享給別人；線上文件建在她自己的帳號、她同意了才建。** 東西一出去收不回來（R-09）。

## 骨架

- 分辨是哪一種。`kb office check` 看工具並印工作區；缺工具照「要先做」問她，說好才 `kb office setup`。
- **新做**：收資料（實體用 `kb lookup`、按卡型或年列卡用 `kb cards list`、日程用 `kb agenda list`）→ 簡單的直接照用途做成（`references/make.md`），筆記直接存成定稿（draft.md「md 本身就是成品的」），複雜的先寫草稿放暫存區（`references/draft.md`）、她說可以再做：本機檔在工作區做好後 `kb output save … [--draft <草稿>]`，線上文件建好後 `kb output link`；剛回答過的直接做成。
- **改既有、轉格式**：關著：`kb office copy <原檔> --unpack` → 在工作區改 → `kb output save "<夾>"`（蓋回原檔，舊的存成同夾（版本 N））；最後問要不要刪舊版本。開著照知識庫 CLAUDE.md 改視窗裡那份不備份。轉格式、匯出、另存一樣做好在工作區、經 `kb output save` 放進來。
- **回答**：說放在哪（哪個夾，或線上文件存在她帳號）、說「退回」可以退這一步（這份檔先留著，要刪再跟我說）、用了哪幾份資料；做了的事合成一行。

## 共通

- 一次一個指令；路徑加引號，不 cd，不用 && 串接。
- 讀成品用 Read；這台轉 PDF、重算、解開打包用 `kb office`。
- 不自己讀寫 `.system/` 其他地方、`系統/`；工作區例外。被擋或拒絕：照訊息裡的指令或做法接著做完，不跟客戶提；訊息說做不到的，照核心規則 R-12。
